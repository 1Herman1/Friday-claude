# Воркфлоу: Новый проект с нуля

## Шаги запуска

### 1. Определение продукта и стека
- Что делает продукт (1-2 предложения)
- Целевая аудитория
- Монетизация (freemium / подписка / one-time / другое)
- MVP фичи (список)
- **Выбрать стек:** использовать дефолт из `docs/core/stack.md` или обоснованную альтернативу

### 2. Инициализация проекта в репозитории Friday
```bash
# 1. Скопировать шаблон
cp -r docs/projects/_template docs/projects/<имя-проекта>

# 2. Заполнить project.md
# - Описание продукта
# - Стек (совпадает с выбранным на шаге 1)
# - Ветка выкатки (если проект вообще выкатывается)
#   Рабочую ветку НЕ указывать: она одна на весь репозиторий и объявлена
#   в docs/projects/README.md. Новых веток не заводить.
# - Правовой контур (рано проверить, если русская аудитория)

# 3. Заполнить brand.md
# - Тон и характер продукта
# - Визуальные dials (DESIGN_VARIANCE, MOTION_INTENSITY, VISUAL_DENSITY)
# - Компоненты и домены

# 4. Обновить реестр
echo "<имя-проекта>" > docs/projects/.active

# Строку добавить РУКАМИ в таблицу docs/projects/README.md, пять колонок:
# | Проект | Что это | Каталог доков | Код в репозитории | Ветка выкатки |
#
# Колонка «Код в репозитории» — не украшение: из неё design-lint, rkn-lint и
# хук дизайн-линта берут каталоги для проверки. Забыл её заполнить — код
# нового проекта не проверяется, и никто об этом не скажет.
# Сверить после: node .claude/scripts/selftest.mjs
```

### 3. Инициализация кодовой базы
Согласно выбранному стеку:
- **Для Next.js + React:** `npx create-next-app@latest`
- **Для Vite + React:** `npm create vite`
- **Для Fastify + Node:** `npm init` + установка зависимостей
- Установить выбранные технологии из стека

### 4. База данных
Если ORM нужна (согласно стеку):
```bash
# Prisma пример (для стека по умолчанию)
npx prisma init
# Описать схему в schema.prisma согласно дизайн-системе
npx prisma migrate dev --name init
```

### 5. Дизайн-система
```bash
# Сгенерировать эталонные токены
/design-system

# Результат: docs/projects/<проект>/design-system/MASTER.md
# содержит палитру, шрифты, шкалы отступов, тени, радиусы
```

### 6. Аутентификация
Согласно стеку — NextAuth, Clerk, custom JWT или соответствующее решение.
- Настроить провайдеры (если требуется)
- Проверить сессии и middleware

### 7. Структура экранов (MVP)
Определить базовый набор страниц согласно типу продукта (e-commerce, SaaS, лендинг)

### 8. Деплой и инфраструктура
Согласно стеку и `project.md`:
- Выбрать хостинги для фронта и бэка
- Настроить CI/CD
- Настроить домен и SSL

## Чеклист перед лончем
- [ ] Auth работает (вход / выход / защита роутов)
- [ ] Оплата проходит (согласно интеграции в стеке)
- [ ] Email/уведомления отправляются
- [ ] Ошибки логируются
- [ ] SSL настроен
- [ ] Мониторинг настроен (Sentry, Analytics)

## Правовой контур: до развёртывания, не после

Для проекта с российской аудиторией, который собирает персональные данные, —
прогнать `rkn-compliance` в **раннем** режиме на этапе выбора стека, до того как
развёрнута база и оформлен домен.

Проверяется необратимое: где физически стоит база и бэкапы, есть ли хостер в
реестре РКН, на кого оформлен домен, допустим ли способ входа, куда уходят
данные. Ответы записываются в раздел «Правовой контур» файла
`docs/projects/<проект>/project.md`.

Перед сдачей эти пункты уже не правка, а переезд.
