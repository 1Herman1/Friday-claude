# ТЗ: Универсальный дневник трейдера (journal) — v3

Статус: рабочая версия, разработка начата. Владелец: Герман. Обновлено: 2026-10-11.
**Где ведём работу:** Telegram «Трейдинг - крипта» → топик **Т6 «Разработка дневника трейдинга»**.
Связанные документы: модель данных и API — [`../shared/DATA_ARCHITECTURE.md`](../shared/DATA_ARCHITECTURE.md); система агентов — [`../prop-agents/TZ.md`](../prop-agents/TZ.md) (топик Т1).

## 1. Цель

Дневник сам собирает сделки с любых площадок (биржи, пропы, агенты, ручной ввод, голос), считает статистику, находит ошибки и психологические паттерны и подсказывает, что менять. Сначала для Германа; модель данных сразу с заделом под SaaS.

«Универсальный» = одна модель сделки для всех источников: человек и агент, биржа и проп, импорт и ручной ввод. Новая площадка = новый адаптер, а не новая таблица.

## 2. Пользователь и стиль торговли

- **Стиль 1 — смарт-мани (SMC), 15m.** Старт — BTC, дальше **топ-20 по капитализации** (решение 2026-10-10): без стейблкоинов (USDT, USDC, DAI, FDUSD, USDe и т.п.) и обёрнутых/стейкинг-копий (WBTC, stETH, WETH); только те, у кого есть фьючерс на площадке торговли. Список пересчитывается автоматически раз в неделю (CoinGecko). График MEXC (TradingView), исполнение на Bybit (заблокирован).
- **Стиль 2 — шорт пампов на MEXC.** Рост >50%, плечо 10x, стоп = ликвидация; тейки по точкам интереса или 70–80% при скаме.

### 2.1. Сигнальные ИИ-боты (решение 2026-10-10)

Два бота сигналов, у каждого свой алгоритм и свой топик в «Трейдинг - крипта»:
- **Смарт-мани сигналы → Т5 (thread 9).** Сейчас — детектор SMC-BTC 5m; расширяем на топ-20.
- **Памп-дамп сигналы → Т4 (thread 8).** Поиск пампов/дампов под стиль 2.

Сигналы приходят из двух источников:
1. **Свой сканер (поиск сделок).** Код сканирует рынок той площадки, где будем торговать (биржа или проп), находит сетап и считает уровни; агент на Claude Opus 5.5 оценивает и пишет пояснение. Данные берём с площадки исполнения, чтобы цены сигнала совпадали с ценами сделки. **Площадки на старте: MEXC и Hyperliquid** (решение 2026-10-10); у Hyperliquid публичный API, свечи без ключа, есть в ccxt.
2. **Парсер чужих каналов.** Читает сигнальные Telegram-каналы, Opus 5.5 переводит текст в структуру (монета, сторона, вход, стоп, тейки). Каждый канал — запись в **базе каналов**; каждый его сигнал автоматически проверяется по реальным свечам (что сработало раньше — стоп или тейк). Рейтинг канала: число сигналов, win rate, средний R, матожидание, задержка, удалённые/отредактированные посты (сохраняем пост в момент выхода — каналы часто удаляют убыточные). Агент и аналитический отдел отбирают лучшие каналы по рейтингу.

**Связь с дневником:** каждый сигнал (свой или из канала) пишется в общую БД. В дневнике: сделка, открытая по сигналу, связана с ним; статистика — сколько взял/пропустил, результат взятых и «что было бы» по пропущенным; разрезы по источнику (бот/канал), монете, сетапу.
**Изменение схемы (делаем в J0, до первой миграции):** новая таблица `signal_sources` (свой детектор / канал Telegram; рейтинг), у `signals` — `source_id`, `cluster_id`/`strategy_version_id` становятся необязательными, сырой текст поста и ссылка на него.

**Инструменты:**
- Рыночные данные: ccxt, публичные свечи и стаканы без ключа (MEXC, Bybit, Binance); для пропов на бирже — данные биржи-провайдера; для MT5-пропов — терминал MT5 (позже).
- Ключ на чтение — только для своих сделок и баланса, для поиска сетапов не нужен.
- Список топ-20 — CoinGecko API (бесплатный ключ).
- Чтение каналов — Telethon от отдельного Telegram-аккаунта (бот не может читать чужие каналы); `api_id`/`api_hash` с my.telegram.org Герман кладёт сам в `.env`. Чужие сигналы только читаем, не перепубликуем.
- Разбор текста и оценка — Claude Opus 5.5 через Hermes.
- Работа 24/7 — сервер (на Mac сканер спит вместе с ним).

## 4. Ключевые решения (из DATA_ARCHITECTURE)

- **Единица правды — исполнение (fill).** Сделка собирается из исполнений + фандинг + комиссии. Ручная сделка пишется синтетическими исполнениями — статистика считается одинаково.
- **Кто открыл сделку** — три поля: исполнитель (человек/агент), источник (ручной/голос/импорт/движок), сигнал.
- **Числа** — Decimal(38,18) для цен/объёмов/денег; в API строками; float запрещён. Правило «центы» — только для будущего биллинга.
- **Импорт идемпотентный**: уникальные внешние id, сырые ответы биржи сохраняются, курсор двигается после коммита страницы. Ручная сделка и та же из импорта не склеиваются молча — помечаются «возможный дубль».
- **Импорт пишем на Python** (общий пакет `shared/python/tp_core` с адаптерами площадок — те же, что у агентов). Веб только ставит задачу и показывает статус.
- **Схемой и миграциями владеет `shared/db` (Prisma).** Python работает через SQL (SQLAlchemy Core).
- **SaaS-заготовка:** `organization_id` на бизнес-таблицах, роли отдельно от способа входа. Биллинг — только поле тарифа.

## 6. Этапы и критерии готовности

**J0 — общий фундамент (делается здесь, Т1 им пользуется)**
- `shared/db`: Prisma-проект, схема из DATA_ARCHITECTURE, первая миграция применена к локальной БД, SQL-функции пересчёта сделки и дня, seed (площадки, BTCUSDT MEXC, организация «Герман», кластер smc-btc).
- `shared/python/tp_core`: подключение к БД, `money.py` (Decimal, квантование), генерация `tables.py` из живой БД.
- Готово, когда: `prisma migrate` проходит на чистой БД, seed отрабатывает, Python читает/пишет тестовую сделку, тест пересчёта сделки зелёный.

**J1 — импорт MEXC**
- Адаптер MEXC (чтение), сборка сделок из исполнений (positionId или FIFO), фандинг и комиссии, сырые записи.
- Сначала сверить API MEXC по документации и живому ключу: эндпоинты, поля, глубина истории, контракты/монеты.
- Готово, когда: полный импорт истории Германа без ошибок; повторный запуск даёт 0 новых; 5–10 сделок сверены вручную с кабинетом MEXC.

**J2 — статистика и веб**
- `journal/web` (Next.js + TS + Tailwind + shadcn/ui + TanStack Query), API v1 из DATA_ARCHITECTURE §7.
- Дашборд: PnL, win rate, profit factor, средний R, equity, просадки; разрезы по стилю, монете, дню недели, часу, длительности, исполнителю.
- Список сделок с фильтрами, ручной ввод сделки.
- Готово, когда: цифры дашборда совпадают с ручным расчётом на выборке; ручная сделка появляется в статистике.

**J3 — карточка сделки и заметки**
- График (TradingView Lightweight Charts) со свечами и отметками входа/выхода/стопа/тейка; причина входа, эмоция, уверенность, следование плану, нарушенное правило, теги, скриншоты.
- Голосовые заметки из Telegram → распознавание → черновик → подтверждение.

**J4 — ИИ-разборы**
- Еженедельный разбор (ошибки, паттерны, рекомендации) и разбор одной сделки — модель Claude Opus 5.5; стоимость каждого вызова LLM пишется в БД.

**Ф2:** чек-лист перед входом; детектор тильта (вход <5 мин после убытка, рост лота после убытка, >N сделок в день, серия убытков, торговля вне своих часов, стоп = ликвидация); сигналы по монетам из арены агентов; метрика «цена ликвидационного стопа».
**Ф3:** Telegram Mini App; мультипользовательность и биллинг (SaaS) — только после решения по РКН (§8).

## 7. Параметры учёта

Сделка: площадка, счёт, инструмент, направление, плечо, объём, маржа, исполнения, стоп (план/факт), тейк(и), ликвидационная цена, комиссии, фандинг, PnL ($, %, R), длительность, стиль/сетап, таймфрейм, исполнитель и источник, сигнал, скриншоты.
Психология: эмоция до/после, уверенность 1–10, следование плану, нарушенное правило, заметка (текст/голос).
День: стартовый/конечный баланс, PnL, макс. просадка, число сделок, оценка дисциплины, план и итог дня.
