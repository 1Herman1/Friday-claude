# Витрина каждой стратегии — требования и приёмка

Владелец: Герман. Топик Т1. Запрос 16.11.2026: «разработай так под каждую рабочую стратегию и сделай дизайн как на витрине по скринам выше».

## Объём

Единая живая диспетчерская `/agents-monitor` внутри дневника и отдельный рабочий экран каждой реализованной семьи. Не запуск новых торговых ботов, не разрешение на реальные заявки и не объявление всех стратегий прибыльными.

Реестр проверяется по существующим исходникам/данным:

- `funding` — многобиржевой funding discovery: live наблюдение, ticker-only кандидаты, всё HOLD. `engine/funding_monitor/out/{latest,progress}.json`. Разница ставок не прибыль; ликвидность/идентичность/комиссии/исполнение не сертифицированы.
- `smc` — SMC-BTC: отдельно legacy v0.1 сигналы и v0.3 preview (1h sweep → 15m IFVG), без подмены live версии. Стоп за sweep, HTF/окно/tick не утверждать автоматически. Старые дефекты v0.2 и ограничения доходности явно видны.
- `pump` — памп/дамп-наблюдение: показать фактический доступный feed. Сохранённый BingX ±20% snapshot — только обзор/прокси, не полноценная стратегия шорта пампов Германа (старый MEXC scanner ≥50%/24h). Нет feed — явный статус и blocker. Новые входы/риск ликвидацией не включать.
- `donchian` — S1, дневной ансамбль: существующий положительный исторический тест, не работающий live-исполнитель. Обязательно период, тип рынка, источник, издержки, ограничение survival bias и отсутствие форварда.
- `tsmom` — S4/S4L: две версии одной семьи, отдельно long-short и long-only, не перепутать цифры. Сохранённый исторический тест, не live PnL.

S2/S3/S5/S6 и baseline не выдаются за работающих агентов только потому, что упоминаются в каталоге. Не пропускать действительно реализованную семью молча: дополнительную найденную семью сначала классифицировать по источнику и объяснить.

## Дизайн

Поверхность MONITOR. Оригинальная композиция по общим принципам присланной владельцем dark hedge-fund витрины: тёплый матовый угольный/коричневый фон, тонкие медные рамки окон, неброские компактные зелёные/янтарные состояния, маленькие нумерованные mono-заголовки, ясная цепочка ролей. Не копировать логотип/автора/метрики чужого проекта.

- Верхняя компактная панель состояния системы, без маркетингового hero.
- Селектор стратегий показывает LIVE OBSERVATION / SAVED / PREVIEW / BACKTEST и возраст источника.
- Центральная область конкретной стратегии: её реальный процесс/численная карточка/кандидаты, а не одна и та же пустая таблица с разными заголовками.
- Правый инспектор выбранного объекта: факты, происхождение, причины HOLD/пропуска и ограничения.
- Лента реальных событий с временем; неполнота и ошибки не скрываются.
- Экран 390px функционально полный: кнопки не мельче 44px, без page-level overflow; таблицы могут иметь собственную горизонтальную прокрутку.
- Предыдущий funding-only экран по возможности остаётся доступным отдельно. Основной публичный путь `/agents-monitor` не меняется.

Оригинальные старые файлы Instagram-скринов больше не найдены в локальном кэше; видимые в переписке характеристики не выдаются за новый pixel-perfect анализ оригиналов. Текущий предыдущий screenshot открыт и передан UI-исполнителю как starting point, не новый целевой референс. Новые PNG проверяются отдельно.

## Честность состояний

Отличать наличие кода, сохранённый результат, свежие данные, текущий запрос, подтверждённую работу LLM и исполненные сделки. Статус последнего запроса не означает свежесть всего dataset. Исторический тест не форвард и не live equity.

Для каждой стратегии видны стадии данных/контекста/детектора/quant/управляющего/risk/execution. Отсутствующие подключения — NOT CONNECTED/NOT WIRED, не SUCCESS. Зелёный допустим только для конкретного подтверждённого события, не как обещание прибыли. Не рисовать выдуманные PnL, позиции, уверенность, графики или «спор агентов».

## Технический контракт

- Типы: `journal/web/src/lib/strategy-observatory-contract.ts`, фиксированный `StrategyPanel`.
- Read-only API `/api/strategy-observatory`, только whitelist источников и ограниченные чтения. Нет произвольного пути из URL, секретов, приватных ключей, записи в live-state, запуска engine или ордеров из HTTP GET.
- Числа финансов — строки. Отсутствующие значения null. Первичная provenance и ограничение/cap каждой выдачи видны.
- Не читать большие 156MB audit файлы целиком при каждом poll. Изолированные fixture tree для missing/stale/invalid tests.
- API отдаёт все панели; выбранная стратегия поддерживается в URL `?strategy=...`, корректны reload/back/forward. Пауза экрана не выключает коллектор.
- Ошибка HTTP сохраняет последние данные с явным OFFLINE/stale состоянием; восстановление подтверждается новым успешным чтением.

## Проверка готовности

1. Реестр программно сверяется: перечислены все пять названных семей, нет одинакового наполнения под разными именами.
2. Каждая панель имеет факты из конкретного источника либо честный missing/blocker, свой pipeline и drilldown.
3. Переключение всех стратегий, URL/reload/back, поиск и выбор объекта проверены браузером, не только по коду.
4. Наличие live funding проверяется отдельно от preview/history. Для SMC версии и даты не перепутаны; pump proxy не переименован в исполнимый short setup; S1/S4/S4L имеют исторический период/издержки.
5. Unit/API тесты, TypeScript и scoped ESLint проходят. Desktop/mobile скриншоты просмотрены. Подтверждённые дефекты исправлены перед итоговым «готово».
6. Нет изменений торговых лимитов, учётных ключей, моделей, cron, real orders или production deployment. По окончании локальные HTTP страницы/API проверены повторно; для телефона удалённый доступ отдельно, localhost работает на Mac.
