# Карточка стратегии кластера — шаблон

Заполняется на каждый кластер. Лежит в `clusters/<имя>/strategy.md`, жёсткие числа — в `clusters/<имя>/rules.yaml`.
Цель: агент должен понимать (а) какой сейчас рынок, (б) что именно ищет стратегия, (в) когда НЕ торговать.

Правило заполнения: всё, что можно измерить, — числом. Всё, что нельзя, — примером со скриншотом.

---

## 1. Паспорт
- [ ] Название кластера и версия (например `smc-btc v1.0`)
- [ ] Автор / кто утвердил
- [ ] Идея в одном предложении: на чём зарабатываем, чья ошибка — наша прибыль
- [ ] Стиль: скальп / интрадей / свинг
- [ ] Рабочий таймфрейм входа + старшие таймфреймы для контекста (например 15m вход, 1h/4h контекст)
- [ ] Инструменты (whitelist) и минимальная ликвидность / объём за 24ч
- [ ] Площадки, где разрешено торговать (демо / какие пропы)

## 2. Контекст рынка (что агент должен проверить ДО поиска входа)
- [ ] **Режим рынка:** тренд / флэт / высокая волатильность — как определяем (например ADX > 25 = тренд, ATR% к среднему за 30 дней)
- [ ] **Старший тренд:** по какому ТФ и инструменту (EMA, структура HH/HL)
- [ ] **Сессии:** Азия / Лондон / Нью-Йорк — в какие торгуем, какие пропускаем
- [ ] **BTC как фон** (для альтов): корреляция, что делаем при резком движении BTC
- [ ] **Деривативы:** фандинг, открытый интерес, ликвидации — какие значения считаем перегревом
- [ ] **Новости и календарь:** FOMC, CPI, листинги, разлоки токенов — окно запрета до/после (мин)
- [ ] **Сентимент:** источник (Fear&Greed, соцсети, новостная лента) и как влияет на решение
- [ ] **Режимы, в которых стратегия НЕ работает** — перечислить явно

## 3. Сетап (что ищем)
- [ ] Определения терминов стратегии **числами** (например: «BOS = закрытие тела свечи за последний swing high, swing = 3 свечи слева и справа»)
- [ ] Обязательные условия входа (все должны выполниться)
- [ ] Подтверждающие условия (повышают уверенность, но не обязательны)
- [ ] Условия отмены сетапа (инвалидация до входа)
- [ ] Тип входа: рынок / лимит / по закрытию свечи; срок жизни лимитки
- [ ] 3–5 эталонных примеров: скриншот + разметка + почему вход (хорошие) и 2–3 примера «похоже, но не вход»

## 4. Выход
- [ ] Стоп: где ставится (за структуру / ATR × k) — обязателен всегда
- [ ] Тейк(и): цели и доли частичного закрытия
- [ ] Перенос в безубыток / трейлинг: когда
- [ ] Выход по времени: если за N свечей не пошло
- [ ] Минимальное соотношение риск/прибыль (например ≥ 1:1.5)

## 5. Риск (жёсткие числа → rules.yaml, агент их не меняет)
- [ ] Риск на сделку, % от счёта
- [ ] Макс. плечо
- [ ] Макс. одновременных позиций, макс. позиций в одну сторону
- [ ] Дневной стоп (%) и стоп по серии убытков (N подряд → пауза X часов)
- [ ] Макс. сделок в день
- [ ] Профиль пропа (дневной лимит по equity, общий лимит, время сброса, запреты)

## 6. Поведение агента
- [ ] Когда звать дебаты (только при сигнале детектора)
- [ ] Порог уверенности для входа
- [ ] Что агент ОБЯЗАН вернуть: JSON-схема решения + обоснование по пунктам 2–4
- [ ] Что запрещено: перечень (усреднение убыточной, мартингейл, вход без стопа и т.д.)

## 7. Оценка
- [ ] Бейзлайн для сравнения (простая версия без LLM)
- [ ] Метрики успеха: доходность после комиссий и стоимости API, макс. просадка, Sharpe, win rate, средний R
- [ ] Минимальный срок и число сделок до вывода (например 4 недели или 50 сделок)
- [ ] Критерий допуска на проп и критерий отключения

## 8. Журнал изменений
- [ ] Версия, дата, что изменено, почему, результат на арене
