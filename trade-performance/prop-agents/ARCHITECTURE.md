# Архитектура агентов prop-agents

Принцип: **LLM думает, код решает, где деньги.** Всё, что можно посчитать, считает код (быстро, дёшево, одинаково). LLM — там, где нужно суждение: контекст, новости, картинка графика, дебаты, улучшения.

LLM: Claude Opus 5.5 (сильные роли), Claude Sonnet 5.5 (массовые роли). Бесплатные модели OpenRouter — для черновых прогонов и бейзлайна.

## Слои и агенты

```
 ДАННЫЕ ──▶ ДЕТЕКТОРЫ ──▶ МОЗГ КЛАСТЕРА ──▶ РИСК ──▶ ИСПОЛНЕНИЕ ──▶ ЖУРНАЛ
   код         код           LLM             код        код           код
                               ▲                                        │
                               └──────── УЛУЧШАТЕЛИ (LLM) ◀────────────┘
                              НАДЗОР: Сторож (код) + Диспетчер + Telegram
```

### 1. Данные (код, без LLM)
| Компонент | Что делает | Частота |
|-----------|-----------|---------|
| Market Feed | Свечи, стакан, сделки (ccxt, WebSocket) | Поток |
| Derivatives Feed | Фандинг, открытый интерес, ликвидации | 1–5 мин |
| News Feed | Новости, календарь (FOMC, CPI, разлоки) | 1–5 мин |
| Sentiment Feed | Fear&Greed, соцсети | 15–60 мин |
| Chart Renderer | Рисует график с разметкой → PNG для «глаз» | По запросу |

Всё пишется с временем публикации: агент видит только прошлое.

### 2. Детекторы (код, без LLM) — по одному на кластер
Находят сетап по карточке стратегии (`clusters/<имя>/rules.yaml`): MA-cross, SMC (BOS/CHoCH, OB, FVG, ликвидность), новостной всплеск. Нет сетапа — LLM не вызывается.

### 3. Мозг кластера (LLM) — запускается только при сигнале
| Агент | Модель | Роль |
|-------|--------|------|
| Market Context Analyst | Sonnet | Режим рынка, старший тренд, сессия, BTC-фон, деривативы |
| Chart Vision Analyst | Sonnet (vision) | Смотрит картинку графика, подтверждает/опровергает разметку детектора |
| News & Sentiment Analyst | Sonnet | Новости и сентимент по инструменту за окно [t−N, t] |
| Bull Researcher / Bear Researcher | Sonnet | Дебаты: аргументы за и против входа |
| Strategy Trader | Opus | Сводит всё с карточкой стратегии → решение в JSON |

Выход: `{action, entry, sl, tp[], confidence, reasons{context, setup, exit}}`, проверка по схеме. Невалидный ответ = HOLD.

### 4. Риск (код, неизменяем для агентов)
Risk Gate: размер позиции от риска и стопа, плечо, R:R ≥ порога, дневной/общий лимит по equity, профиль пропа, серия убытков → пауза, whitelist, запреты. Может уменьшить объём или отклонить. Меняет только Герман.

### 5. Исполнение (код)
| Адаптер | Площадка |
|---------|----------|
| API | Hyperliquid testnet, OKX Demo, BloFin demo, Propr, HyroTrader |
| Terminal (браузер) | SizeProp и другие, где автоматизация терминала разрешена |
Order Manager: выставляет ордера, следит за стопами/тейками, безубыток, трейлинг, выход по времени.

### 6. Журнал (код)
Все промпты, ответы, решения риска, ордера, филлы, комиссии, стоимость LLM → PostgreSQL → дневник (`journal/`).

### 7. Улучшатели (LLM) — по расписанию, не в торговом цикле
| Агент | Модель | Роль |
|-------|--------|------|
| Post-Trade Reviewer | Sonnet | Разбор каждой закрытой сделки: что сработало, что нет |
| Strategy Researcher | Opus | Раз в неделю: паттерны ошибок → предложения правок карточки (новая версия) |
| Shadow Evaluator | код | Гоняет новую версию в тени рядом со старой, сравнивает после комиссий |
| Promoter | код + Герман | Заменяет версию, если тень обыграла по критериям; уведомление в Telegram |

### 8. Надзор
- **Сторож (код):** kill-switch, проверка связи с площадками, расхождение позиций, аварийное закрытие.
- **Диспетчер (Hermes):** расписания, очереди, лимиты LLM, перезапуски.
- **Telegram:** статус, стоп/старт, сигналы, отчёты; топик на каждого агента.

## Агент = кластер + версия + модель + площадка
Каждый экземпляр имеет свой счёт и свой топик в Telegram. Контекст агента живёт в репозитории (`clusters/<имя>/`), а не в чате: обсуждаем в топике → правка карточки → новая версия → тень → замена.

```
clusters/
  smc-btc/
    strategy.md      # карточка (по шаблону)
    rules.yaml       # жёсткие числа
    examples/        # эталонные скриншоты
    CHANGELOG.md
  ma-cross/
  news-sentiment/
```

## Топики агентов в Telegram
Один топик = один кластер (все его версии/модели). Что приходит в топик автоматически: сигналы детектора, решения агента с обоснованием, сделки, итог дня, предложения улучшателя.
Что делает Герман в топике:
- `/context <текст/скрин>` — добавить знание (наблюдение, пример, «тут не входим») → черновик в `clusters/<имя>/inbox.md`.
- `/rule <правка>` — предложить правку карточки → новая версия в тени, не сразу в бою.
- `/why <id сделки>` — разбор решения.
- `/pause`, `/resume` — остановить/запустить кластер.
Правило: чат — только вход. Агент в торговом цикле читает карточку из репозитория, не историю чата (иначе контекст размывается и правки не версионируются).

## Стоимость
LLM вызывается только при сигнале детектора: ~6 вызовов на сигнал (5 Sonnet + 1 Opus). Пример: 3 кластера × ~10 сигналов в день ≈ 180 вызовов в день. Улучшатели — раз в день/неделю.
