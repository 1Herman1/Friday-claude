# Приёмка: отдельные витрины стратегий

Проверено основным агентом 17.11.2026 MSK. Запрос владельца — отдельный рабочий экран каждой стратегии и дизайн по присланной dark hedge-fund витрине. Реальная торговля не включалась.

## Результат

Путь на Mac: `http://127.0.0.1:3100/agents-monitor`. Существующий пункт меню «Агенты · Live» ведёт в общий селектор пяти семей:

1. Funding: публичный многобиржевой discovery, live-наблюдение. Completed snapshot и текущий progress раздельны. Свежий sidecar может показывать этап сбора RUNNING при старом dataset; старый heartbeat не считается работающим процессом. Все связки HOLD.
2. SMC: 71 сохранённый v0.3 preview-кандидат, 19 файловых legacy v0.1 сетапов, 9 конфигураций аудита. Preview не заменяет live-конфиг; production eligibility=0. DB с 66 SMC signals в этот адаптер не включена: 19 не объявлены полной историей/доставкой.
3. Pump: первичный read-only SELECT из существующего дневника, 131 сохранённый MEXC-сигнал. Последний signal time не означает текущую работу collector и не равен API времени чтения. При отказе БД — явно обозначенный saved BingX ±20% proxy, не полноценная short-стратегия ≥50%.
4. Donchian S1: 3 исторических split, режим BACKTEST_ONLY; нет live-исполнителя.
5. TSMOM: 6 исторических split-строк (S4 и S4L раздельно). В инспекторе указаны вариант/направление/период выбранного split. Дополнительные whole-period расходы явно помечены «весь период 2021-01 — 2026-09», а не приписаны каждому split.

Количество funding rows/pairs меняется; отдельный проверочный цикл дал 3839 observations / 4534 пары, более поздний partial-cycle — 3317 / 2880. Это записи инструмент×биржа и тикерные кандидаты, не независимые монеты, сделки или прибыль. У каждой панели видны реальные источники, лимит/полнота выдачи, режим, возраст, блокеры, события и drilldown.

## Дизайн и взаимодействие

- Тёплые матовые угольно-коричневые поверхности, тонкие медные рамки/inset, компактные зелёные и янтарные состояния, терминальные номера и mono-подписи. Нет скопированного логотипа, чужих PnL или маркетингового фото-hero.
- Один селектор пяти стратегий и собственный workspace каждой, без подмены SMC/pump/исторических данных funding-таблицей.
- Внутри пять пронумерованных секций: цепочка решения, кандидаты/доказательства, исходная кривая, досье и журнал. Семь стадий pipeline — code/LLM/human со статусами по источникам; отсутствующие подключения не зелёные.
- Кривая у текущих источников отсутствует: показано честное пустое состояние, equity/PnL не синтезируются из агрегатов.
- Выбор этапа, кандидата и строки; поиск по всем загруженным строкам до display cap, явный loaded/total/display лимит. Частично выданный источник не называется полным.
- URL `?strategy=...`, обновление страницы и back/forward. Пауза экрана не выключает коллектор. API error сохраняет последние данные с предупреждением.
- Старая funding-only консоль сохранена по `/agents-monitor/funding-detail`, старый API не менялся.

## Реальные проверки

- Основной агент независимо повторил тесты: **11/11 PASS** (7 backend + 4 UI helper). Node сообщает MODULE_TYPELESS_PACKAGE_JSON при direct TS tests; менять весь package type ради этого не стали.
- `npx tsc --noEmit --incremental false` и scoped ESLint — exit 0 после финальных правок.
- `verify-real.mjs 131`: реальные HTTP/schema/whitelist/source-count assertions PASS; последний полный верификатор — 94ms. Число pump131 отдельно сверено read-only SQL по configured local DB, а не выведено только из API ответа.
- Parent browser: последовательно выбраны все пять стратегий, URL/headings соответствуют, desktop width=1440. Финальный повтор подтвердил секции #01–#05 во всех пяти, empty curve и split facts в S1/TSMOM. JSON — `parent-final-ui-checks.json`.
- Mobile390: page scrollWidth=390, overflow не обнаружен. Screenshot — `tsmom-mobile.png`. UI-исполнитель дополнительно проверил 768px, pause/offline/recovery/back; его проверки отделены от родительских.
- Сообщённый единичный Next dev HMR JSON500: после завершения промежуточной записи файлов основным агентом выполнены пять page/API повторов, всё HTTP200. Не заявляется доказанная причина без воспроизведения; финальные браузерные сценарии ошибки не повторили.

## Независимое ревью и устранение замечаний

Адаптированный code-reviewer (`deleg_188ea8a8`, read-only) проверил scope, source verifier и live UI desktop/mobile. Других подтверждённых дефектов безопасности/корректности не нашёл, но отметил пропущенную секцию #03. Формулировка его критерия «пять панелей для каждой стратегии» была шире исходного требования пяти семей, однако UX-дефект скачка нумерации принят: основным агентом воспроизведён RED в браузере, затем всегда добавлена #03 с честным empty state, повтор GREEN по всем пяти стратегиям.

Дополнительно основным агентом найдено и исправлено через RED→GREEN: отсутствие явного split-периода/области whole-period расходов в historical inspector; отсутствие отображения текущего progress RUNNING на самом этапе данных. Сохранённый dataset age не заменён свежим progress time.

## Что осталось вне этой работы

Не подключены торговый executor, news/управляющий LLM, реальные risk/quant вызовы из витрины и paper fills. Не менялись API-ключи, торговые лимиты, версии стратегии, cron или условия входа. Сервер только loopback Mac, не внешний/24×7 production. Нужны отдельные работы по защищённому remote-доступу, хосту, ротации raw, ретраям и актуальным feed для остальных стратегий. Наличие витрины не доказывает доходность.
