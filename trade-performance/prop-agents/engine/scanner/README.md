# BingX public scanner — read-only MVP

Изолированная утилита: Python 3.9+ standard library + системный `curl`, без установки пакетов. Не читает `.env`, не принимает ключи, не импортирует торговый движок. Только allowlist публичных GET market-data endpoints. Никаких ордеров, переводов, cron, запуска сервера или deployment. Все изменения и артефакты находятся внутри `engine/scanner/`.

## Запуск

Из `/Users/germanbryzgalov/Friday-claude/trade-performance/prop-agents`:

```sh
env -u PYTHONPATH .venv/bin/python -m unittest discover -s engine/scanner -p 'test_*.py' -v
env -u PYTHONPATH .venv/bin/python engine/scanner/scanner.py --oi-limit 8 --flow-limit 3
```

Universe ВСЕГДА полный: все активные USDT perpetual контракты из `contracts`, один bulk ticker и один bulk funding запрос. Включает не только криптовалюты, если BingX возвращает другие базовые активы. OI и sampled buy-flow — отдельное явно ограниченное обогащение по убыванию абсолютного 24h изменения цены. По умолчанию эти per-symbol запросы отключены: пропуски показаны, а не заменены нулями. Полное обогащение доступно явно:

```sh
env -u PYTHONPATH .venv/bin/python engine/scanner/scanner.py --oi-limit -1 --flow-limit -1
```

**Полное OI/flow обогащение на 908 символах в этой работе НЕ запускалось.** Каждый endpoint ограничен примерно 1 запросом/с; полный обход длительный, при сетевых таймаутах ещё дольше. Не путать поддержку полного обхода с выполненной проверкой на всех символах.

Результат: `artifacts/<UTC timestamp>/snapshot.json`, `raw.json`, автономный `report.html`. HTML открывается локальным файлом; нет внешних JS/CSS, fetch и CDN. `--out` разрешён только внутри scanner; явно выбранный существующий каталог перезапишет одноимённые артефакты. `--retries 0|1|2` ограничивает повторы. Код возврата: **0** полное покрытие, **2** partial (включая не запрошенные OI/flow), **1** недоступный/пустой universe. Неполнота не маскируется успешным exit 0.

## Что вычисляется и что неизвестно

- Price screen: `abs(priceChangePercent) >= 20%` за rolling 24h, pump/dump метки. Это порог, не статистическое доказательство аномалии, не торговый сигнал и не краткосрочный памп-детектор.
- Quote turnover: реальный rolling-24h оборот USDT для каждой монеты; отношение к медиане положительных оборотов полного universe, метка `>=10x`. Это **межрыночная концентрация оборота**, НЕ всплеск относительно собственной истории: крупные BTC/ETH естественно выделяются.
- Funding: реальные decimal ставки и индивидуальный период; absolute threshold `>=0.001` (0.1% за заявленный период). Не сравнивать разные периоды как равнозначную доходность, это не annualized rate.
- OI: реальные возвращённые значения и время только для запрошенных контрактов. Единицы не подтверждены, конвертации в USDT нет.
- Buy-flow: доля USDT-оборота сделок, где покупатель был taker, только в полученной recent-trades выборке. Время окна и объём классифицированных/неизвестных записей сохранены. Не общий приток денег, не дельта всего рынка, не достоверный сигнал накопления. У каждой сделки есть покупатель и продавец.
- История пока **не собрана**: `history_status=not_collected`, `volume_anomaly=null`, `oi_anomaly=null`. Ноль означает измеренный ноль; null означает unknown. Нет выдуманной baseline, исторических z-score, OI роста или вывода «аномалий нет» из отсутствующих данных.
- Все финансовые значения обрабатываются через Decimal, сохраняются строками; NaN/Infinity/битые значения становятся null.
- Снимок не атомарный: начало, завершение, время получения raw и биржевые timestamps сохранены. Актуальность оценивается относительно времени снимка, HTML не обновляет цены сам.

## Реальный проверенный результат

Финальный запуск: `2026-11-14T21:49:01.491189+00:00` — `2026-11-14T21:50:11.553129+00:00`.

- Получено 1334 contract records, bulk ticker 957 records; universe активных USDT: **908**.
- Цены/24h оборот: **908/908**, отсутствующих/битых ticker строк **0**.
- Funding: **908/908**.
- OI: **7 успешных из 8 запрошенных**, ещё **900 не запрашивались**. `PUSSY-USDT` — финальный SSL connection timeout после ограниченных повторов. Отмечено в failures; не заменено нулём.
- Buy-flow: **3/3** запрошенных; **905 не запрашивались**.
- 19 HTTP попыток, из них 6 неудачных; 1 окончательная endpoint ошибка. Повторяемые ошибки не исчезают из request_audit.
- Метки: 3 pump, 22 dump, 21 funding threshold, 28 cross-sectional turnover; категории могут пересекаться.
- `env -u PYTHONPATH .venv/bin/python engine/scanner/scanner.py --oi-limit 8 --flow-limit 3` → **exit 2, status partial**, честно по покрытию.
- `env -u PYTHONPATH .venv/bin/python -m unittest discover -s engine/scanner -p 'test_*.py' -v` → **13 tests, 1.145 s, OK, exit 0**. Тесты написаны до соответствующих реализаций; RED и GREEN реально выполнялись.
- Независимо проверено равенство множества universe исходным contracts, 908 уникальных строк snapshot и 908 HTML rows, null исторических аномалий.
- HTML проверен реальным браузером: 908 строк, фильтр EVAA → 1, отсутствующий символ → 0, без JS ошибок; desktop 1440 и mobile 390 px. Таблица имеет собственный horizontal scroll.

## Воспроизводимый рабочий процесс

1. Проверить официальные документы и реальные публичные ответы; не считать документационный пример живыми данными.
2. RED → GREEN для universe, транспорта/безопасности, неизвестных значений, обогащения и HTML.
3. Сначала contracts, затем bulk ticker/funding; никогда не выдавать наличие ticker за доказательство полного universe.
4. Ограничить дорогой по времени per-symbol сбор явно; показать attempted / present / not-requested / failures.
5. Сохранить raw + нормализованный timestamped snapshot + локальный HTML, проверить множества и количества кодом.
6. Отдельно проверить HTML и фильтр браузером; сообщить ограничения и реальные exit codes.

Далее для настоящих временных volume/OI аномалий нужны накопление сопоставимых окон/истории, контроль пропусков и freshness, затем causal baseline и проверка ложных срабатываний. Исторические аномалии, полный market-wide buy-flow, websocket stream, мультибиржевой капитал/spot inflow, profitability и торговое исполнение в этом MVP не заявляются.
