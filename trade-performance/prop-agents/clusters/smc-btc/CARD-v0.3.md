# SMC v0.3 — изолированный PREVIEW, НЕ production

**Статус:** реализован и проверен детектор кандидатов `1h sweep → 15m IFVG`.
Это не законченный v0.3, не переключение live-бота и не доказательство доходности.
HTF-фильтр помечен `UNAPPROVED_CONTEXT`; **production_eligible всегда false**.
Ни отправки сообщений, ни заявок, ни записи в live `out/seen.json` здесь нет.

## Утверждённое и ещё не утверждённое

Утверждена лесенка: снятие значимой ликвидности на **1h**, подтверждение входа на **15m**.
Основа — `engine/backtest/smc_v02.py`, а не переименование v0.1.
Реализация не импортирует live-детектор и не использует его состояние.

Для preview явно наследуются исследовательские параметры v0.2:
- Азия / Лондон / предыдущий день; в UTC-вариантах также предыдущая неделя;
- подтверждённые 4h swings: одна свеча слева и справа, известны лишь после закрытия правой;
- FVG lookback 12 часов до открытия sweep; поиск входа ещё 8 часов после его закрытия;
- срок уровней сессии/PD 24 часа, PW 7 дней, swing 20 дней, целевого FVG 30 дней;
- варианты окон `ny`, `crypto`, `all` разделены, аргумент `--variant` обязателен.
  Запуск `all` — исследовательский контроль, а не согласование торговли круглосуточно.

Числа выше **не выдаются за новую утверждённую карточку v0.3**.
`config.v03.preview.json` — снимок фиксированной реализации и её статусов, не tuning-конфиг;
правка чисел в этом JSON не меняет алгоритм. Снимок включён в CLI-отчёт.

## Точная механика preview

1. Первый строгий выход 1h-фитиля за доступный неснятый уровень расходует этот уровень.
   Если час не закрылся обратно, причина `NOT_SWEEP`; повторного sweep этого уровня нет.
   Выход вне выбранного окна даёт `OUTSIDE_PROPOSED_WINDOW`.
2. Для шорта час должен иметь high > уровень и close < уровень; для лонга зеркально.
   Только **после** закрытия этого часа рассматриваются последующие 15m.
3. Направленный FVG — трёхсвечный зазор: для шорта bullish `low[i] > high[i−2]`,
   для лонга bearish `high[i] < low[i−2]`. Берётся последний сформированный зазор
   в наследуемом lookback; допускаются новые FVG до входа, как в v0.2.
   Свеча формирования не может быть свечой собственного IFVG-входа.
4. IFVG: предыдущий close находился на/за пересекаемой дальней границей зазора,
   текущий close строго перешёл её в сторону разворота. Вход — **этот close**,
   timestamp входа — время закрытия 15m, а не открытия.
   Это явное требование нового пересечения, строже проверки «цена уже ниже» в v0.2.
   Дополнительная политика давности/повторной инверсии FVG ещё не согласована.
5. До входа close 15m обратно за снятым уровнем отменяет кандидат:
   `BODY_BACK_BEYOND_LEVEL`. На равенстве отмены нет. Просрочка —
   `NO_IFVG_BEFORE_DEADLINE`; если данных для решения пока нет — `PENDING_IFVG`.
6. Экстремум обновляется от начала sweep до свечи входа включительно.
   SL — `math.nextafter` за этим экстремумом, **не от FVG**.
   Это математическая граница для preview, не пригодный для заявки tick-rounded SL.
   Биржа/тик/буфер требуют согласования: `STOP_TICK_ROUNDING_UNAPPROVED`.
7. TP1 = 2R. TP2 — ближайшая противоположная ещё не затронутая ликвидность
   или ближняя грань 4h FVG строго дальше 2R, доступная к закрытию входа.
   Касание цели считается её расходованием; вся проверка только по уже закрытым 15m.
   Если TP2 есть: план 50% на TP1, остаточный SL → entry; иначе 100% на 2R.
   Это **план уровней**, не симуляция исполнения.

Совпадающие уровни разных типов остаются отдельными кандидатами. Нет объединения
в сигнал, учёта занятых позиций, лимита «одна сделка на окно», PnL, комиссий или
тайм-стопа. Справочные v0.2 120h / taker+slippage 0.0007 / maker 0.0002
не используются для обещаний о результате.

## Защита от заглядывания вперёд

- Вход — непрерывные положительные OHLC 15m, UTC open-time; дубликаты, разрывы,
  некорректный диапазон цен и невыравненные timestamps отклоняются.
- Открытые 15m отбрасываются. 1h/4h собираются только из полных 4/16 закрытых 15m.
- Уровень сессии/дня/недели возникает только при наличии **всей** сессии.
  Предыдущая неделя — понедельник–понедельник UTC. NY учитывает календарный DST.
- Минимальный warmup — 768 закрытых 15m (8 суток); кандидаты до его окончания
  не выводятся. Это не гарантия 20/30-дневной истории всех возможных HTF-уровней.
  Для такой истории нужно отдельно запросить больше свечей, например `--bars 3840`.
- У каждого кандидата есть symbol, venue, version, вариант, UTC sweep/entry/decision,
  исходный уровень с known/expire и стабильный версионированный ключ.
- `--verify-prefix` сравнивает завершённые записи полного прогона с отдельными
  прогонами усечённых данных: на всех decision/sweep-close и промежуточных
  незавершённых HTF-границах. Pending вправе изменяться; завершённые записи — нет.

## Запуск (из `trade-performance/prop-agents`)

```bash
.venv/bin/python -m unittest discover -s tests -p test_smc_v03_preview.py -v

# Только публичные GET MEXC SPOT, никаких ключей
.venv/bin/python clusters/smc-btc/v03_preview.py \
  --symbol BTCUSDT --variant all --bars 1920 --verify-prefix \
  --output-dir clusters/smc-btc/preview-v03/новый-прогон

# Детерминированный offline replay реально полученных свечей
.venv/bin/python clusters/smc-btc/v03_preview.py \
  --input clusters/smc-btc/preview-v03/20261111-btc-all/candles.json \
  --as-of 2026-11-11T17:26:02.007480Z --variant all --verify-prefix \
  --output-dir clusters/smc-btc/preview-v03/повтор
```

`--output-dir` обязателен. Live `out`, его подкаталоги, родительские каталоги
и symlink-файлы результата запрещены. Новые файлы: `candles.json`
(исходные публичные klines, OHLC, endpoint/время загрузки) и `report.json`
(кандидаты, причины пропуска, счётчики, blockers и проверки причинности).
Сеть не подменяется синтетикой при ошибке: команда завершается с ошибкой.
`--input` — воспроизведение указанного файла; provenance сохранён, а не выдумывается.

## Что блокирует production

1. **UNAPPROVED_CONTEXT:** численно определить dealing range 4h/D, premium/discount,
   направление/порог, unmitigated FVG и OB, правила их комбинации и актуальности.
   Никакого фиктивного пропуска этого фильтра «как утверждённого» здесь нет.
2. Утвердить **одно** окно и точные session/timezone правила; наследуемые числа
   sweep/FVG/дедлайна/срока уровней пока исследовательские.
3. Утвердить SL-тик/буфер, биржу и futures-свечи; SPOT не эквивалентен BingX.
4. Отдельно интегрировать дедупликацию, ограничения позиций/риска и сопровождение,
   затем проверять доходность с издержками и неизбежной неоднозначностью OHLC.

Live `smc_detector.py`, `config.json`, `out/seen.json`, `risk.py`, `limits.yaml`
и расписание этой работой не менялись. Активация не выполнялась.

Код, карточка и публичные данные/отчёты сохранены в репозитории; это не разрешение
