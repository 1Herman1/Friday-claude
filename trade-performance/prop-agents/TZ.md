# ТЗ: Автономная торговая система ИИ-агентов на пропах (prop-agents) — v3

Статус: рабочая версия. Владелец: Герман. Обновлено: 2026-10-10.
Источники: ТЗ DeepSeek v1.0, исследование «Open-source основы для мультиагентной LLM-торговли», решения из чата 2026-10-06…10, [`../research/props-and-testbeds.md`](../research/props-and-testbeds.md).
Связанные документы: [`ARCHITECTURE.md`](ARCHITECTURE.md) — роли агентов; [`STRATEGY_CARD_TEMPLATE.md`](STRATEGY_CARD_TEMPLATE.md) — чек-лист карточки стратегии; [`../journal/TZ.md`](../journal/TZ.md) — дневник трейдера.

## 1. Цель

Много ИИ-агентов, сгруппированных в кластеры по стратегиям, торгуют на демо, затем на крипто-пропах, где автоматизация разрешена правилами. Система сама ищет улучшения, но не может ослабить риск-лимиты.

## 2. Понятия

- **Кластер** — группа агентов на одной стратегии (например `smc-btc`).
- **Агент** — экземпляр: кластер + версия + модель + площадка, со своим счётом и топиком.
- **Карточка стратегии** — `clusters/<имя>/strategy.md` (по чек-листу) + жёсткие числа в `config.json` / `rules.yaml`.
- **Детектор** — код, который находит сетап по числам свечей. Без LLM.

## 3. Главный принцип

**Код ищет и считает, LLM оценивает, риск решает код.**
- Сетап, уровни входа/стопа/тейка, размер позиции — код. Причина: в тесте 2026-10-07 разные модели по одним данным давали разные уровни, часть — с отрицательным R:R.
- LLM: контекст рынка, разбор картинки графика, новости, дебаты «за/против», итоговое ВЗЯТЬ/ПРОПУСТИТЬ, разбор сделок, предложения улучшений.
- LLM вызывается только при сигнале детектора.

## 4. Кластеры

| Кластер | Суть | Где | Статус |
|---------|------|-----|--------|
| SMC-BTC | Снятие ликвидности → CHoCH → вход от FVG | Пропы | Детектор v0.1 работает (сигналы) |

## 5. Архитектура (подробно — ARCHITECTURE.md)

1. **Данные** (код): свечи, фандинг, OI, ликвидации, новости, сентимент. Всё с временем публикации — агент видит только прошлое. Только закрытые свечи.
2. **Детекторы** (код, по одному на кластер).
3. **Мозг кластера** (LLM, только при сигнале): Context Analyst → Chart Vision → News & Sentiment → Bull/Bear → Strategy Trader. Выход — JSON по схеме; невалидный ответ = HOLD.
4. **Глаза**: код рисует график с разметкой → vision-модель; режим B — агент сам открывает график в браузере.
5. **Шлюз моделей** (при переходе на API): OpenRouter/LiteLLM, модель — строка конфига, логируются токены и стоимость.
6. **Риск-слой** (код, неизменяем для агентов): размер от риска и стопа, плечо, R:R, дневной/общий лимит по equity, профиль пропа, серия убытков → пауза, whitelist, kill-switch. Меняет только Герман.
7. **Исполнение** (код): API-адаптеры (Hyperliquid testnet, OKX Demo, BloFin demo, Propr, HyroTrader), терминал в браузере там, где разрешено (SizeProp). Order Manager: стопы на стороне биржи, безубыток, трейлинг, выход по времени.
8. **Арена**: матрица {модель × кластер × площадка}, у каждой ячейки свой счёт, N≥3 повтора, бейзлайны без LLM (buy&hold, простое пересечение MA, детектор без LLM-фильтра).
9. **Журнал**: промпты, ответы, решения риска, ордера, филлы, комиссии, стоимость LLM → PostgreSQL → дневник.
10. **Улучшатели** (по расписанию): Post-Trade Reviewer, Strategy Researcher → новая версия в тени → замена только после победы на живых данных после комиссий и стоимости LLM, с подтверждения Германа. Риск-лимиты и допуски на проп агентам не доступны.
11. **Надзор**: Сторож (код: kill-switch, связь, сверка позиций), Диспетчер (Hermes: расписания, очереди), Telegram.

## 6. Оркестрация на старте — Hermes (решение 2026-10-09)

- Отдельного API-ключа нет: LLM-роли выполняет Hermes (Claude) на подписке.
- Схема: cron Hermes каждые 5 мин запускает монитор-скрипт (`~/.hermes/scripts/smc_btc_monitor.sh`) → детектор `--live`. Вывод монитора меняется только при новом сигнале → только тогда Hermes будит агента. Нет сигнала — LLM не тратится.
- При сигнале агент читает `out/last_signal.json` и картинку, тянет контекст (1h/4h, 24h, фандинг MEXC), отыгрывает роли и шлёт карточку ВЗЯТЬ/ПРОПУСТИТЬ с картинкой в Telegram. Уровни не меняет.
- Торговли нет: только сигналы (этап Ф2). Дальше — полуавто (кнопку жмёт Герман), потом демо-исполнение.
- Ограничения: лимиты подписки; Mac должен быть включён; задержка 1–5 мин (вход лимиткой это смягчает); правила подписки на массовую автоматизацию проверить до реального пропа.
- Переход на API (Anthropic/OpenRouter) и сервер — когда упрёмся в лимиты, понадобится 24/7 или >3–4 агентов на арене.

## 7. Детектор SMC-BTC v0.1 (реализован 2026-10-09)

Файлы: `clusters/smc-btc/smc_detector.py`, `clusters/smc-btc/config.json`. Окружение: `prop-agents/.venv` (pandas, numpy, matplotlib). Свой код вместо библиотеки `smartmoneyconcepts` — прозрачные правила, которые Герман может поправить числом.
- Рынок: BTCUSDT, MEXC spot, вход 5m, фильтр 1h.
- Swing: экстремум выше/ниже 3 свечей с каждой стороны, подтверждается через 3 свечи (без заглядывания в будущее).
- Sweep: тень за последний swing, закрытие обратно.
- CHoCH: в течение 24 свечей (2 ч) после sweep закрытие тела за противоположный swing.
- FVG в импульсе sweep→CHoCH, размер ≥ 0,03%. Вход — лимит на ближней границе FVG, живёт 24 свечи.
- Стоп: экстремум sweep ± 0,03%; допустимый стоп 0,10–0,80%. Тейк: RR 1:2.
- Фильтр: лонг только если 1h close > EMA50, шорт — если ниже.
- Статусы: pending / open / win / loss / expired / cancelled (тейк до входа). Свеча со стопом и тейком одновременно = стоп.
- Режимы: без флага — история + `out/history.png`; `--live` — только новые сетапы → `out/last_signal.json`, `out/live.png`.
- Первый прогон (25.09–09.10, 4031 свеча): 19 сетапов, закрыто 12, винрейт 50%, +6R без комиссий, ≈ +3,8R с комиссией 0,04%. **Выборка мала — это проверка кода, не стратегии.**
- Все числа — классический SMC по умолчанию; заменить на правила Германа через карточку стратегии.

## 8. Telegram: группы и топики

- Отдельная группа под трейдинг, внутри — топики по ролям. Карта топиков — в [`../README.md`](../README.md).
- **Общий топик** — весь масштабный проект (ТЗ, архитектура, решения, сводки); **топик на подпроект** — journal, инфраструктура prop-agents, исследования; **топик на кластер** — сигналы, решения, сделки, итог дня, предложения улучшателя.
- Команды в топике кластера: `/context`, `/rule`, `/why <id>`, `/pause`, `/resume`.
- Чат — только вход. Агент в торговом цикле читает карточку из репо, не историю чата. Правка → новая версия → тень → замена.
- Cron SMC-BTC доставляет сигналы в чат, где создан; перенести в топик SMC-BTC, когда известен его ID.

## 9. Правила пропов

Каждый проп — профиль в БД: цель, дневной лимит (метод и время сброса), макс. просадка (статическая/трейлинг), плечо, обязательный стоп, мин. дни, запрещённые практики, политика ботов. Не в промптах.
Автоматизация — только где разрешено или с письменного разрешения. Маскировку бота под человека не делаем.

## 10. LLM

- Claude Opus 5.5 — финальное решение, исследователь стратегий; Claude Sonnet 5.5 — аналитики, дебаты, vision, разбор сделок.
- На старте всё через Hermes.
- Бесплатные модели OpenRouter — черновые прогоны и бейзлайн (рабочие на 2026-10-07: Laguna S 2.1, Ling 3.0 Flash, Apodex mini, dots-3).
- Модели выбираем по своей арене; TradingArena.ai — только ориентир.
