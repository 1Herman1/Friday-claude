## 1. Цель

ИИ-агенты, сгруппированные в кластеры по стратегиям, торгуют на демо, затем на крипто-пропах, где автоматизация разрешена. Система сама ищет улучшения, но не может ослабить риск-лимиты.

## 2. Главный принцип

**Код ищет и считает, LLM оценивает, риск решает код.**
- Сетап, уровни, размер позиции — код (в тесте 2026-10-07 модели по одним данным давали разные уровни, часть — с отрицательным R:R).
- LLM — контекст рынка, разбор картинки, новости, «за/против», ВЗЯТЬ/ПРОПУСТИТЬ, разбор сделок, предложения улучшений. Вызывается только при сигнале детектора.
- Риск-лимиты меняет только Герман. Бот на пропе не маскируется под человека: автоматизация только где разрешена или с письменного разрешения.

## 5. Архитектура (подробно — ARCHITECTURE.md, папки — DATA_ARCHITECTURE §6)

1. **Данные** (код): свечи, фандинг, OI, ликвидации, новости — с временем публикации, только закрытые свечи.
2. **Детекторы** (код, по кластеру) → сигнал по контракту `signal.v1`.
3. **Мозг** (LLM, только при сигнале): Context → Chart Vision → News → Bull/Bear → Strategy Trader → `decision.v1` (JSON; невалидный ответ = HOLD).
4. **Риск-слой** (код) → APPROVE/REDUCE/REJECT + размер.
5. **Исполнение** (код): адаптеры Hyperliquid testnet, OKX Demo, BloFin demo, Propr, HyroTrader; терминал в браузере только где разрешено. Стопы на стороне биржи.
6. **Журнал**: сигналы, решения, вызовы LLM, проверки риска, ордера, исполнения → общая БД → дневник.
7. **Арена**: {модель × кластер × площадка}, свой счёт у каждой ячейки, N≥3, бейзлайны без LLM.
8. **Улучшатели**: разбор сделок, новая версия в тени, замена только после победы после комиссий и с подтверждения Германа.
9. **Надзор**: Сторож (kill-switch, связь, сверка позиций), Hermes (расписания), Telegram.

## 6. Этапы и критерии готовности

**P1 — детектор готов к БД** (сейчас, Т1)
- Номера свечей → время (`sweep_time`, `fvg_time`, `fill_time`, `exit_time`).
- Ключ сигнала: символ + ТФ + кластер + версия + время + сторона.
- Live-прогон обновляет статус открытых сигналов (pending → open → win/loss/expired/cancelled).
- Проверить, что время закрытия свечи MEXC стабильно между прогонами.
- В истории считать и R, и R после комиссий.
- Готово, когда: перепрогон истории даёт те же ключи; тесты на детектор.

**P2 — бумажная торговля (форвард-тест)**
- Каждый сигнал SMC → решение Hermes (ВЗЯТЬ/ПРОПУСТИТЬ) → риск-слой → виртуальный счёт с профилем demo → учёт исполнения по живым свечам.
- Параллельно бейзлайн: тот же детектор без LLM-фильтра — чтобы видеть, добавляет ли LLM пользу.
- Пока БД не готова — файл; после J0 — запись в общую БД (сигналы, решения, проверки риска, виртуальные сделки).
- Готово, когда: каждый сигнал имеет след «сигнал → решение → риск → результат»; ежедневный итог в Т5.

**P3 — общая БД** (после J0 дневника)
- Детектор, решения Hermes и риск пишут в PostgreSQL; `seen.json` заменяется уникальным ключом; история перепрогоняется детектором v0.1 в БД.
- Дневник показывает сделки агентов.

**P4 — демо-исполнение и арена** (4–8 недель)
- Адаптер демо-площадки, Order Manager, Сторож; MA-cross как второй кластер и бейзлайн.

**P5 — проп**
- Сверить правила выбранного пропа по T&C и заполнить профиль; Propr Beta → челлендж с минимальным счётом и kill-switch.
- Перед реальным пропом — проверить правила подписки Claude на автоматизацию или перейти на API.

**P6 — улучшатели и тени.**

## 7. Оркестрация через Hermes

- LLM-роли выполняет Hermes на подписке; отдельного API нет.
- Детектор без LLM каждые 5 мин; агент будится только при новом сигнале; карточка ВЗЯТЬ/ПРОПУСТИТЬ с картинкой в Т5. Уровни агент не меняет.
- Ограничения: лимиты подписки; Mac должен быть включён; задержка 1–5 мин (вход лимиткой).
- Переход на API и сервер — при упоре в лимиты, нужде в 24/7 или >3–4 агентах на арене.

## 8. Правила пропов

Каждый проп — профиль: цель, дневной лимит (метод и время сброса), макс. просадка (статическая/трейлинг), плечо, обязательный стоп, мин. дни, запреты, политика ботов. Сейчас — YAML в `engine/profiles/`, после P3 — в БД (только чтение для движка, изменения — новой записью с историей).
Площадки: Propr (API, Beta), HyroTrader (бот через BloFin), SizeProp (терминал). Hash Hedge — только после письменного разрешения. Bybit заблокирован; MEXC — данные.

## 9. LLM

Claude Opus 5.5 — решение и исследователь; Sonnet 5.5 — аналитики, дебаты, vision, разборы (при переходе на API). Сейчас всё через Hermes. Бесплатные модели OpenRouter — черновые прогоны и бейзлайн. Модели выбираем по своей арене.
