# H&B Learning Department — локальная v0.1

Первая работающая учебная веб-среда для одного сотрудника и владельца. Не только HTML-макет: Python HTTP backend, SQLite, реальные файлы учебного проекта и серверная проверка ролей.

## Запуск

Из корня репозитория:

```sh
cd projects/hb-learning-department
python3 app.py --port 8765
```

Открыть `http://127.0.0.1:8765` на том же компьютере. По умолчанию доступны только loopback-адреса. Если порт занят, выбрать другой через `--port`.

При первом запуске создаются `.local/learning.sqlite3`, `.local/tokens.json` и каталог учебных проектов. Роли owner и student получают разные случайные токены. Сервер печатает только путь к файлу доступа, не значения. Владелец открывает файл локально и вводит нужный токен в форме входа; ученик получает только student-токен по защищённому каналу. Не присылать токены в Telegram и не добавлять файл в Git. Каталог `.local` исключён из Git; SQLite и файл токенов имеют права 0600, основной каталог создаётся с 0700.

Для подготовки без запуска сервера:

```sh
python3 app.py --bootstrap
```

Можно указать отдельное хранилище через `--data-dir` и разрешённые материалы через `--course-dir`. Это параметры владельца при запуске, не поля запроса ученика.

## Что действительно работает

- Две роли с проверкой Bearer-токена на сервере; поле `role` в теле сообщения не даёт прав.
- 24 учебных дня из согласованного `course.md`; подробный текст выбирается из фиксированного `lessons/day-NN.md`, если он существует.
- Один постоянный диалог, сохранение сообщений, проекта, поданных работ и прогресса в SQLite.
- Создание одного собственного учебного проекта; чтение/запись допустимых текстовых файлов только внутри него.
- HTML/CSS-предпросмотр с очисткой разметки, пустым `sandbox` iframe и ограничительной CSP; скрипты, сеть, внешние ресурсы, ссылки и формы не работают.
- Подача работы с объяснением, свидетельствами и снимком файлов. Решение owner фиксируется; ученик не может принять себя сам.
- Production-допуск закрыт, пока нет 24 принятых дней и явной аттестации owner. Даже после допуска приложение не публикует сайты и не выдаёт доступ к клиентским системам.
- Локальный журнал инцидентов с объединением повторов, статусом и безопасными кодами вместо секретов и полного текста исключений.
- Защищённая загрузка PDF-учебника через `/api/handbook`; произвольный путь параметром не выбирается.
- Ограничения размера запроса, отдельных файлов, проекта, количества файлов и частоты обращений; запрет обходов пути, symlink и доступа к ядру через файловый API.

## Live-наставник: выключен по умолчанию

Без провайдера сообщение сохраняется, запрос модели остаётся в очереди, интерфейс показывает «провайдер не подключен». Ответ ИИ не имитируется. Владелец видит очередь и может повторить запрос после настройки.

Адаптер поддерживает OpenAI-compatible Chat Completions API с серверными переменными `HB_MENTOR=openai`, `HB_API_URL` (базовый адрес, заканчивающийся на `/v1`), `HB_API_KEY`, `HB_MODEL`. Ключ не возвращается клиенту. Поддержан HTTPS и локальный HTTP для контролируемого теста; перенаправления запросов провайдера запрещены. Не хранить реальные значения в коде или командных примерах.

Это НЕ подключённый Hermes/Codex runtime. Наличие личной подписки не превращается автоматически в API-доступ или разрешённый многопользовательский сервис. Реальный провайдер и схема доступа требуют отдельного согласования и проверки. В текущем релизе внешняя модель на реальном ключе не тестировалась; тестировались только отключённое состояние и локальный контролируемый сервер отказа.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

Фактический прогон 14 ноября 2026: **31 backend-тест прошёл**. Он включает роли, невозможность повышения прав телом запроса, ограничения файлов, symlink, снимки/свидетельства, повтор подачи, production-gate, сохранение данных, очередь без провайдера, безопасные отказы upstream, сохранение системной инструкции в длинной истории, PDF-доступ и preview.

`tests/ui-smoke.cjs` выполняет настоящий браузерный сценарий с временными данными и отдельным сервером. Нужны `playwright-core` в тестовом окружении и совместимый Chromium. Он не устанавливает зависимости в корень монорепозитория. Параметры окружения: `HB_PLAYWRIGHT_MODULE` — путь к пакету, `HB_CHROME_PATH` — браузер, при необходимости `HB_PYTHON` — Python. Пример:

```sh
HB_PLAYWRIGHT_MODULE=/path/to/playwright-core HB_CHROME_PATH=/path/to/chromium node tests/ui-smoke.cjs
```

Фактический прогон прошёл: вход student → 24 урока → безопасное текстовое сообщение → проект/файл/preview → подача → решение owner → запрет раннего допуска → загрузка настоящего PDF → явный отказ live-наставника без поддельного ответа → восстановление после reload → экран 390 px без горизонтального переполнения. Отчёт: `reports/ui-smoke.json`; изображения — `reports/screenshots/`. Это демонстрационные тестовые записи, не аттестация реального сотрудника. Реальные локальные данные рабочего экземпляра тест не меняет.

## Границы v0.1

Это локальная подготовительная версия, не готовая удалённая платформа и не полноценная операционная песочница. Процесс Python работает с правами своего пользователя; HTTP API ограничен, но администратор компьютера может изменить локальный код. Не открывать сервер в интернет или учащемуся удалённо без отдельного security review, TLS/защищённого доступа, изоляции процесса, бэкапов и проверенного восстановления.

Пока нет: подключения нового Telegram-бота и группы; уведомлений в Telegram; исполнения JS/React/тестовых команд; деплоя проектов; integration с Hermes/Codex; нескольких учеников; настоящего внешнего LLM-запроса. Развёрнутые материалы в наличии для пяти дней, остальные показывают согласованную программу. Весь практический курс нельзя считать технически готовым к запуску только по этой v0.1.

Следующий этап: выбранный удалённый хост и безопасный доступ, согласованный модельный backend, изолированный исполнитель учебного кода, завершение подробных занятий и видеоподборки. Основная конфигурация Hermes, её авторизация и клиентские проекты этим приложением не изменяются.
