# Скрипт импорта оптовых цен — import-prices.ts

Идемпотентный скрипт переноса оптовых цен и признака «профессиональный» из JSON в каталог.

## Запуск

### Сухой прогон (по умолчанию, без записи в БД)
```bash
npm run import:prices
```

Прочитает `assets/price-import.json`, выведет таблицу сопоставлений, список несопоставленных и расхождений розничной цены, но ничего не изменит.

### Применение изменений (запись в БД)
```bash
npm run import:prices -- --apply
```

Выполнит сухой прогон и при совпадениях запишет изменения в одной транзакции. После записи:
- обновятся `ProductVariant.wholesalePrice` и `ProductVariant.isProfessional`
- пересчитается `Product.isProfessional` (true только если ВСЕ активные фасовки профессиональные)
- пересчитаются `Product.minPrice` и `Product.maxPrice` (без профессиональных фасовок)

### Другой входной файл
```bash
npm run import:prices -- --file path/to/custom-prices.json --apply
```

## Формат входного JSON

```json
{
  "_meta": {
    "source": "Источник данных",
    "date": "2026-09-22",
    "note": "Необязательное описание"
  },
  "items": [
    {
      "name": "Название товара или его начало",
      "volume": "50 мл",
      "wholesaleKopecks": 450000,
      "retailKopecks": 807700,
      "isProfessional": false
    }
  ]
}
```

- **name**: сопоставляется по полному или частичному совпадению (нормализация: нижний регистр, ё→е, кавычки и спецсимволы удаляются)
- **volume**: парсится как "число единица", единицы: мл/ml, г/g, шт/pcs
- **wholesaleKopecks**: оптовая цена в копейках
- **retailKopecks**: розничная цена (проверяется, не переписывается; null = не менять)
- **isProfessional**: признак кабинетной позиции

## Логика сопоставления

1. **Поиск товара**: нормализованное имя из прайса равно, является префиксом или содержит нормализованное имя каталога как префикс
2. **Выбор фасовки**: если несколько фасовок — выбор по `volumeValue` и `volumeUnit`; если одна фасовка — берётся независимо от volume
3. **Неоднозначности**: если под запись подходит больше одного товара — репортится как неоднозначная, не обрабатывается
4. **Несопоставленные**: товары, не найденные в каталоге или фасовки не совпали — репортируются отдельной секцией

## Отчёт сухого прогона

```
✅ СОПОСТАВЛЕНО: таблица первых 10 совпадений (товар, объём, цена, профессиональный)
⚠️ НЕСОПОСТАВЛЕННЫЕ: список записей, которые не нашли товар
🔀 НЕОДНОЗНАЧНЫЕ: записи, подошедшие к нескольким товарам
💰 РАСХОЖДЕНИЯ РОЗНИЧНОЙ ЦЕНЫ: товары, где прайс отличается от БД (не меняем)
📊 СВОДКА: числа сопоставлено/не сопоставлено/неоднозначные/расхождения
```

## Особенности

- **Идемпотентно**: повторный `--apply` на одних и тех же данных не изменит ничего (проверяются текущие значения)
- **Розничная цена не меняется**: если `retailKopecks` из прайса отличается от текущей цены, это выводится в отчёт, но не применяется. Розница — отдельное бизнес-решение
- **Профессиональный флаг**: `Product.isProfessional` становится `true` ТОЛЬКО если ВСЕ активные, не удаленные фасовки имеют `isProfessional = true`
- **Единая транзакция**: все изменения либо применяются полностью, либо откатываются при ошибке

## Примеры команд

```bash
# Проверить структуру файла и сопоставления
npm run import:prices

# Применить с дебагом
npm run import:prices -- --apply 2>&1 | tee import.log

# Использовать файл из другой директории
npm run import:prices -- --file /tmp/prices-update.json --apply
```

## Юнит-тесты

Функции нормализации и сопоставления покрыты 25 unit-тестами (не требуют БД):
```bash
npm run test -- src/test/import-prices.unit.test.ts
```

Тесты проверяют:
- Нормализацию текста (регистр, ё→е, кавычки, спецсимволы, пробелы)
- Логику сопоставления (префиксы, точные совпадения)
- Парсинг объёмов (все единицы: мл, г, шт; целые и дробные значения)
- Интеграцию сопоставления товара и фасовки
