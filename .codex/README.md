# Friday для Codex

Адаптация рабочего набора Claude. Собственные инструкции и память Codex
находятся в .codex/. Исходные CLAUDE.md и .claude/ не изменяются.
Код продуктов исправляется только в рамках отдельной разрешённой задачи.

## Запуск

В локальном клоне Friday с Python 3.11+, Node.js, npm и установленным Codex CLI:

```bash
bash .codex/setup.sh
bash .codex/start.sh
```

В дальнейшем достаточно запускать `codex` из этого репозитория. В доверенном
проекте Codex сам читает .codex/config.toml: загружает входные инструкции,
регистрирует роли, подключает установленный скилл-плагин и события хуков. Каждый раз писать
«прочитай CODEX.md» не требуется. При первом запуске подтвердите штатное
доверие к проекту и хукам в интерфейсе Codex; конфигурация не обходит его.
Уже открытая сессия получает новые настройки после перезапуска.

## Что перенесено

- Полные правила CLAUDE.md → CODEX.md с адаптацией инструментов и обращением «Гермес».
- Все 45 ролей → agents/*.toml и читаемые инструкции по департаментам.
- Добавлен codex-docs для вопросов о самом Codex; anthropic-docs сохранён.
- Семь скиллов и 15 команд → 22 скилла в skills/, подключённые локальным плагином friday-workflows.
- Шесть процессов → workflows/.
- Проверки дизайна, права, переносимости, скриншоты и остальные утилиты → scripts/.
- Три MCP-сервера: 21st, icon-library и nullume.
- Пять событий: SessionStart, PostToolUse, PreCompact, Stop, SessionEnd.
- Полная карта исходников и их хешей → migration-manifest.json.

Все роли наследуют модель основной сессии. Названия моделей Anthropic
не выдаются за модели OpenAI. По смыслу задачи Codex выбирает нужных
специалистов автоматически; все 46 сразу на каждую задачу не запускаются.
Команды вызываются как `$feature`, `$review`, `$secure`, `$preflight` и т. д.

## Автоматизация

Обязательный цикл до соответствия ТЗ — workflows/review-loop.md.
Task gate привязывает критерии, проверки и независимые ревью к текущей
версии файлов. Stop возвращает активную незавершённую задачу на доработку;
реальный внешний блокер отмечается отдельно и не считается готовностью.

SessionStart подаёт контекст, проект и ветку. PostToolUse проверяет изменённые
UI-файлы через design-lint и не повторяет проверку неизменённого содержимого.
Stop сохраняет технические факты в игнорируемом .runtime/, PreCompact и
SessionEnd создают краткую запись накопленной работы, включая уже выполненные
коммиты, удаления и новые файлы. Пояснения агента сохраняются при повторном сбросе.
Хуки не копируют переписку и не выполняют Git pull, переключения, коммиты
или деплои. Эти действия выполняют агенты по правилам задачи.

Смысловые итоги, результат, реальные проверки и следующий шаг агент сохраняет
в context.md / sessions/. Историческую память Claude можно читать, но свои
записи Codex добавляет сюда. Hermes-задачи и системные cron на Mac не меняются
публикацией GitHub-файлов; подключение описано в workflows/hermes.md.

## MCP и ключи

`setup.sh` устанавливает зависимости локальных MCP-инструментов и регистрирует
локальный плагин friday-workflows в Codex. Файлы плагина остаются в .codex/;
регистрация хранится в пользовательских настройках Codex.
Каталог skills/ сам по себе не объявляется нативно обнаруженным: для этого
используется плагин.
Для 21st требуется TWENTYFIRST_API_KEY, для платной генерации Nullume —
KIE_API_KEY, для Lottie — LOTTIEFILES_API_KEY. Передайте их через защищённое
окружение запуска; значения в Git и в чат не добавлять. Статические иконки
и локальные проверки доступны без ключа генерации.

## Проверки

```bash
python3 .codex/scripts/selftest.py
python3 -m unittest discover -s .codex/scripts -p 'test_*.py' -v
```

Selftest проверяет непустой реестр ролей, 22 скилла, хуки, регистрацию MCP,
синтаксис и изменения исходников. При изменении .claude/ он сообщает, что
нужна повторная адаптация; существующие роли не перезаписываются молча.
Проверки текущего переноса перечислены в validation.md.

Проектная конфигурация действует в клиентах, поддерживающих эти механизмы.
Управляемая облачная среда может задавать собственные ограничения; они
сохраняют приоритет. Наличие конфигурации не заменяет реальные доступы к
GitHub, серверу, Hermes, браузеру и платным сервисам.


## Выполнение задач и цикл ревью

Контракт: workflows/review-loop.md. Координатор фиксирует критерии ТЗ,
обязательные проверки и независимых ревьюеров. scripts/changes.py собирает
staged/unstaged/untracked/deleted и изменения после SHA начала задачи.
Task gate требует актуальные доказательства для текущего содержимого и
исполняемости файлов; конфликт index/worktree блокирует готовность.
Stop-хук возвращает активную задачу на доработку до выполнения критериев.
Это не самопроверка достоверности отчётов: результаты реальных запусков
и независимые reviewer ID должны быть записаны честно.

ID owner-session подаёт SessionStart. Для параллельных задач задай при init
--scope с файлами/каталогами задачи, например --scope projects/perfect-skin.
Без --scope применяется весь репозиторий: чужие изменения консервативно
инвалидируют ревью. Конечные роли исполняют порученную область сами,
координаторы запускают проверки волнами по свободным слотам.

Смысловые итоги сохраняются в context.md/sessions; автоматический архив
добавляет только Git-факты, сохраняет пояснения и не копирует переписку.
Исходные инструкции Claude при изменении вызывают предупреждение о
необходимости синхронизации, а не запрещают открыть Codex для исправления.
