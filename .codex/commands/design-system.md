# design-system

Генератор дизайн-системы под конкретный продукт/страницу. Не про ревью готового
UI (`/audit-design`) и не про правки (`/polish`) — это про то, чтобы задать
характер интерфейса ДО написания кода **и зафиксировать его на диске**, чтобы
токены не переизобретались каждую сессию.

Использование:
- `/design-system` — дизайн-система проекта целиком → пишется в `MASTER.md`
- `/design-system [страница]` — переопределения для страницы → `pages/<страница>.md`

## Порядок

1. **Определи контекст.** Тип продукта, аудитория, вайб. Выведи явным списком
   **5–7 mood-ключевиков** — это промежуточный артефакт, который делает выбор
   проверяемым. Бренд проекта — `docs/projects/<проект>/brand.md`.

2. **Возьми доменный профиль.** Найди профиль в `docs/core/design-profiles.md`
   (таблица A; для лендинга — плюс паттерн из таблицы B) и возьми оттуда
   паттерн, роли палитры, motion, **доменные анти-паттерны и триггеры** как
   отправную точку. Суждение тратить только на отклонения и бренд-специфику.
   Проверить триггеры (`if_checkout`, `if_data_heavy`) — применимы ли.

3. **Задай регуляторы (dials).** `DESIGN_VARIANCE`, `MOTION_INTENSITY`,
   `VISUAL_DENSITY` из `docs/core/design-principles.md`. База проекта — в его
   `brand.md`. Отклонения объявить вслух и обосновать.

4. **Собери токены с готовыми значениями:**

   - **Палитра — обязательно ролями, парами «цвет + on-цвет»:**
     `background/foreground`, `card/card-foreground`, `muted/muted-foreground`,
     `primary/on-primary`, `accent/on-accent`, `border`, `success`,
     `destructive/on-destructive`, `ring`.
     Так контраст гарантирован структурно. Проверить каждую пару ≥ 4.5:1
     (крупный текст ≥ 3:1) и указать фактическое значение.
   - **Типографика** — пара из `docs/core/typography-pairs.md`.
     **Обязательно проверить поддержку кириллицы** для русскоязычного продукта.
     Дать готовый блок `fontFamily` и строку `<link>` подключения.
   - **Motion** — уровень из `MOTION_INTENSITY`, конкретные длительности и
     easing из `docs/core/motion.md`.
   - **Шкала отступов** — под `VISUAL_DENSITY`, кратность 4px.

5. **Запиши на диск.**
   - Полная система → `docs/projects/<проект>/design-system/MASTER.md`
   - Страница → `docs/projects/<проект>/design-system/pages/<страница>.md`,
     и **только дельты** к MASTER, не копия целиком.
   - В шапке MASTER — правило приоритета: *если существует `pages/<страница>.md`,
     он переопределяет MASTER*.
   - Имя страницы слугифицировать (`Корзина` → `cart`), путь не должен выходить
     за пределы `design-system/`.
   - **Если файл уже существует — не перезаписывать.** Сообщить об этом и
     спросить: обновить точечно или перегенерировать целиком. Молча затирать
     существующую дизайн-систему запрещено.

6. **Pre-delivery чек-лист.** Приложи выжимку P1–P2 из
   `docs/core/ux-guidelines.md` (доступность + тач) как пункты приёмки.

## Правила

- Не генерировать «типовой красивый» интерфейс — держать характер бренда
  проекта и не повторять AI-slop из `docs/core/design-principles.md`.
- Не плодить токены сверх нужного — минимальная палитра и шкала.
- Результат — спецификация на диске, не код. Реализация — отдельным шагом
  через `coder` или `/feature`.
- MASTER.md — источник истины для `coder` и для `design-lint.mjs`: линтер
  сверяет код с зафиксированными здесь палитрой, шрифтом и шкалой.
