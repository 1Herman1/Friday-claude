# Новая фича

Следуй `.codex/workflows/review-loop.md` до соответствия ТЗ: task gate,
полный scope staged/unstaged/untracked/deleted и коммитов с начала задачи,
независимое ревью и повторная проверка текущей revision обязательны.
Координатор запускает специалистов штатным доступным механизмом; конечные
специалисты выполняют свою область сами. Нет spawn — конкретный blocker,
а не обещание нативной активации.

1. `planner` — декомпозируй описание фичи из запроса пользователя:
   файлы и риски, критерии готовности и минимальный поэтапный план.
2. `researcher` — найди похожую логику и точки интеграции (лимит 15 файлов
   только для первоначального поиска аналогов). Изучи текущую архитектуру,
   выяви все затронутые файлы и передай контекст следующему специалисту.
   Лимит не ограничивает полный scope ревью или явный исчерпывающий аудит.
3. `architect` — если трогаем БД/API: схема и контракт роута;
   стек бери из `docs/projects/<проект>/project.md`.
4. `coder` — реализуй минимально необходимый код в стиле и стеке проекта,
   передай ему план и результаты исследования; следуй `docs/core/rules/`.
   Сохраняй TDD: RED → GREEN → REFACTOR, без лишних функций.
5. Ревьюеры по типу файла — параллельно независимыми волнами в пределах
   слотов: `typescript-reviewer` для .ts, `react-reviewer` для .tsx,
   `database-reviewer` при изменении схемы БД. `code-reviewer` — качество,
   безопасность и fallback для остальных языков; `security-secrets-scanner`
   не исключается. `silent-failure-hunter` проверяет тихие ошибки.
   Проверяй полный scope, не только файлы первоначального исследования.
6. `qa-engineer` — покрой тестами связанное с деньгами, доступом или инвариантами
   (сток, идемпотентность). Для остального достаточно ручной проверки сценария,
   если ТЗ и обязательный review-loop не требуют дополнительных проверок.
7. Проверь сборку и ключевой E2E-сценарий; запиши фактические команды и результаты.
   Отсутствие среды или skip не считаются успешным выполнением.
8. Исправь каждую подтверждённую находку; повторяй затронутые тесты, сценарии
   и независимое review текущей revision, пока все критерии ТЗ выполнены
   и нет открытых дефектов. Самопроверка не заменяет независимое ревью.
9. Сохрани смысловую память Codex, проверь итоговый scope, затем закрой
   `task_gate.py complete`. Коммит и пуш на рабочую ветку — только после завершения и проверки.
   Ветку проверь по `docs/projects/README.md`, контекст и выкатку — по
   `docs/projects/<проект>/project.md`; чужую незавершённую работу не включай.
   Публикация только в разрешённом scope по runbook, затем её проверка.

Явный запрет на commit/push/deploy, бюджет, права, preview/pilot и owner acceptance
сохраняются; workflow не расширяет полномочия. Внешний блокер объявлять явно.
Не путать неизвестный результат с pass.
