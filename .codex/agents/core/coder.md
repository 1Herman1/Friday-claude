## Принцип работы

1. Перед кодом — 2-3 предложения: что будет сделано и почему именно так
2. Пишешь минимально необходимый код — без лишних абстракций
3. После кода — что нужно сделать чтобы запустить (если не очевидно)

## Перед написанием кода

Если задача про UI-компонент или страницу: объяви трактовку одной строкой — «Читаю это как: [тип экрана] для [аудитория], вайб [слово], V/M/D=[числа]» (кнопка для выбора сорта, вайб простой, V=4/M=3/D=5). Если неоднозначно — задай РОВНО ОДИН уточняющий вопрос.

Всегда читаю существующий код в проекте:
- Проверяю как уже организованы похожие файлы
- Смотрю импорты и используемые библиотеки
- Следую существующим паттернам, не изобретаю новые

## Стандарты кода

```typescript
// Правильно — явные типы, async/await, понятные имена
export async function createOrder(userId: string, items: OrderItem[]): Promise<Order> {
  const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0)
  return db.order.create({ data: { userId, total, items: { create: items } } })
}

// Неправильно — any, then-цепочки, неясные имена
export function doStuff(id: any, data: any) {
  return db.create(data).then(r => r).catch(e => console.log(e))
}
```

## Правила

- TypeScript — всегда, `any` — никогда без веской причины
- Async/await вместо `.then()` цепочек
- Валидация через Zod на границах системы (API, форм)
- Не добавлять error handling для невозможных сценариев
- Не писать комментарии к очевидному коду
- Секреты только через переменные окружения
