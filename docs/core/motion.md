# Моторика (анимация и переходы)

Эталоны анимации и переходов для UI. Не запреты — конкретные значения,
которые нужно использовать. Источник вдохновения — принципы Эмиля Ковальски
(Vercel/Rauno) и подход Apple к движению интерфейса.

Этот файл отвечает на вопрос «как должно двигаться». Чем это делается —
`docs/core/motion-engine.md`: движок anime.js и обязательная обёртка
`client/src/lib/motion.ts`, через которую только и разрешены анимации на
движке. CSS `transition` при этом остаётся базой по умолчанию.

## 1. Гейт «надо ли анимировать?»

Частота действия определяет, нужна ли анимация вообще:

| Частота действия | Пример | Решение |
|---|---|---|
| 100+ раз/день | клавиатура, шорткаты | НЕ анимировать |
| Десятки раз/день | ховер, наведение | убрать анимацию или сильно сократить (< 100мс) |
| Изредка | модалки, шторки, корзина | стандартная анимация (см. таблицу длительностей) |
| Редко / первый раз | онбординг, пустые состояния | можно delight (чуть дольше, с характером) |

Правило: никогда не анимировать действия с клавиатуры (ввод текста, навигация
табом, шорткаты) — задержка воспринимается как лаг.

## 2. Easing

CSS-переменные (добавить в глобальные стили):

```css
:root {
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
  --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
}
```

Дерево выбора:
- Появление / уход (fade, поповер, модалка) → `--ease-out`
- Движение / морфинг (перемещение, ресайз, drag) → `--ease-in-out`
- Ховер / изменение цвета → `ease` (браузерный дефолт достаточен)
- Постоянное движение (marquee, спиннер) → `linear`
- Дефолт, если не уверен → `--ease-out`

НИКОГДА не использовать `ease-in` для UI-переходов — он тормозит старт, из-за
чего интерфейс ощущается медленным и вязким.

Единственное теоретическое исключение — уход элемента **за пределы экрана**, где
ускорение прочь читается естественно. На практике мы это исключение не
используем: `design-lint.mjs` намеренно помечает любой `ease-in` как ERROR.
Простое правило дешевле, чем исключение, которое будут применять не там.

## 3. Длительности

| Элемент | Длительность |
|---|---|
| Нажатие кнопки (press feedback) | 100–160мс |
| Тултипы, малые поповеры | 125–200мс |
| Дропдауны, селекты | 150–250мс |
| Модалки, шторки (drawer) | 200–500мс |

Правило: большинство UI-анимаций короче 300мс. Крупные поверхности (модалки,
шторки) могут доходить до 500мс. Дольше 500мс — уже воспринимается как «залипание»,
а не отклик.

**Привязка к MOTION_INTENSITY:** таблица выше соответствует **MOTION_INTENSITY=3**
(значение проекта — в его `brand.md`).
При M=3 только hover/active + короткие переходы, без parallax/scroll-hijack. Увеличение M
→ больше деlight-анимаций, стаггеры, scroll-reveal; уменьшение M → только критические
переходы (модалки, корзина), остальное статично.

## 4. Правила компонентов

- Кнопка при нажатии: `transform: scale(0.97); transition: transform 160ms var(--ease-out);`
- Никогда не появляться из нуля: не `scale(0)`, а `scale(0.95)` + `opacity: 0` →
  к `scale(1)` + `opacity: 1`.
- Анимировать ТОЛЬКО `transform` и `opacity` (GPU-композитинг). Не трогать
  `width`/`height`/`margin`/`padding` — это триггерит layout/reflow и тормозит.
- Поповеры — origin-aware: `transform-origin` указывает на триггер (кнопку,
  из которой поповер вырос). Модалки — `transform-origin: center`.
- Для динамичного UI (тосты, тоглы, чекбоксы) — использовать `transition`, а
  не CSS `@keyframes`/`animate-*`: `transition` можно прервать на середине без
  рывка, `keyframes` — нет.
- Стаггер между элементами списка: 30–80мс. Декоративный эффект, не должен
  блокировать ввод (пользователь может кликать пока анимация идёт).

## 5. prefers-reduced-motion

Не «убрать всё» — убрать движение/трансформ, но оставить `opacity`/цветовые
переходы (иначе интерфейс "телепортируется", что хуже, чем плавное появление):

```css
@media (prefers-reduced-motion: reduce) {
  * {
    transform: none !important;
    transition-property: opacity, color, background-color !important;
  }
}
```

Для анимаций на движке то же самое делает обёртка `client/src/lib/motion.ts` —
сама, без участия компонента. Прямой импорт `from 'animejs'` это правило
обходит, поэтому запрещён.

## 6. Пружины (Apple-подход)

Использовать параметры `damping ratio` + `response`, НЕ `mass`/`stiffness`
(они не переносятся интуитивно между компонентами).

- `damping: 1.0` (критическое затухание, без отскока) — для большинства UI
- `damping: ~0.8` (лёгкий overshoot) — только когда жест нёс инерцию (флик,
  свайп с разгоном)
- `response: 0.3–0.4с` — время до первого приближения к цели

| Переход | damping | response |
|---|---|---|
| Репозиция элемента | 1.0 | 0.4с |
| Поворот | 0.8 | 0.4с |
| Шторка (drawer) | 0.8 | 0.3с |

## 7. Мини-словарь терминов

- **Стаггер** — задержка между анимацией соседних элементов списка (30–80мс),
  создаёт ощущение каскада, а не одновременного появления.
- **Морфинг** — плавное превращение одной формы/состояния в другое (например,
  кнопка превращается в поле поиска), а не резкая замена.
- **Crossfade** — одновременное затухание старого элемента и появление нового
  вместо последовательного скрытия/показа.
- **Rubber-banding** — резиновое сопротивление у границы (скролл, свайп): чем
  дальше тянешь, тем больше сопротивление, без жёсткого стопа.
- **Momentum** — инерция после отпускания жеста (скролл продолжает двигаться
  и плавно тормозит), а не мгновенная остановка.
- **Interruptibility** — способность анимации быть прерванной новым вводом в
  любой момент без рывка (анимируем от текущего значения, не от целевого).
- **Press feedback** — визуальный отклик в момент нажатия (pointerdown), а не
  после отпускания (release) — снижает воспринимаемую задержку.
- **Scroll reveal** — появление элементов при попадании в viewport при скролле,
  обычно fade + небольшой translateY, не более 20px смещения.

## Производительность анимаций

- `will-change: transform` ставить **только** на элементы, которые реально
  анимируются, и снимать после. Проставленный «на всякий случай» он создаёт
  лишние композиторные слои и жрёт память — эффект обратный ожидаемому.
- Бесконечные анимации (спиннеры, marquee, пульсация) останавливать, когда
  элемент вне вьюпорта или вкладка неактивна — иначе они крутят рендер вхолостую.
- Не чередовать чтение и запись DOM в одном кадре (layout thrashing): сначала
  все чтения, потом все записи.

## Хореография группы

Когда анимируется не один элемент, а несколько сразу.

- **Иерархия движения.** Главный элемент получает максимальное смещение,
  поддерживающие — заметно тише по всем осям. Если все двигаются одинаково,
  сцена читается как шум, а не как сообщение.
- **Единый вектор.** Элементы одной группы входят с согласованных направлений.
  Смешение векторов (один слева, другой снизу, третий из масштаба) — визуальный шум.
- **Не больше трети.** Одновременно в движении — максимум ~1/3 элементов экрана.
- **Окно старта 50мс — для разнородной группы** (герой + подпись + кнопка от
  одного триггера): они начинают почти синхронно, иначе группа «рассыпается».
  К однородным спискам это не относится — там работает стаггер (см. выше),
  и разброс стартов там намеренно больше.
- **Паттерны стаггера:** последовательный (списки), center-out (сетка от центра),
  волна. Внутри одного паттерна — **единое семейство easing**, варьируется только
  тайминг.

## Длительность от расстояния

Длительность зависит не только от типа элемента, но и от пройденного пути:

- Смещение до ~200px — базовая длительность из таблицы выше.
- Смещение больше ~200px — прибавить к базовой; полноэкранные переходы берут
  верхнюю границу диапазона.
- **Выход = 65–75% от длительности входа.** Модалка вошла за 300мс → уходит за 200мс.
  Уход всегда ощущается быстрее — пользователь уже принял решение.

## Lottie-анимации (иконки)

До этого раздела весь файл — про CSS-transitions, это по-прежнему база по
умолчанию. Lottie — осознанное дополнение (см. `docs/decisions/ADR-003-icon-mcp-lottie.md`),
не замена: используй только когда статичный SVG недостаточен для передачи
смысла (состояние загрузки, success/celebration, сложный многошаговый
переход) — не как украшение по умолчанию. Для обычных UI-иконок статичный SVG
дешевле и предсказуемее.

- **Lazy-load.** Плеер и JSON грузить только при появлении элемента в
  вьюпорте (IntersectionObserver / динамический импорт) — не тянуть в
  основной бандл.
- **Бюджет размера.** Одна анимация ≤ 50–80КБ JSON после оптимизации. Крупнее
  — либо упростить (LottieFiles editor), либо вернуться к статичному SVG.
- **`prefers-reduced-motion` обязателен** — не автозапускать анимацию,
  показывать статичный первый кадр вместо loop.
- **Плеер** — `@lottiefiles/dotlottie-web` (легче классического `lottie-web`).
- **Источник и лицензия** — фиксировать у каждой сохранённой анимации (см.
  правила агента `icon-curator`).
