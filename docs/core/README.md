# Универсальная база (core)

Всё в `docs/core/` — **не привязано к конкретному проекту** и переносится в
новый проект как есть. Специфика проекта живёт отдельно, в
`docs/projects/<проект>/`.

## Состав

| Файл | Что внутри |
|---|---|
| `design-principles.md` | Глобальные anti-references (AI-slop), регуляторы dials, позитивные ориентиры |
| `design-profiles.md` | Доменные профили: e-commerce / SaaS / дашборд / лендинги. Анти-паттерны **домена** и триггеры переключения |
| `typography-pairs.md` | Проверенные шрифтовые пары с кириллицей, правила подключения |
| `ux-guidelines.md` | Кросс-доменный чек-лист по 10 категориям, приоритеты P1–P10 |
| `motion.md` | Анимация: длительности, easing, гейт «надо ли анимировать» |
| `apple-patterns.md` | Моторика: отклик, interruptibility, материалы |
| `stack.md` | Технологический стек по умолчанию для новых проектов |
| `rules.md`, `rules/` | Правила и соглашения кода (React, TypeScript) |
| `anti-patterns/` | Негативные списки по доменам. `security.md` — ядро отдела безопасности: 26 классов уязвимостей, не привязанных к стеку |
| `security-runtime.md` | Проверки на живой системе: снаружи, изнутри сервера, активные тесты |

## Как завести новый проект

1. Скопировать `docs/projects/_template/` → `docs/projects/<имя>/`.
2. Заполнить `project.md` (контекст, стек, ветка, как общаться) и `brand.md`
   (продукт, тон, аудитория, dials).
3. Указать доменный профиль из `design-profiles.md` в `brand.md`.
4. Сгенерировать дизайн-систему: `/design-system` → она запишется в
   `docs/projects/<имя>/design-system/MASTER.md`.
5. Сгенерировать профиль безопасности: `/security-profile` → он запишется в
   `docs/projects/<имя>/security-profile.md`. Без него агенты `security-*`
   работают, но менее точно.
6. В `CLAUDE.md` переключить ссылку на активный проект.

Универсальную базу (`docs/core/`) при этом **не трогать** — она общая.

> Что требует ручной адаптации под новый проект:
> - `.claude/commands/` — `deploy.md`, `feature.md`, `review.md` содержат специфику хостинга, стека и ветки;
> - `.claude/hooks/session-start.sh` — имя ветки захардкожено;
> - `.claude/settings.json` — переносить обязательно: без `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` отделы не работают;
> - `CLAUDE.md` — в части активного проекта;
> - часть агентов (`devops`, `react-reviewer`, `typescript-reviewer`, `database-reviewer`, `seo-specialist`) упоминают стек прямо в `description` — сверить под новый проект;
> - агенты `security-*` адаптации **не требуют**: стек они берут из `security-profile.md`.
>
> Переносимо без правок: `docs/core/` и агенты, не привязанные к стеку.

## Правило разделения

Если правило верно для любого проекта — оно в `core/`.
Если оно про конкретный продукт, бренд, бизнес-логику или домен данных — оно в
`projects/<проект>/`.

Сомневаешься — спроси себя: «это сломается, если завтра проект будет не
магазином, а SaaS?» Если да — это специфика проекта.
