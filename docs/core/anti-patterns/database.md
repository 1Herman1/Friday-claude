# Anti-patterns: база данных

Негативный список того, к чему модель тянется в работе с БД. Читается
`database-reviewer`; сверять находки с этим файлом.

**Стек:** универсальные правила для PostgreSQL; реальный стек проекта —
в `docs/projects/<проект>/project.md`. По умолчанию ORM — Prisma + PostgreSQL (см. `docs/core/stack.md`),
но конкретные пути схемы и сервисов зависят от проекта.

## Производительность запросов
- ❌ Prisma-запрос внутри `.map`/`for`/`forEach` (N+1) → `include`/`findMany` с `in`
- ❌ `findMany` без `take`/пагинации на потенциально больших таблицах
- ❌ Загрузка всей записи там, где нужен `select` из пары полей
- ❌ `include` глубоких вложенных связей, когда данные не используются
- ❌ Фильтрация/сортировка в JS после выборки вместо `where`/`orderBy` в запросе
- ❌ Несколько отдельных запросов там, где хватает одного `transaction`/`include`

## Индексы и схема
- ❌ Внешний ключ (`*Id`) без `@@index` — медленные join'ы и фильтры
- ❌ Поле, по которому часто ищут (`slug`, `email`), без `@unique`/`@@index`
- ❌ Relation-поле без обратной стороны (Prisma не сгенерируется, P1012)
- ❌ Отсутствие `createdAt`/`updatedAt` на новой таблице (см. docs/core/rules.md)
- ❌ Хранение денег во float → цены в копейках `Int` (`249900` = 2499 ₽)
- ❌ Каскад `onDelete` не продуман — либо `Cascade`, либо явный `Restrict`

## Целостность и доступ
- ❌ Уникальность/обязательность только в коде, без ограничения в схеме
- ❌ Мягкое удаление есть (`deletedAt`), но запросы его не учитывают
- ❌ Сырой SQL (`$queryRawUnsafe`) с пользовательским вводом (см. security.md)
- ❌ Миграция, меняющая тип/удаляющая колонку, без учёта существующих данных
