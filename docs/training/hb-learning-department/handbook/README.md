# Материалы студента — PDF v2

Редакция начата 15 ноября; сборка и итоговая проверка — 16 ноября 2026.

## Комплект

- `HB-Web-Development-Handbook.pdf` — 118 страниц, 22 главы, 100 терминов, 30 самостоятельных упражнений и 30 разборов в последнем разделе. 12 встроенных авторских схем/снимков примеров и 48 кликабельных внешних источников.
- `HB-Student-Workbook-24-Days.pdf` — 26 страниц, задания всех 24 дней, ежедневный дизайн-спринт, поля для собственных проверок и решения куратора. Основание — согласованный `../course.md`.
- `HB-Examples-v2.zip` — 10 файлов: полные HTML/CSS-примеры книги, JSON для чтения манифеста и инструкция. Это не копия репозитория; секретов и клиентских материалов в архиве нет. Автоматический импорт ZIP приложением не реализован.

В книге: состав веб-проекта, файлы и безопасность, зависимости и команды, путь DNS/IP/HTTP/HTTPS/API; композиция, типографика, сетка и адаптив; собственные концепции по клиентскому брифу, насмотренность, 3D/motion и полный сценарий нынешнего приложения.

Каждое упражнение следует за близким полностью разобранным примером; все входные данные даны рядом. Номера глав и учебных дней различаются. Решения самостоятельных заданий книги находятся после источников, не разбросаны по главам. Дневные работы практикума принимаются по артефактам и проверкам, а не по совпадению с единственным «правильным дизайном».

## Источники и границы

Включены ровно 10 каталогов референсов и 6 реальных видео (4 русскоязычных и 2 от GSAP/Spline). Для видео проверены ID, издатель, заголовок, описание и метаданные; полного просмотра, проверки каждого таймкода и педагогической приёмки всего видео не было. Подборка — предложенный маршрут, не мировой рейтинг и не отдельный видеокурс на все 24 дня.

`citations-ledger.json` — общий реестр 48 источников книги. Старый `source-verification.json` относится только к первоначальным 26 адресам; новые результаты/границы получения — `revision-v2/research/` и `revision-v2/design/source-notes.md`. Исходные страницы/полные описания видео и растры контроля остаются локальным gitignored-кэшем, не перепубликуются.

FORMA и остальные клиенты вымышлены. Скриншоты — реальные результаты авторских примеров, не доказательства работ ученика. Среда пока исполняет только HTML/CSS: без JS/React, внешней сети/картинок/форм, терминала и деплоя; live-наставник выключен. Содержание книги не означает готовность этих интеграций.

## Исходники и сборка

`handbook.md` / `continuation.md` — сохранённая база первой редакции. Актуальные новые главы, пары пример/упражнение, ответы и исследование находятся в `revision-v2/`. `assemble_revision.py` собирает `manuscript-v2.md`, `answers-v2.md`, проверяет пары и программу; `build_handbook.py` добавляет реестр источников перед ответами и пишет `complete-handbook.md` / PDF. Не заменять эту цепочку простой конкатенацией старых текстов.

Нужен управляемый Python документов с reportlab, pypdf, pypdfium2 и Pillow; основной интерпретатор Hermes не изменяется. Получение пути: `hermes pm environment documents --extra documents --extra documents-pdf`. Используются системные Arial/Courier New либо DejaVu; сами шрифты не копируются в Git.

Из этого каталога, где `python` — именно интерпретатор документов:

```sh
python assemble_revision.py
python make_diagrams.py
python export_examples.py
python build_handbook.py
python build_workbook.py
python -m unittest test_build_handbook -v
python verify_documents.py
```

Для реальных снимков макетов выполнить `projects/hb-learning-department/tests/handbook-examples.cjs` с настроенным Playwright/Chromium, как в README приложения. UI-снимки берутся из его smoke-проверки. Сборщик списка источников использует локальный skill grounded-citations.

## Проверка

Машинные отчёты: `verification.json`, `revision-v2/content-verification.json`, `projects/hb-learning-department/reports/handbook-examples.json` и `reports/ui-smoke.json`. Проверены текст каждой страницы, номера глав/дней, соответствие 30 упражнений ответам, финальное расположение ответов, источник каждого внешнего PDF-адреса, вставка изображений, отсутствие личного имени и старого повторяющегося предупреждения. Короткие деревья/листинги удерживаются на одной странице; длинный код делится, а исходники доступны отдельным ZIP.

Вёрстка проверяется выборочно на настоящих растрах: обложка/оглавление, объяснения файлов и сети, схемы, дизайн, приложение, упражнения и ответы. Это не утверждение о ручном осмотре всех страниц и всех PDF-просмотрщиков.
