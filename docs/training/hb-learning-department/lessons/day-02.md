# День 02 — HTML/CSS и адаптивная карточка

## Цель простыми словами

Собрать карточку учебного товара так, чтобы человек понимал название, назначение, цену и действие на телефоне и большом экране. ИИ напишет код, но ты объяснишь, почему здесь заголовок, здесь кнопка и почему карточка не вылезает за край страницы. Это первая маленькая задача, в которой внешний вид проверяется не по одному красивому снимку.

Работаем только в подготовленной учебной папке через диалог, файлы, diff и предпросмотр оболочки. Данные FORMA вымышленные. Реальную корзину и оплату сегодня не подключаем. Если стартовая среда ещё не готова, сообщаем наставнику, не устанавливаем другую IDE и не меняем ядро H&B.

## Понятия и подробное объяснение

**HTML** задаёт структуру и смысл содержимого: где заголовок, абзац, изображение, ссылка и кнопка. **Элемент** состоит из разметки и содержимого; **атрибут** уточняет свойства элемента. Например, `class` связывает элемент с оформлением, а `alt` передаёт текстовую альтернативу изображения. MDN разбирает элементы, атрибуты и вложенность.[1]

**CSS** задаёт отображение. **Селектор** выбирает элементы, **свойство** обозначает, что меняем, **значение** — как меняем. В записи `.product { padding: 1rem; }` точка означает выбор класса, `padding` задаёт внутреннее пространство. Внутренний отступ отделяет содержимое от края блока; внешний `margin` отделяет блок от соседей. `gap` регулирует промежутки между элементами сетки или гибкого контейнера. Смешивать эти задачи опасно: трудно понять, почему расстояние получилось слишком большим.

Карточка — не картинка с текстом. У неё есть содержание, которое может измениться: длинное название, другая цена, отсутствующее фото. Фиксированная высота текста может выглядеть аккуратно на коротком примере, но обрезать важные слова на реальном русском названии. Поэтому сначала делаем устойчивый поток содержимого, затем украшаем.

**Адаптивность** означает перестройку под доступное место. На узком экране фотография может находиться над текстом; на широком — слева от текста. Это не уменьшение всей страницы вместе с буквами. MDN описывает гибкие размеры и медиазапросы как инструменты такого подхода.[2] Значения в примере — учебные решения, а не обязательные размеры всех устройств.

Ссылка предназначена для перехода, кнопка — для действия. Внешне их можно сделать похожими, но назначение должно оставаться понятным. Сегодня кнопка лишь показывает учебное сообщение. Она не создаёт заказ, поэтому подпись «Оплачено» после её нажатия была бы ложной. Проверка клавиатурой нужна потому, что не каждый пользователь действует мышью: фокус должен быть видим, действие — доступно.

## Разобранный пример

Попроси ИИ встроить этот принцип в существующий шаблон, не заменяя проект целиком. Файл картинки — собственная учебная заглушка, которую нужно действительно создать в разрешённой папке, а не оставлять сломанную ссылку.

```html
<article class="product" aria-labelledby="lamp-title">
  <img class="product__image" src="./demo-lamp.svg"
       alt="Учебная настольная лампа FORMA с круглым основанием">
  <div class="product__body">
    <h2 id="lamp-title">Настольная лампа «Линия»</h2>
    <p>Мягкий свет для рабочего стола. Демонстрационный товар.</p>
    <p class="product__price">2 400 ₽ · учебная цена</p>
    <button type="button">Показать учебное действие</button>
  </div>
</article>
```

```css
* { box-sizing: border-box; }
.product {
  display: grid;
  gap: 1rem;
  padding: 1rem;
  width: 100%;
  max-width: 50rem;
  margin-inline: auto;
}
.product__image { width: 100%; height: auto; display: block; }
.product__body { min-width: 0; overflow-wrap: anywhere; }
.product h2 { margin: 0; font-size: 1.5rem; line-height: 1.25; }
.product p { line-height: 1.5; }
.product button { padding: .75rem 1rem; font: inherit; }
.product button:focus-visible { outline: 3px solid #2456a6; outline-offset: 3px; }
@media (min-width: 48rem) {
  .product { grid-template-columns: 1fr 1fr; align-items: start; }
}
```

Прочитай код сверху вниз. `article` объединяет самостоятельный товарный фрагмент. `h2` подходит карточке внутри страницы с главным заголовком. `width: 100%` позволяет занимать доступное место, а `max-width` ограничивает разрастание на большом экране. `box-sizing` включает отступы в рассчитанную ширину. На узком экране сетка одноколоночная; при достаточном месте появляются две колонки. `min-width: 0` разрешает текстовой части сжиматься внутри сетки. `overflow-wrap` страхует длинный непрерывный фрагмент, но не заменяет проверку обычного текста.

У этой кнопки пока нет обработчика. Это честная разметка, а не готовая интерактивность. В практике попроси ИИ связать нажатие с видимым сообщением «Учебное действие выполнено; заказа нет» средствами стартового шаблона. Сегодня достаточно объяснить наблюдаемое поведение, подробный JavaScript будет завтра.

## Практика FORMA: шаги и ожидаемый результат

1. Открой вчерашнюю карту и найди страницу, стили и место собственных изображений. Зафиксируй точку восстановления. Результат: понятная область изменения.
2. Запиши пять частей карточки: изображение, название, описание, цена, кнопка. Для кнопки заранее назови учебный результат. Результат: короткое проверяемое задание, а не просьба «сделай красиво».
3. Попроси ИИ изучить связанные файлы и собрать только разметку с собственной заглушкой. Прочитай diff, объясни элементы, запусти доступные проверки и открой карточку. Результат: всё содержимое видно даже без улучшения оформления.
4. Отдельной редакцией добавь гибкую сетку, размеры текста и отступы. После diff и проектных проверок открой ширины 360, 768 и 1440 пикселей. Результат: читаемая карточка без горизонтального переполнения страницы.
5. Отдельно добавь учебное действие кнопки. Проверь мышь, Tab, видимый фокус, Enter и пробел. Результат: одно нажатие даёт одно ожидаемое сообщение, без настоящего заказа.
6. Замени название на «Настольная лампа для маленького рабочего пространства с регулируемым направлением света». Повтори цикл проверок на всех трёх ширинах. Результат: цена и кнопка остаются доступными, текст не обрезан.
7. В учебной копии временно убери картинку или укажи отсутствующий учебный файл. Проверь, остаётся ли понятен товар по тексту. После восстановления изображения снова проверь страницу. Результат: зафиксирован негативный случай, а не только идеальный макет.
8. Сравни два варианта расстояния между ценой и кнопкой. Объясни, где они воспринимаются одной группой и где связь теряется. Не выбирай большее расстояние автоматически.

## Типичные ошибки

Фиксированная ширина карточки больше экрана вызывает прокрутку; скрывать её общим `overflow: hidden` означает прятать симптом и иногда содержимое. Одинаково большие название, описание и цена уничтожают приоритет. Кнопка из обычного `div` требует дополнительной доступности, которой легко забыть; здесь проще использовать настоящий `button`. Удаление контура фокуса ради красоты лишает пользователя ориентира. Наконец, отсутствие ошибки сборки не доказывает, что длинное название помещается: это проверяется в предпросмотре.

## Чеклист проверок, включая негативные случаи

- [ ] На ширинах 360, 768 и 1440 всё читается, элементы не перекрываются.
- [ ] Горизонтальная прокрутка не нужна для чтения цены и действия.
- [ ] Длинное название и непрерывная строка не раздвигают страницу.
- [ ] При отсутствующем изображении смысл остаётся понятным; затем картинка восстановлена.
- [ ] Кнопка достигается Tab, фокус виден, Enter и пробел работают.
- [ ] После нажатия нет ложного утверждения об оплате или заказе.
- [ ] Соседняя навигация не сломана, в diff нет несогласованных зависимостей.
- [ ] Каждая логическая редакция имеет собственные результаты проверок; после исправления они повторены.

## Что ты сдаёшь и критерии допуска

Сдай карточку в проекте, три снимка с указанными ширинами, объяснение пяти CSS-свойств, журнал длинного текста и отсутствующего изображения, доказательство действия клавиатурой, ответы и дневной отчёт. Допуск: нет переполнения и перекрытий; понимаешь разницу структуры и оформления; действие работает и честно маркировано. Если не получается сетка, наставник помогает с одной колонкой: надёжная простая композиция лучше сломанной сложной.

Для **контрольной точки 3, день 9** сохрани требования к карточке и соответствующие проверки как будущие пункты ТЗ. Для **контрольной точки 6, день 18** сохрани три ширины, длинный текст и клавиатурный сценарий в регрессионный список: при смене акцентного цвета или товара они проверяются снова.

## Ответы и подсказки

1. HTML задаёт элементы и смысл содержимого, CSS — отображение. Большая буква сама по себе не делает абзац семантическим заголовком.
2. `padding` создаёт пространство внутри блока до его края, `gap` — между дочерними элементами подходящего контейнера.
3. При уменьшении всей картинки уменьшается и текст. Адаптивная композиция перераспределяет место, сохраняя читаемость и доступность действия.
4. Длинное русское название или увеличенный текст может занять больше строк: фиксированная высота обрежет содержимое либо вытолкнет его поверх цены.
5. Снимок не показывает фокус, достижимость Tab и фактический результат нажатия. Требуется пройти действие и записать наблюдение.
