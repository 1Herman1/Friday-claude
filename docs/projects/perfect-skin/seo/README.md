## Почему частот нет

Сбор через XMLRiver из этой среды невозможен, проверено:

1. `XMLRIVER_USER` / `XMLRIVER_KEY` в окружении нет — ключ живёт только в секретах GitHub (так и задумано).
2. `https://xmlriver.com` — прокси среды режет соединение: `curl: (56) CONNECT tunnel failed, response 403`.
3. Запустить workflow из сессии нельзя: API GitHub для репозитория отвечает
   `403 GitHub access to this repository is not enabled for this session`.

Цифры не придуманы: пустая клетка = «не собрано», а не «ноль».

## Как запустить (нужен доступ к GitHub Actions)

0. **Сначала закоммитить и запушить** `data/*.txt` — workflow берёт файл запросов из репозитория.
1. `wordstat.yml`: `queries_file=docs/projects/perfect-skin/seo/data/wordstat-queries.txt`,
   `region=225`, `out=docs/projects/perfect-skin/seo/data/russia/wordstat.csv`.
2. То же с `region=213`, `out=docs/projects/perfect-skin/seo/data/moscow/wordstat.csv`.
   Каталоги разные специально: файл связанных фраз пишется рядом с итогом, и в andrey-massage
   два прогона в одну папку затёрли друг друга.
3. `geo-collect.yml`: сначала `mode=dry-run` (бесплатная смета), затем `mode=live`;
   `topic=perfect-skin-moscow`, `engines=yandex`, `region=moscow`, `depth=10`, `max_queries=0`,
   `queries_file=docs/projects/perfect-skin/seo/data/serp-queries.txt`.

Учесть: **оба workflow сами коммитят и пушат результаты** в ветку, с которой запущены
(`geo-collect` — в корневой `geo_agent/`). И `geo-collect` выполняет сторонний код GEO-рантайма —
на это нужно отдельное согласие Гермеса.

После сбора: заполнить частоты в `core.csv`, слить кластеры с нулём, разделить крупные
(возраст 30/35/40, подкатегории очищения), разобрать топ-10 выдачи (маркетплейсы / магазины / медиа)
и ИИ-ответы — кого цитирует Яндекс в ответах.

## Топ-10 выводов (по коду и ассортименту; спрос подтвердит Wordstat)

1. **Брендов как страниц нет.** ISSEIMI и GLACÉE доступны только через `/catalog/all?brand=…`, а на старом
   WordPress `/isseimi/` и `/glacee-skincare/` отдают 404. Брендовый спрос — самый тёплый, его некуда приземлить.
2. **EGF — фирменный актив ассортимента**: он есть в 23 из 54 товаров, озон — в 16, гиалуроновая
   кислота — в 17, пептиды — в 14. Подборки «косметика с EGF» и «с озоном» — ниша, где у маркетплейсов
   нет отдельных страниц по этим брендам.
3. **Подборки по задаче** (антивозраст 30–50+, пигментация, сухая, проблемная, чувствительная кожа,
   мужской уход) сейчас существуют только как галочки фильтра. Адреса у них нет, проиндексировать нечего.
4. **Четыре категории — сироты**: тоники, кремы для век, масла, флюиды. Ссылок из шапки, подвала и с
   главной нет.
5. **Товар не ссылается на бренд и линейку** (простой текст). 54 страницы не передают вес вверх.
6. **Блог изолирован**: в шапке и мобильном меню его нет, в статьях нет ссылок в тексте, статья
   «Яблоко…» не ведёт ни на один товар (хотя DINAMIZANTE — ровно про стволовые клетки яблока),
   с товаров на статьи ссылок нет.
7. **Дубли адресов каталога**: `/catalog` и `/catalog/all`, `/catalog?brand=` и `/catalog/all?brand=`.
8. **SPF-категория пустая** (0 товаров), BHA-кислот нет ни в одном товаре: эти запросы
   забирать только статьями, без обещаний товара.
9. **«Аптечная косметика»** — чужой интент (там ищут аптечные бренды). Его стоит забирать статьёй
   «профессиональная или аптечная: в чём разница», а не категорией. Это и сильный кандидат на цитирование
   в ИИ-ответах.
10. **Медицинские слова** (акне, купероз, «лечит») на коммерческих страницах — правовой риск: закон
    о рекламе запрещает приписывать косметике лечебные свойства. Формулировки — через `rkn-compliance`.
