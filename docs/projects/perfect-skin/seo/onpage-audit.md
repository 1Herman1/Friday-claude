# Perfect Skin — аудит on-page SEO по коду (28.10.2026)

Источник: `seo-department` + `seo-specialist`, чтение кода, без правок. План исполнения — `roadmap.md`.


## Главное

Яндекс и ИИ-боты сейчас видят пустой сайт:
- Робот, который не исполняет скрипты, получает пустой `<div id="root">` и один заголовок вкладки на все страницы: «Perfect Skin — про-косметика из Испании» (`client/index.html:13,25,51`).
- SSR нет. SSR — это когда сервер сам собирает страницу в HTML, без скриптов в браузере.
- Пререндера нет. Пререндер — заранее сохранённые HTML-копии страниц.
- Подстановки мета-тегов на сервере тоже нет. Всё раздаёт nginx одной строкой `try_files $uri /index.html` (`deploy/nginx-perfect-skin.conf:105-107`).
- ИИ-боты (GPTBot, ClaudeBot, PerplexityBot) скрипты не исполняют вовсе. Яндекс исполняет их с задержкой и без гарантий; проверить можно только в Вебмастере после подключения домена.

## Таблица «проблема → как исправить → приоритет»

**КРИТИЧНО** (дешёвое и самое полезное первым):
1. **`noindex` стоит в пяти местах:** `nginx-perfect-skin.conf:22,50,95,101` и `nginx-perfect-skin-media.conf:22`. Инструкция `deploy/DEPLOY.md:210` велит снять одну строку — тогда сайт останется закрытым. Снимать все пять, оставить запрет только на `/api/`, затем проверить `curl -I` на главной, товаре и `/assets/`.
2. **Пустой HTML для роботов.** Решение — серверная подстановка (вариант 2 ниже): title, description, canonical, Open Graph (теги для превью в соцсетях), JSON-LD (микроразметка), а также H1, текст, цены и ссылки прямо в HTML.
3. **Мягкая 404.** Отдавать настоящий 404, а для снятых товаров 410 («удалено навсегда»).
4. **Нет 301 со старого сайта** (постоянных перенаправлений) и нет карты старых адресов. Перенос старого адреса товара сейчас делается в браузере, а не кодом 301, и робот его не видит.
5. **Одинаковые title и description у всех страниц.** Нужен хук `usePageMeta` на клиенте и такие же значения в серверной подстановке.
6. **Нет robots.txt и sitemap.xml.** Сейчас по этим адресам отдаётся HTML со статусом 200.
7. **Дубли каталога:** `/catalog` и `/catalog/all`, параметры `category=`, `offset`, `sort`, `q`, слэш на конце, регистр букв. Нужны canonical и 301.

**ВАЖНО:**
- `noindex` на служебные страницы.
- Микроразметка Product/Offer: цена для гостя, валюта RUB, наличие. Кабинетные фасовки со скрытой ценой не выводить. Рейтинг не выдумывать — отзывов на сайте нет.
- Микроразметка BreadcrumbList (хлебные крошки) и Organization/LocalBusiness (телефон, адрес на Звенигородском шоссе, часы работы).
- Микроразметка BlogPosting для статей. Для неё API статей должен отдавать `seoTitle`, `seoDescription` и дату обновления.
- Главное фото товара — исходный JPG/PNG без размеров. Это LCP (время отрисовки самого крупного элемента): перейти на webp из `products-optimized/`.
- Убрать предзагрузку `/snapshot/catalog.json`: она идёт на каждой странице впустую.
- Предзагрузка шрифтов и картинки первого экрана главной.
- Адрес сайта: 301 с http, с www и с IP-адреса на один основной адрес.

**КАЧЕСТВО:**
- пробел в H1 главной;
- `###` выводить как `<h3>`;
- «Показать ещё» сделать ссылкой `?page=2`;
- осмысленный alt (подпись картинки) у обложек статей;
- FAQPage (разметка вопросов-ответов) отдавать с сервера. В Google эффекта не будет: с 2023 года он показывает такие сниппеты только госсайтам и медицинским сайтам;
- одно имя категории «Маски» вместо двух разных.

**Не проверено, «похоже на»:** условные хуки в `CatalogPage.tsx:60-106`. Это может ронять страницу при переходе из хаба в категорию и мешать любому пререндеру. Проверить в браузере.

## Как решить индексацию: три варианта

| Вариант | Цена | Риск | Вывод |
|---|---|---|---|
| 1. Пререндер при сборке | 1–2 дня | Цены и наличие застывают до следующей выкатки, а меняются они через админку и обмен с 1С | Только для статичных страниц |
| **2. Подстановка в Fastify по адресу** | **3–5 дней вместе с robots, sitemap, 404 и 301** | Низкий: данные всегда из базы. HTML одинаковый для всех, без разбора User-Agent — маскировка под бота грозит санкциями | **Рекомендую** |
| 3. Полный SSR | 2–4 недели | Переписать загрузку данных на всех страницах, сложная поддержка | Для 54 товаров не окупается |

## sitemap и robots

- **В sitemap:** главная, `/catalog`, 9 непустых категорий, около 54 видимых гостю товаров, `/brands`, `/about`, `/contacts`, `/pro`, `/consultation`, `/blog`, статьи. Без SPF и «Ухода за телом».
- **Закрыть в robots:** `/admin`, `/staff-login`, `/auth`, `/pro/register`, `/checkout`, `/orders`, `/track`, `/api/`, `/snapshot/`, параметры `q`, `pro`, `sort`, `offset`, `minPrice`, `maxPrice`, `category`, `need`, `skin`. Для Яндекса добавить `Clean-param` — его директиву «эти параметры адреса не меняют содержимое».
- **Пока не закрывать `?brand=`:** до появления страниц брендов это их единственные адреса.
