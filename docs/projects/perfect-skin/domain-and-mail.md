# Perfect Skin — перенос домена с reg.ru и почта для писем сайта

Обновлено: 29.10.2026. Для Гермеса и клиента.
- **[клиент]** — делает владелец домена в панели reg.ru или в почтовом сервисе.
- **[студия]** — делаем мы.

## Коротко

1. Домен `perfect-skin.shop` **переносить с reg.ru не нужно**. Регистратор остаётся прежним, меняем только две записи в DNS. DNS — это «адресная книга» домена: она говорит браузеру, на какой сервер идти. Перенос регистратора занимает 5–7 дней, стоит денег и ничего не даёт.
2. Почта на домене уже есть: `mail@perfect-skin.shop`, она указана в контактах. При переключении сайта **почтовые записи (MX) не трогаем**, иначе почта перестанет приходить.
3. Для писем сайта нужен отдельный ящик-отправитель, например `noreply@perfect-skin.shop`. Сайт отправляет с него коды входа, письма о заказах и уведомления. Ящику нужен пароль для внешних программ (SMTP) — его вносим в настройки сервера через секреты GitHub, не в чат.

## Часть 1. Переключение домена на новый сервер

### Шаг 0. Подготовка, за 1–2 дня до переключения
- **[клиент]** Дать доступ к панели reg.ru или быть на связи во время переключения: это 15 минут.
- **[клиент]** Решить судьбу старого сайта на WordPress. После переключения он перестанет открываться по домену. Если в нём есть что-то нужное (заказы, тексты, база клиентов), выгрузить заранее.
- **[студия]** Снять список адресов старого сайта для переадресаций 301. Без них накопленный в поиске вес старых страниц пропадёт. Источник — карта сайта старого WordPress или Яндекс.Вебмастер.
- **[клиент]** В reg.ru: **Домены → perfect-skin.shop → DNS-серверы и управление зоной**. Посмотреть, какие DNS-серверы указаны.
  - `ns1.reg.ru` / `ns2.reg.ru` (или `ns1.hosting.reg.ru`) — зону правим прямо в reg.ru, дальше по инструкции.
  - Другие серверы (например, Яндекс или Cloudflare) — записи правятся там. Сообщите нам, какие указаны.
- **[клиент]** У текущих записей `A` для `@` и `www` уменьшить **TTL до 300** (5 минут), если reg.ru даёт это сделать. TTL — время, на которое интернет запоминает старый адрес. Тогда переключение пройдёт быстро.
- **[клиент]** Сделать снимок экрана текущей зоны DNS — на случай отката.

### Шаг 1. Студия готовит сервер (до переключения, сайт при этом не ломается)
- **[студия]**
  - В nginx прописать `server_name perfect-skin.shop www.perfect-skin.shop`.
  - Включить переадресацию `www` → без `www`, а также `http` → `https`.
  - Подготовить таблицу 301 со старых адресов.
  - Подготовить переключатель индексации.

### Шаг 2. Клиент меняет две записи в reg.ru
В зоне DNS домена:

| Тип | Имя (хост) | Значение | TTL |
|---|---|---|---|
| A | `@` | IP-адрес сервера Perfect Skin (студия пришлёт в личном сообщении, в документы его не пишем) | 300 |
| A | `www` | тот же IP | 300 |

- Старые записи `A` для `@` и `www` **удалить**: в зоне не должно быть двух разных A-записей на одно имя.
- Записи `AAAA` для `@` и `www` (если есть) **удалить**: сервер работает по IPv4.
- **Не трогать:** записи `MX`, `TXT` (SPF, DKIM, проверочные записи Яндекса и Google), `CNAME` вида `mail`, `autodiscover`, `_dmarc`. Это почта и подтверждения сервисов.

### Шаг 3. Студия включает HTTPS и проверяет
- **[студия]** Дождаться, пока домен начнёт вести на новый сервер. Обычно это от 15 минут до нескольких часов, в редких случаях до суток.
- **[студия]** Выпустить сертификат HTTPS (Let's Encrypt, бесплатно, продлевается автоматически).
- **[студия]** Проверить:
  - главную;
  - карточку товара;
  - вход по коду;
  - корзину;
  - переадресации со старых адресов и с `www`.
- **[студия]** Переключить сайт в открытый режим. Это одна настройка: открытый `robots.txt`, снятие `noindex`.
- **[студия]** Подключить домен в Яндекс.Вебмастере и отправить карту сайта. Нужен доступ клиента или подтверждение через запись TXT в DNS.

### Откат
Если что-то пошло не так, вернуть старые записи `A` по снимку экрана из шага 0. Через 5–10 минут откроется старый сайт.

## Часть 2. Почта для писем сайта (коды входа, заказы)

### Что нужно
Отдельный ящик-отправитель на домене, например `noreply@perfect-skin.shop`, и доступ к нему по SMTP — протоколу, которым программы отправляют письма.

### Где сделать ящик
1. **Там же, где сейчас `mail@perfect-skin.shop`** — самый простой путь. Узнать у клиента, где живёт почта: Яндекс 360, VK WorkSpace (Mail.ru для бизнеса) или почта reg.ru. Подсказка: записи `MX` в зоне DNS.
   - `mx.yandex.net` — Яндекс;
   - `emx.mail.ru` — VK WorkSpace;
   - `mx1.hosting.reg.ru` и похожие — reg.ru.
2. **Если почты на домене по факту нет** — подключить **Яндекс 360 для бизнеса** или **VK WorkSpace**.
   - Оба российские: для 152-ФЗ это важно, данные покупателей не уходят за рубеж.
   - Зарубежные сервисы (Gmail, SendGrid, Mailgun) **не использовать**.
   - Тарифы смотреть на сайте сервиса, точные цены не называю, они меняются.

### Шаги на примере Яндекс 360
- **[клиент]** В Яндекс 360 для бизнеса подключить домен `perfect-skin.shop`, если он ещё не подключён. Подтвердить владение записью TXT в reg.ru — Яндекс покажет точное значение.
- **[клиент]** Если домен подключается к Яндексу впервые, добавить в зону reg.ru записи, которые покажет Яндекс:
  - `MX` `@` → `mx.yandex.net.`, приоритет 10. **Только если почта переезжает на Яндекс** — иначе текущий ящик `mail@` перестанет получать письма;
  - `TXT` `@` → `v=spf1 redirect=_spf.yandex.net` (SPF: какие серверы вправе отправлять письма от имени домена). Если запись SPF уже есть — не создавать вторую, а дополнить первую;
  - `TXT` `mail._domainkey` → значение DKIM из админки Яндекс 360 (раздел «Почта → DKIM-подписи»). DKIM — цифровая подпись письма;
  - `TXT` `_dmarc` → `v=DMARC1; p=none; rua=mailto:mail@perfect-skin.shop`. DMARC — правило для почтовых серверов, что делать с поддельными письмами. Начинаем с мягкого `p=none`.
- **[клиент]** Создать сотрудника или ящик `noreply@perfect-skin.shop`.
- **[клиент]** Войти в этот ящик: **Аккаунт → Безопасность → Пароли приложений → Почта**. Создать пароль приложения. Это отдельный пароль только для отправки писем сайтом. Обычный пароль от ящика не подходит и передавать его не нужно.
- **[клиент или Гермес]** Внести 6 значений в секреты GitHub. **В чат и письма пароль не пишем.** Путь: GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Значение для Яндекс 360 |
|---|---|
| `PS_SMTP_HOST` | `smtp.yandex.ru` |
| `PS_SMTP_PORT` | `465` |
| `PS_SMTP_SECURE` | `true` |
| `PS_SMTP_USER` | `noreply@perfect-skin.shop` |
| `PS_SMTP_PASS` | пароль приложения из предыдущего шага |
| `PS_SMTP_FROM` | `Perfect Skin <noreply@perfect-skin.shop>` |

  Для VK WorkSpace: хост `smtp.mail.ru`, порт `465`, `true`. Для почты reg.ru хост и порт берутся из их инструкции, обычно это `mail.hosting.reg.ru`, порт `465`.
- **[студия]** Выкатка сама запишет эти значения в настройки сервера (`deploy-perfect-skin.yml` уже так умеет).
  - Проверим: письмо с кодом входа на тестовый адрес, письмо о заказе, отметку «не спам» в Яндекс.Почте и Gmail.
  - Проверим SPF, DKIM и DMARC в заголовках письма.

### Что важно
- Письма сайта — служебные: коды входа, статусы заказов. Рекламные рассылки с этого ящика **не отправляем**: для рекламы нужны отдельное согласие и отдельный сервис.
- У офисной почты есть суточный лимит на отправку. Для старта магазина его хватает с запасом. Если писем станет много (сотни в день), перейдём на российский сервис транзакционных писем, например Unisender Go. Перенос — только смена шести секретов.
- Пока SMTP не настроен, вход по email на боевом сервере работать не будет: сервер не сможет отправить код. Поэтому почту настраиваем **до** переключения домена.

## Что нужно от клиента, одним списком
1. Доступ к reg.ru или время на созвон для смены двух записей A.
2. Где сейчас живёт почта `mail@perfect-skin.shop`: Яндекс, VK или reg.ru.
3. Ящик `noreply@perfect-skin.shop` и пароль приложения к нему — внести в секреты GitHub или передать Гермесу лично, не в общий чат.
4. Решение по старому сайту на WordPress: что выгрузить перед переключением.
5. Доступ к Яндекс.Вебмастеру, если домен там уже подтверждён.
