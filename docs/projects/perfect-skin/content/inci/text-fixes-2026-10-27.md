# ISSEIMI: полная сверка текстов с официальным составом (INCI), список правок

Дата: 27.10.2026. Решение владельца, согласовано с клиентом: все расхождения исправляем под состав.
Правило: вещества нет в INCI, упоминание убираем; в INCI другая форма, называем по составу (по-русски понятно, при необходимости INCI в скобках).
GLACÉE не трогаем (официального INCI нет). Код и данные не правились, это только список.

Источник составов: `docs/projects/perfect-skin/content/inci/isseimi.json` (20 товаров с INCI, один из них NATURAL CLEANSING MILK клиент пометил `skip`; 11 товаров в `notFound`).
Прежняя сверка (`isseimi-text-vs-inci.md`) проверяла только «Активные», «Как работает» и вступление. Здесь сверены все текстовые поля карточки (tagline, intro, extra, howItWorks, actives, forWhom, usage, lifehack, pro.*), названия и короткие описания, тексты брендов, статьи.

## 1. Сводка

- Правок всего: **65** в 19 товарах из 20 (чист только SEA FOAM, у него только дефект текста, см. раздел 8).
  - в тексте карточки (`product-details`): 48, из них 3 условные (NATURAL CLEANSING MILK, см. вопросы);

  - тексты брендов в клиенте: 2;
  - статьи: 1 (Scrub Lotion).
- Новое по сравнению с прошлой сверкой (не было поймано): COLLAGEN BOOSTER (фермент СОД, микроэлементы), CREMA ELITE (фибронектин, «минимум консервантов» при шести консервантах в INCI), PURE MARINE («100% натуральная» при феноксиэтаноле), 3 FLOWER (гидролаты вместо экстрактов в прозе), KERATHOR («ферментированные»), SCRUB LOTION («биоцеллюлозные шарики» в статье), oil-товары («инкапсулированный озон» без носителя в INCI), BLOCKMELAN/HYDRA VIEW/TTS ESSENTIAL («Глицин сои» это соевое масло), catalog-curated (Pronalen, Масло чиа, Гидролизат шелка, Экстракт розмарина).
- Особые случаи: название TTS ENERGIZING (раздел 3); правки вне механизма override (раздел 6); вопросы владельцу (раздел 7). **DINAMIZANTE это GLACÉE, а не ISSEIMI; в `glacee.json` он в `notFound`, состава нет: не трогаем, вопрос в разделе 7.**

Уверенность: уверен / похоже / догадка. Без пометки значит уверен (вещества или формы нет в INCI дословно).

## 2. Откуда что попадает на сайт (проверено по коду)

| Поле на сайте | Источник | Как попадает в БД |
|---|---|---|
| Карточка (`details`), `description`, `usage` | `server/assets/product-details/<slug>.json`, собирается `parse-client-docx` из docx + `product-details-overrides.json` | `prisma/import-content.ts` обновляет существующие товары |
| `name` | `server/assets/catalog-curated.json` (3 товара: ещё `retail-products.json`, имена там верны) | `prisma/seed.ts`, **только создание**, существующие товары пропускаются |
| `shortDescription` | первое предложение `action` из `catalog-curated.json`, до 160 знаков | `seed.ts`, только создание |
| `ingredients` (ProductIngredient) | `catalog-curated.json` | `seed.ts`, только создание; на карточку этих 19 товаров не выводится (`PlainProductInfo` только для товаров без `details`); участие в фильтрах не проверял |
| `inciText` | `isseimi.json` | `prisma/import-inci.ts` |
| `price-import.json`, `products/manifest.json` | сопоставление прайса / обработка картинок | `name` и `shortDescription` не пишут; у ENERGIZING сопоставление идёт по `siteName: "TTS ENERGIZING MASK"` (латинский префикс), переименование русского хвоста его не ломает |
| `client/public/snapshot/catalog.json` | генерится `npm run content:snapshot` | после правок перегенерировать |

Важно: файлы в `assets/product-details/*.json` уже содержат результат прежних override. Правки в override вступают в силу только после повторного `parse-client-docx`, затем `import-content --apply` (на проде через `run-command.yml`, сначала без `--apply`).

Латинский префикс сохраняем: по нему работают сопоставление прайса (`siteName`) и разбор docx (`productKey` строится по латинской части). Места: `catalog-curated.json` (name), БД (`Product.name`, нужен разовый скрипт, см. раздел 6), `products/manifest.json` (name и alt картинки, 2 вхождения, для порядка), `client/public/snapshot/catalog.json` (перегенерировать), `price-import.json` поле `name` (только лог, сопоставление идёт по `siteName`; для порядка можно поправить, не обязательно). Строка `sources[0].title` в `product-details/…energizing….json` это заголовок из docx, на сайт не выводится, трогать не нужно. Названия остальных 19 товаров правок не требуют (кроме вопроса про NATURAL CLEANSING MILK, раздел 7).

## 6. Что нельзя выразить существующими операциями override и как сделать

Операции: `actives` (весь массив верхнего уровня), `removeHowItWorks` (пункт по точному заголовку), `replace` (точная подстановка по всем строкам карточки, кроме ключа `actives`; падает, если фрагмент не найден; заменой на пустую строку нельзя убрать элемент массива, схема требует непустой `Line`).

1. **Название и короткое описание** (правки 26, 35, 53, 57). Лежат вне `details`: `name` и `shortDescription` берутся из `catalog-curated.json`, а `seed.ts` существующие товары пропускает. Предложение: правка `catalog-curated.json` (чтобы свежий сид был верным) плюс разовый скрипт по образцу `prisma/fix-product-names.ts` (по списку slug, сухой прогон по умолчанию, `--apply` отдельно) для `Product.name` и `Product.shortDescription`. Slug не меняется, алиасы не нужны.
2. **`actives`**: `replace` их не трогает по замыслу, любая правка состава это замена массива целиком. У 7 товаров override на `actives` ещё нет (O3 DEPUR, COLLAGEN BOOSTER, BLOCKMELAN, HYDRA VIEW, KERATHOR PLUS, NATURAL CLEANSING MILK, TONICO): нужны новые ключи в `product-details-overrides.json`, сама операция есть. Для остальных 9 (ROSE HIP, JOJOBA, BAOBAB, SCRUB LOTION, CHIA, 3 FLOWER, CREMA ELITE, ESSENTIAL, ENERGIZING) надо поменять уже существующие массивы. Массив `pro.actives` недоступен ни одной операции; сейчас он пуст у всех 20 товаров, так что не мешает.
3. **Правки текста в самих override ломают уже стоящие пары**: у SCRUB LOTION (пара «с микроцеллюлозой и гераниолем») и TTS MOISTURIZING («формула с АТФ и разноуровневой гиалуроновой кислотой») надо менять `to` существующей пары, а не добавлять вторую (вторая не найдёт исходный фрагмент после первой и упадёт).
4. **Тексты брендов в клиенте** (64, 65) и **статья** (28): это код и markdown, не данные карточки; правятся прямым редактированием. Статьи владелец публикует дословно, поэтому только правка 28.
5. **Перегенерация витрины**: `client/public/snapshot/catalog.json` (команда `content:snapshot`) и повторный `parse-client-docx` для `product-details/*.json`. Руками править `product-details/*.json` не стоит: следующий разбор docx их перезапишет.
6. **Удаление целого элемента** списка (пункт «Кому подойдёт», шаг применения, абзац лайфхака) операциями не выражается (только пункты «Как работает»). В этом списке такой нужды нет; если появится, нужна новая операция либо правка исходного docx.
7. Ничего из этого не ломает `price-import` и разбор docx, пока латинский префикс названия сохранён.
