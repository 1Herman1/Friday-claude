## Две категории покупателей

Это главная развилка всей архитектуры — от неё зависят цены, каталог и порталы.

| | Розничный клиент | Профессионал (косметолог) |
|---|---|---|
| Кто | Покупает уход себе домой | Покупает для работы в кабинете и на перепродажу пациентам |
| Цены | Видны всем сразу | Видны **только после регистрации и проверки документов** |
| Портал | Бьюти-клуб | Pro-кабинет |
| Механика | Новости бьюти, предложения, скидки, подарки, уходы | Промокод для своих пациентов |

## Ключевые механики

1. **Скрытие профессиональных цен.** Неавторизованный посетитель и розничный
   клиент профи-цен не видят. Доступ открывается после заявки: ИНН или ОГРНИП
   и обязательное фото сертификата или диплома. Реестры ФНС (DaData, сервис
   самозанятых) дают менеджеру подсказку, одобряет всегда человек — в админке
   или в Telegram-боте. Фото удаляется через 30 дней после решения
   (`client-questions.md`, 5.4–5.7).
2. **Промокод косметолога — 15%** (утверждено заказчиком). У профессионала
   личный код, его пациент покупает по нему со скидкой.
   Принятые допущения (меняются настройкой, не кодом): код бессрочный и без
   лимита применений, действует пока косметолог одобрен; вознаграждения
   косметологу с продаж нет. Промокод не применяется к профессиональному
   прайсу — оптовая цена уже снижена.
3. **Два портала с разным контентом и лояльностью** — Pro-кабинет и Бьюти-клуб.
   Это не две вкладки одного кабинета, а разные разделы с разными правилами.
4. **Подбор косметики** — плашка на главной, ведёт в подбор средств по типу
   кожи и задаче. `УТОЧНИТЬ`: анкета или каталог с фильтрами.
5. **Консультация косметолога** — плашка на главной, запись на консультацию.
   `УТОЧНИТЬ`: онлайн-форма, мессенджер или запись в кабинет.

## Технологический стек

Решено: стек Симбы — React 18 + Vite + TypeScript + Tailwind (витрина и
админка), Fastify + Prisma + PostgreSQL (сервер). Не Next.js.

Проект живёт отдельным воркспейсом `perfect-skin/` с **собственной базой**
(`PS_DATABASE_URL`) и собственным пакетом `@ps/shared`. Обоснование и границы
переиспользования — `docs/decisions/2026-07-perfect-skin-architecture.md`.

Не предлагать решения из мира Next.js — `app/api`, NextAuth, Vercel неприменимы.

Что реально переиспользуется из Симбы: каталог с вариантами товара, корзина,
оформление заказа, роли и админка, интеграции доставки. Что не подходит:
зоо-поля товара (`isGrainFree`, `protein`, `fat`, `ProductVariant.weight`) —
для косметики нужны свои характеристики (объём, тип кожи, активные компоненты).

## Выкатка

Ветка выкатки — **`deploy/perfect-skin`**. Пуш в неё и есть спуск деплоя:
`git push origin <рабочая ветка>:deploy/perfect-skin`. Сервер делает
`merge --ff-only`, поэтому своих коммитов в ветке выкатки быть не должно.

| Что | Где |
|---|---|
| Сервер | Timeweb Cloud, Россия. Ubuntu 26.04 LTS, 2 vCPU / 4 ГБ / 40 ГБ NVMe |
| Адрес стенда | Пока только по IP (адрес — в `.env` сервера и в панели Timeweb, в чат и логи не выводится), закрыт от индексации. Домен `perfect-skin.shop` (сейчас старый WordPress) переключаем к запуску |
| Конфигурация | `projects/perfect-skin/deploy/`, рунбук — `deploy/DEPLOY.md` |
| Первичная настройка | workflow `bootstrap-perfect-skin.yml`, запуск вручную |
| Выкатка | workflow `deploy-perfect-skin.yml` |
| Что крутится | Postgres в Docker, приложение под PM2 (`ps-server`), Nginx; сертификат Let's Encrypt — после подключения домена |
| Health | `GET /api/v1/health` |
| Бэкапы | `pg_dump` перед каждой миграцией в `/var/backups/perfect-skin`, хранится 10 последних, плюс штатные бэкапы Timeweb |

Секреты доступа — `PS_DEPLOY_HOST`, `PS_DEPLOY_USER`, `PS_DEPLOY_SSH_KEY` в
GitHub Secrets. Секреты приложения (`JWT_SECRET`, `PS_COOKIE_SECRET`,
`PS_PROMO_HMAC_SECRET`) генерируются на сервере при первичной настройке и
живут только в `.env` там; в прод сервер не стартует, если они пустые.

**Ловушка, про которую забывают.** Адрес API вшивается в клиентский бандл на
этапе сборки (`VITE_API_URL`). При переезде на боевой домен клиент нужно
**пересобрать** — поменять переменную в рантайме нельзя.

**Перед запуском на домене убрать `VITE_DEMO_VIDEO_REVIEWS=1` из сборки** — демо-отзывы на открытом сайте недопустимы (ЗоЗПП, закон о рекламе). Сейчас флаг стоит в `deploy-perfect-skin.yml` (шаг сборки клиента).

### SEO — большая отдельная задача (решение Гермеса 25.10: отложить)

Статус: ждёт команды Гермеса. Исполнитель — отдел `seo-department`.

Готово (24–25.10):
- `seo/core.csv` и `seo/core.xlsx` — ядро на 404 запроса в 49 кластерах.
  Частоты Wordstat по РФ и Москве, у каждого запроса — целевая страница.
- `seo/README.md` — выводы и приоритеты страниц.
- `seo/structure.md` — схема перелинковки и перетока ссылочного веса.

Главные выводы:
- Брендового спроса почти нет: ISSEIMI — 9 показов в месяц, GLACÉE — 0.
- Спрос — по задачам и активам. Топ подборок:
  - антивозраст — 68,8 тыс.;
  - гиалуроновая кислота — 37 тыс.;
  - пептиды — 33 тыс.;
  - пигментация — 19 тыс.
- Головы вида «крем для лица» заняты маркетплейсами — только для замера.

Что осталось, по порядку:
1. Перелинковка:
   - бренд и линейка на карточке товара — ссылками;
   - статьи ↔ товары;
   - один адрес у каталога и фильтра брендов;
   - «← Все статьи» — ссылкой.
2. Техническое SEO до запуска домена:
   - свой `<title>` и описание у каждой страницы;
   - карта сайта и `robots.txt`;
   - переадресации 301 со старых адресов.

   Исполнитель — `seo-specialist`.
3. Тексты на готовых страницах: «Бренды» (под запрос «испанская профкосметика»), «Специалистам», главная.
4. Подборки — по одной, начиная с «Антивозрастного ухода». Остальные — с другим порядком товаров и своим текстом, после индексации первой: иначе дубли.
5. Выдача Яндекса и ответы нейросетей (`seo/data/serp-queries.txt`, `geo-collect.yml`). Сбор платный: сначала смета и согласие Гермеса, запуск GEO-рантайма — отдельным разрешением.

- ретинол: один крем, сывороток нет.
