## Технологический стек Симбы (реальный)

Важно для агента: проект Симба работает НЕ на Next.js.
Это React 18 + Vite (клиент) и Fastify (сервер). Не предлагать
для Симбы решения из мира Next.js — `app/api/**/route.ts`, `getServerSession`,
`NextRequest/NextResponse`, `next.config.js`, NextAuth, Vercel. Всё это не применимо.
Пути роутов: `server/src/routes/**`, аутентификация — свой OTP + JWT.

Общий стек по умолчанию для новых проектов описан в `docs/core/stack.md` — для Симбы
источник истины только этот раздел.

### Frontend (клиент + админка)
- Framework: React 18 + Vite (SPA, не Next.js, не App Router)
- Language: TypeScript
- Styling: Tailwind CSS
- Routing: React Router
- State: React Context (Zustand планируется)
- Forms: Zod (React Hook Form планируется)
- Data Fetching: Axios + TanStack Query
- Воркспейсы: `client/` (магазин) и `admin/` (панель управления)

### Backend
- Runtime: Node.js
- API: Fastify (роуты в `server/src/routes/**`, защита через `preHandler`)
- ORM: Prisma
- Validation: Zod
- Auth: свой OTP (код на email/SMS) + JWT (сейчас в localStorage)

### База данных и хранилище
- Primary: PostgreSQL (self-hosted в Docker, не Supabase/Neon)
- Storage: MinIO (S3-совместимое, не Supabase Storage / AWS S3) — изображения товаров
- Cache/Queue: Redis не подключён (нет в docker-compose) — не предлагать BullMQ без установки Redis

### Инфраструктура
- Hosting: Timeweb VPS (не Vercel/Railway)
- Process manager: PM2
- Reverse proxy: Nginx
- Деплой: `git pull` на VPS → `prisma migrate deploy` → сборка → `pm2 reload`

## Выкатка на сервер

Общие правила выкатки — в `CLAUDE.md`, раздел «Выкатка на сервер». Здесь —
конкретика Симбы.

- **Ветка выкатки: `deploy/simba`.** Деплой = пуш рабочей ветки в неё:
  `git push origin claude/greeting-nnz368:deploy/simba`. Сервер делает
  `merge --ff-only`, поэтому `deploy/simba` всегда должна быть предком рабочей
  ветки — своих коммитов в ней не бывает.
- **Workflow `deploy-simba.yml`** сам снимает бэкап базы, собирает, применяет
  миграции, гоняет бэкфиллы, перезапускает PM2 и проверяет health.
- **Следить за прогоном** — `mcp__github__actions_list` (`list_workflow_runs`,
  ветка `deploy/simba`), логи упавшего шага — `mcp__github__get_job_logs`.
  Выкатка не закончена, пока последний прогон не `success`.
- **Что не выкатывать** — если Гермес сказал «это на сервер не выкатывай»,
  держать такие изменения вне `deploy/simba` до отдельной команды и напоминать
  о них в отчёте.

## Резюме сессии

В конце сессии (пользователь прощается, просит закруглиться, явно говорит
«резюме» / «сохрани контекст» / «передать в другую сессию») — вызвать команду
`/summary`. Она выводит резюме прямо в чат (не в файл, без коммита) по
фиксированному шаблону — не пересказ диалога, а конкретика: что сделано, что
отложено, незапушенные коммиты, договорённости, следующий шаг. Гермес сам
копирует текст и вставляет в начало новой сессии.
