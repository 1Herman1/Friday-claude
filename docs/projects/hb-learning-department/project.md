# Проект: H&B Learning Department

Учебная веб-среда для начинающего сотрудника H&B. Спецификация и содержание: `docs/training/hb-learning-department/`; код: `projects/hb-learning-department/`.

## Рабочий статус

16 ноября 2026: собрана редакция материалов v2 по семи замечаниям владельца. Учебник: 118 страниц, 22 главы, 30 пар пример/упражнение с ответами в конце, 12 авторских схем/снимков, 48 источников. Включены 10 каталогов и 6 видео с проверенными метаданными (без полного просмотра). Практикум: 26 страниц / 24 дня; дизайн-спринт каждого дня включён в прежний бюджет времени. Первые два отдельных урока обновлены; HTML/CSS-примеры главы об инструменте прошли настоящий API/preview временного профиля, не проверку на реальных сотрудниках. PDF-проверки и регрессия 43 backend / 11 Chromium-групп прошли; отчёты в `handbook/verification.json` и `projects/hb-learning-department/reports/`. Выбор API для live-наставника остаётся нерешённым; новые интеграции эта редакция не включает.

14 ноября 2026: локальная v0.2 запущена и проверена. 43 backend-теста и настоящий браузерный smoke-сценарий прошли. PDF-учебник и практикум сгенерированы. Не называть эту версию подключённым агентским runtime или готовой удалённой платформой.

## Пользователи и ответственность

Герман — owner: клиентская коммуникация, приёмка, ручной выпуск. Два отдельных сотрудника — «Тест» (`test`) и «Матвей» (`matvey`), оба student: каждый со своим учебным проектом, диалогом, очередью, работами и прогрессом. Следующий урок открывается после приёмки предыдущего. Куратор переключает профили, ученик не может выбрать чужой. Личные файлы входа — закрытый `.local/access/`; инструкция — `docs/training/hb-learning-department/access-and-testing.md`. Авторство запроса проверяется серверным токеном; роли в тексте не дают полномочий.

## Реальный стек

- Backend: Python standard library `http.server`, `sqlite3`; НЕ Next.js/Fastify/Prisma.
- Frontend: локальные HTML/CSS/vanilla JavaScript, без CDN и сборки.
- БД и файлы: `.local/`, gitignored; не использовать общую PostgreSQL дневника.
- Доступ: только localhost по умолчанию; личные токены owner/student.
- Live model: off. Есть адаптер OpenAI-compatible API, внешняя интеграция на реальном ключе не проверена. Hermes/Codex runtime ещё не подключён.
- Preview: только HTML/CSS; JS, сеть, формы и внешние ресурсы отключены.

## Проверки

Из каталога кода: `python3 -m unittest discover -s tests -v`, `node --check static/app.js`. Браузерный сценарий — `tests/ui-smoke.cjs`, параметры и реальные результаты в README проекта и `reports/ui-smoke.json`.

## Выкатка

Удалённой выкатки и её ветки нет. Сервис запущен локально на `127.0.0.1:8765`; это не адрес доступа с чужого устройства. Для удалённого запуска сначала нужны хост, защищённый доступ, решение о provider, изоляция и отдельная приёмка. Основной Telegram gateway не переключался.

## Правовой и операционный контур

В учебных примерах только вымышленные данные FORMA. Оператор реальных ПД, размещение, срок хранения и условия доступа ещё не согласованы: публичный сервис не запущен. Не загружать реальные клиентские данные, платежные секреты или личные OAuth-токены студии. Плату около 30 USD и общие расходы около 60 USD пользователь предложил как гипотезу; право предоставления доступа через персональную подписку не утверждено.

## Следующие этапы — по порядку пользователя

1. Live-наставник и ограниченный учебный доступ к студийным агентам. Приёмка — реальный ответ модели в учебном диалоге и проверенные границы доступа; очередь без ответа не считается подключением.
2. Изолированный запуск JS/React и проверок ученического проекта.
3. Контролируемый деплой учебных проектов после разрешения куратора.
4. Telegram-уведомления: проверка авторства, очистка секретов и дедупликация.
5. Безопасное удалённое размещение, доступ с телефона и компьютера Матвея.
6. Подробные отдельные занятия для остальных дней и преподавательская приёмка видеомаршрута (в v2 уже есть шесть метаданных-проверенных вводных видео).

Один этап за раз; последующие не объявлять готовыми по наличию адаптера или документа. Проверка этапа 1: в учебном приложении и глобальном Hermes нет настроенного отдельного API-ключа наставника; установленный `hermes proxy` предлагает Nous/xAI, оба без авторизации, текущий рабочий провайдер Hermes — openai-codex. В другом, трейдинговом проекте есть отдельный OpenRouter-ключ: он не скопирован и не использован для обучения. Перед использованием этого ключа требуется явное решение владельца; иначе нужен отдельный учебный API-доступ. Основную конфигурацию и авторизацию Hermes не менять для эксперимента.

## Не сделано

Telegram-бот/группа/внешние уведомления; удалённое размещение; работающая модельная авторизация; изолированное исполнение JS/React; production-публикация; подробные отдельные занятия для всех 24 дней и полный преподавательски проверенный видеокурс. Проверенные материалы и непроверенные интеграции учитываются отдельно.
