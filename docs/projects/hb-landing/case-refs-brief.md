# Бриф: референсы для макетов 6 кейсов H&B

Задача: у каждого вымышленного кейса раздела «Избранные работы»
(`hb_landing/src/content/cases.ts`) должен быть свой узнаваемый интерфейс —
правдоподобная работа студии для конкретного клиента. Сейчас все шесть кадров
(`src/assets/cases/shots/<id>.jpg`) собраны по одному шаблону. Этот бриф —
вход для `taste-curator`: он подбирает референсы в библиотеке Nullume, по ним
дизайнер пишет спек, макеты верстаются в HTML и снимаются с DPR 3. Генерации
нет.

Источники правил: `docs/core/design-principles.md` (anti-references, dials),
`docs/core/design-profiles.md` (доменные профили), `docs/core/typography-pairs.md`
(кириллица), `docs/decisions/ADR-007-reference-sources-policy.md` (источники).

---

## 0. Диагноз нынешних кадров (общий анти-референс для всех шести)

Все шесть кадров — один экран с подменёнными словами:
- тёмный сайдбар слева + светлое тело + логотип-квадрат терракотового цвета;
- ряд из трёх одинаковых KPI-карточек «крупная цифра + моно-подпись», первая
  цифра — терракотовым;
- под ними таблица или две карточки одного вида;
- один шрифт (системный гротеск) + моно для подписей, акцент `#C2410C` —
  это цвет самой H&B, а не клиента;
- маркетинговые цифры кейса («+18% конверсия») вынесены в интерфейс продукта,
  где их в жизни нет; пустая нижняя половина кадра; цветные заглушки вместо фото.

Запрещено для всех шести макетов:
- шаблон «тёмный сайдбар + 3 KPI-карточки + таблица»;
- акцент H&B `#C2410C` и шрифты H&B (Montserrat, Open Sans) — у клиента свой бренд;
- Inter/Arial/системный как бренд-шрифт; фиолетово-синий градиент; глоу;
  карточка в карточке; side-tab бордеры; `#000` для текста;
- метрики кейса как декоративные плитки: цифра попадает на экран, только если
  её показал бы сам продукт (счётчик, итог расчёта, статус);
- однотонные плашки вместо фото товара; пустые полэкрана;
- повтор стилистики уже существующих живых кейсов: персиково-бежевый + тёмно-синий
  + капс-гротеск (pro-cosmetics) и кремовый + капс-антиква (zoo-moscow).

## 1. Условие разнообразия: 6 разных стилевых семейств

| Кейс | Тип экрана | Семейство (slug) | Акцент | Шрифты (кириллица есть) | Свет/тема |
|---|---|---|---|---|---|
| Смена | веб-приложение, недельный таймлайн | `warm-hospitality-planner` | кобальт `#2D5BD7` + пастельные роли | Onest / Onest | светлая, кремовая |
| Атлас | корпоративный портал, карточка договора | `swiss-engineering-portal` | сигнальный жёлтый `#F5C400` | IBM Plex Sans / IBM Plex Mono | белая, строгая |
| Дом Керамики | витрина, карточка товара | `material-showroom` | глазурь, морская волна `#1F5E63` | Jost / PT Sans | тёплый камень, фото-текстуры |
| Прайм.Фитнес | мобильное приложение iOS, 2–3 экрана | `bold-sport-dark` | лайм `#C8F031` | Unbounded / Manrope | тёмная (единственная) |
| Поток | CRM, сплит «письмо → поля» | `operator-cockpit` | ночной синий `#0B2545` + мятная подсветка `#9EE6C9` | Golos Text / JetBrains Mono | светлая, плотная |
| Советник | сайт магазина + открытый чат-виджет | `clinical-skincare` | ягодный `#B4235A` | Commissioner / Commissioner | белая, клиническая |

Правила:
- Цвета и шрифты — стартовая гипотеза. Куратор вправе заменить по найденным
  рефам, но: никакие два кейса не делят шрифт; акценты разнесены по оттенку
  минимум на ~30°; ровно один кейс тёмный; сохраняется 3 разных типа экрана
  на 6 кейсов минимум (сейчас их 5: приложение, портал, витрина, мобайл, CRM,
  сайт с виджетом).
- Шрифт проверять на сабсет `cyrillic` на fonts.google.com до фиксации.
- Рамка подачи общая и нейтральная (светлый хром браузера / рамка телефона,
  без терракоты) — это «подпись студии»; уникальным должно быть всё внутри.
- Кадр показывается в раскрытой карточке на тёмном фоне (`Portfolio.astro`),
  поэтому тёмный макет (Прайм.Фитнес) кладётся на светлую или лаймовую
  подложку, иначе сольётся.

## 2. Кейсы

### 2.1 Смена (`smena`) — `warm-hospitality-planner`

- **Отрасль / продукт / пользователь:** сеть из 14 кофеен; веб-сервис
  составления графика смен (SaaS по подписке); пользователь — менеджер сети,
  открывает и с телефона.
- **Экран:** десктоп, вид «Неделя»: таймлайн точек × дней со сменами-блоками.
- **Ключевые элементы:**
  1. Сетка «точки × дни недели» (видно 5–6 из 14 точек, счётчик «14 точек»),
     смены — цветные блоки с именем и ролью (бариста / кассир / старший).
  2. Боковая панель «Автоподбор» для выбранной смены: дата, время, позиция →
     2–3 кандидата с совпадением навыков и свободного времени.
  3. Проверки ограничений у кандидата: «макс. часы в неделю ✓», «дни отдыха ✓»,
     один конфликт подсвечен.
  4. Статус-строка генерации: «График собран за 20 минут».
  5. Мини-превью мобильной версии в углу (облако, доступ с телефона) — по желанию.
- **Настроение:** тёплое, спокойное, «кофейное», без корпоративной сухости.
  **Dials:** V4 / M2 / D6. **Профиль:** SaaS с триггером `if_data_heavy`.
- **Анти-референсы:** таблица фамилий без визуализации времени (как сейчас);
  KPI-плитки; Excel/Google Sheets-эстетика; кислотные цвета ролей; пастель,
  дающая серый текст на цветном (< 4.5:1).
- **lib_search (EN — отправлять в инструмент):**
  - `shift scheduling app weekly timeline view`
  - `staff rota calendar pastel role colors cream background`
  - `restaurant workforce scheduling dashboard`
  - `resource timeline gantt light ui friendly`
  - (по картинке) лучший найденный реф → `lib_search` по изображению за похожими.
- **RU (для ручного поиска на Pinterest/в Eagle, не в lib_search):** «график
  смен приложение», «календарь сотрудников пастель», «планировщик смен кафе».
- **lib_import:** свои доски Pinterest (API v5) про календари и планировщики;
  коллекции Raindrop/Eagle с SaaS-интерфейсами; RSS Land-book/siteinspire
  (раздел SaaS/productivity).
- **Критерии отбора:** таймлайн с читаемыми блоками и подписями внутри;
  ролевая цветовая кодировка из 3–4 тонов при тёмном тексте; кремовый/тёплый
  фон, а не холодно-серый; плотность средняя — видно неделю целиком.

### 2.2 Атлас (`atlas`) — `swiss-engineering-portal`

- **Отрасль / продукт / пользователь:** строительный холдинг, 800 сотрудников;
  внутренний портал согласования договоров; пользователи — диспетчер, подрядчик,
  юрист, финансист.
- **Экран:** десктоп, карточка одного договора с маршрутом согласования.
- **Ключевые элементы:**
  1. Шапка договора: номер (ДП-2418), подрядчик, тип договора, сумма, кнопка
     «Экспорт в Word».
  2. Визуальный чеклист этапов: Диспетчер → Подрядчик → Юрист → Финансы →
     Подписание; кто на каком этапе, сколько часов на этапе.
  3. Лента событий с уведомлениями «отправлено в email и Telegram».
  4. Боковой блок метрик юристов: «где тормозит» — типы договоров по среднему
     сроку, этап-узкое место; итог «средний срок 2 дня (было 9)».
- **Настроение:** инженерная точность, порядок, документ. **Dials:** V3 / M2 / D7.
  **Профиль:** Дашборд/админка (корпоративный портал).
- **Анти-референсы:** очередная таблица списком (как сейчас); «стартаповый»
  SaaS с округлыми карточками и пастелью; жёлтый как цвет текста (контраст);
  лишние тени.
- **lib_search (EN):**
  - `contract approval workflow stepper enterprise ui`
  - `swiss grid corporate portal document detail page`
  - `construction company intranet dashboard yellow black`
  - `approval timeline audit log interface`
- **RU (вручную):** «согласование договоров интерфейс», «корпоративный портал
  строгая сетка», «строительная компания дашборд жёлтый».
- **lib_import:** Pinterest-доски по швейцарскому стилю и enterprise UI; RSS
  Godly/Awwwards (раздел corporate/industrial); Eagle-папки с документными
  интерфейсами.
- **Критерии отбора:** модульная сетка с 1px-линиями, углы 0–4px; жёлтый —
  только маркеры этапа/плашки с тёмным текстом; моно-цифры для номеров и
  сроков; документ как центральный объект экрана.

### 2.3 Дом Керамики (`dom-keramiki`) — `material-showroom`

- **Отрасль / продукт / пользователь:** магазин плитки и керамики, 12 000 товаров
  из 1С; интернет-магазин с калькулятором метража; покупатель — человек на
  ремонте, считает количество.
- **Экран:** десктоп, карточка товара (одна плитка) со встроенным калькулятором.
- **Ключевые элементы:**
  1. Крупное фото/текстура плитки + вид «в интерьере» (реальные фото из
     Unsplash/Pexels с атрибуцией — не цветные плашки).
  2. Калькулятор метража: размеры комнаты 4,2 × 3,6 м, формат 60 × 60 см,
     запас 7% → 45 шт, 16,2 м², сумма. Арифметика должна сходиться с ценой за м²
     (например, 1 240 ₽/м² × 16,2 м² = 20 088 ₽).
  3. Статус «в наличии · остатки из 1С обновлены» (success-green) и цена
     табличными цифрами.
  4. Ряд образцов коллекции (свотчи других цветов) + «Каталог: 12 000 товаров»
     в навигации.
- **Настроение:** шоурум, тактильность материала, спокойная архитектурность.
  **Dials:** V6 / M3 / D4. **Профиль:** E-commerce (общий): глубина, success-green,
  цены `tabular-nums`.
- **Анти-референсы:** заглушки-прямоугольники вместо товара (как сейчас);
  плоская витрина без глубины; маркетплейсная пестрота и urgency-таймеры;
  люкс-чёрное с золотом.
- **lib_search (EN):**
  - `tile store product page room calculator`
  - `ceramic tiles ecommerce showroom warm stone palette`
  - `interior materials shop product detail large texture photo`
  - `architectural minimal ecommerce geometric sans`
- **RU (вручную):** «магазин плитки карточка товара», «керамика интернет-магазин»,
  «калькулятор плитки интерфейс».
- **lib_import:** Unsplash/Pexels (clean, с атрибуцией) — фото текстур плитки
  и интерьеров для самого макета; Pinterest-доски interior/material e-commerce;
  RSS siteinspire (архитектура, интерьер).
- **Критерии отбора:** фото занимает ≥ 40% карточки; тёплый каменный фон;
  геометрический гротеск в заголовках; калькулятор — компактный блок с
  крупным итогом, а не форма-простыня.

### 2.4 Прайм.Фитнес (`prime-fitness`) — `bold-sport-dark`

- **Отрасль / продукт / пользователь:** сеть фитнес-студий, 8 филиалов;
  мобильное приложение iOS; посетитель студии.
- **Экран:** 2–3 экрана телефона в ряд (разной высоты/смещения — не близнецы).
- **Ключевые элементы:**
  1. Расписание: лента дней + слоты с тренером, филиалом и «осталось мест»,
     кнопка брони слота.
  2. Push-напоминание на экране блокировки: «Через час: Силовая · Тверская»
     (напоминания за день и за час).
  3. Профиль: серия посещений/стрик, история, бонусы за регулярность.
  4. Переключатель филиала (8 филиалов).
- **Настроение:** энергия, ритм, уверенность. **Dials:** V5 / M4 / D5.
  **Профиль:** мобильное приложение (ближайший — SaaS + `docs/core/apple-patterns.md`).
- **Анти-референсы:** два одинаковых списка карточек (как сейчас); неоновые
  глоу; градиенты «фитнес-фиолетовый»; фото качков-стоков; тач-таргеты < 44px.
- **lib_search (EN):**
  - `fitness studio booking app dark ui lime accent`
  - `gym class schedule mobile app bold typography`
  - `workout streak profile screen ios`
  - `ios lock screen notification reminder app mockup`
- **RU (вручную):** «фитнес приложение расписание», «запись на тренировку
  мобильное», «спорт приложение тёмная тема».
- **lib_import:** Pinterest-доски mobile UI / fitness app; Eagle-папки с iOS
  экранами. Dribbble — только local-only через CLI с гейтом и с согласия
  владельца (ADR-007).
- **Критерии отбора:** крупный широкий шрифт для дат и времени; один
  кислотный акцент на графите, тёмный текст на лайме; ритм коротких блоков;
  явная иерархия «главное действие — внизу под большим пальцем».

### 2.5 Поток (`potok`) — `operator-cockpit`

- **Отрасль / продукт / пользователь:** логистическая компания, 400 заявок
  в день письмами; ИИ-разбор писем в CRM; диспетчер.
- **Экран:** десктоп, сплит: очередь писем → письмо с вложением → поля сделки.
- **Ключевые элементы:**
  1. Узкая колонка очереди: письма со статусами «разобрано ИИ / нужна проверка»,
     счётчик за день.
  2. Письмо клиента с вложением (PDF/скан); фрагменты текста подсвечены мятным
     и связаны с полями справа.
  3. Поля сделки: откуда, куда, груз, вес, тип кузова, срок, плательщик;
     у неуверенного поля — пометка «проверьте».
  4. Черновик ответа клиенту + кнопки «Создать сделку в CRM» / «Отправить».
  5. Тонкая строка времени: «2 мин на заявку» как реальный таймер обработки.
- **Настроение:** операторский пульт, скорость, контроль. **Dials:** V3 / M3 / D8.
  **Профиль:** Дашборд/админка (плотно, моно-цифры, 1px-разделители).
- **Анти-референсы:** две белые карточки с воздухом (как сейчас); «магия ИИ»
  — блестки, градиенты, роботы; чат-интерфейс вместо рабочего места.
- **lib_search (EN):**
  - `email to crm data extraction split view`
  - `dense operations dashboard inbox triage`
  - `document parsing ui highlighted fields linked`
  - `logistics dispatcher software interface`
- **RU (вручную):** «CRM логистика интерфейс», «разбор входящих заявок»,
  «извлечение данных из документа интерфейс».
- **lib_import:** Eagle/Raindrop-коллекции B2B и dev-tools интерфейсов;
  Pinterest-доски dashboard/inbox UI.
- **Критерии отбора:** трёхколоночная плотная раскладка; подсветка-связь
  «источник ↔ поле» как главный визуальный приём; моно для чисел и адресов;
  цвет только смысловой.

  (занято zoo-moscow); чат-пузыри цвета акцента H&B; аватар-робот.

- **RU (вручную):** «подбор косметики чат-бот», «клиническая косметика сайт»,

- **lib_import:** Unsplash/Pexels (флаконы на белом, с атрибуцией) для фото

- **Критерии отбора:** белый и холодно-серый фон; фото продуктов на чистом

## 3. Общие правила поиска

- `lib_search` получает **только английские** запросы: CLIP кириллицу не
  понимает и на русский возвращает шум. Русские формулировки выше — для
  ручного поиска владельцем.
- Сначала текстом, затем по картинке от лучшего найденного рефа.
- Каждый реф открывать через `Read` и смотреть глазами; по тегам не отбирать.
- Источники — по ADR-007: clean (Eagle, Raindrop, Pinterest API v5 по своим
  доскам, Unsplash/Pexels с атрибуцией, RSS Land-book/Godly/siteinspire/
  Awwwards); local-only (Pinterest-поиск по cookies, Dribbble) — только CLI с
  гейтом и только с согласия владельца. Ссылки не выдумывать.
- Реф, нарушающий глобальные запреты (контраст, глоу, системный шрифт), не
  берётся, даже если красив.

## 4. Формат результата от taste-curator

Папка на кейс: `docs/projects/hb-landing/case-refs/<id>/`, где `<id>` —
`smena`, `atlas`, `dom-keramiki`, `prime-fitness`, `potok`, `sovetnik`.

Внутри:
- `ref-1.jpg … ref-5.jpg` — превью (3–5 штук), ширина не меньше 1200px;
- `refs.md`:
  - семейство (slug) и доминирующий паттерн одной строкой;
