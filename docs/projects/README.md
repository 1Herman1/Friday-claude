# Проекты

Реестр всех продуктов репозитория Friday («Пятница», `1Herman1/Friday-claude`). Проекты равноправны: ни один из
них не задаёт правила для остальных. Общие правила — в `CLAUDE.md` и
`docs/core/`, специфика каждого — в его собственном каталоге.

Активный проект задан файлом `.active` (одна строка — имя каталога). По нему
ориентируются хук `session-start.sh` и `design-lint.mjs`.

**Рабочая ветка: `claude/greeting-nnz368`.** Она одна на весь репозиторий —
свойство репозитория, а не проекта, поэтому и записана здесь однажды, а не в
каждом `project.md`. Новых веток не заводить. Ветка выкатки — у каждого

## Каталоги верхнего уровня, не принадлежащие проектам

Кроме кода проектов в корне лежат служебные каталоги. Они здесь перечислены,
потому что карта репозитория без них неполна, а неполная карта заставляет
гадать, чьё это и можно ли трогать.

| Каталог | Что это | Чей |
|---------|---------|-----|
| `.claude/` | Агенты, команды, скиллы, хуки, детерминированные проверки | Общий |
| `docs/` | Универсальная база, проекты, решения, архив | Общий |
| `projects/` | Весь код всех проектов, по каталогу на проект | По проектам |
| `tools/` | Вспомогательные инструменты (в т.ч. локальный MCP-сервер иконок) | Общий |
| `geo_agent/` | Данные и отчёты GEO-рантайма | `seo-department` |
| `.geo-topic-agent-runtime/` | Код стороннего GEO-агента (вендорен) | Общий |

В корне не осталось ни одного каталога, принадлежащего отдельному проекту:
всё проектное живёт в `projects/<проект>/`, включая конфигурацию выкатки
(`projects/simba/deploy/`) и сборочные скрипты проекта
(`projects/simba/scripts/`). Корневые `package.json` и `package-lock.json`
общие — воркспейсы перечисляют каталоги внутри `projects/`.

## Состав каталога проекта

- `project.md` — контекст, стек, рабочая ветка, выкатка, правовой контур
- `brand.md` — продукт, тон, dials, домены UI
- `design-system/MASTER.md` — зафиксированные токены (генерируется `/design-system`)
- `security-profile.md` — карта стека для агентов `security-*` (`/security-profile`)
- остальное — по надобности проекта (отчёты, медиа, контракты API)

## Новый проект

1. `cp -r docs/projects/_template docs/projects/<имя>` и заполнить.
2. `/design-system` → `design-system/MASTER.md`.
3. Записать имя в `docs/projects/.active` и строку в таблицу выше.

Работа всех проектов идёт в одной рабочей ветке репозитория — своих веток у
проектов нет.
