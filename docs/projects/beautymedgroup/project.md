# Проект: BeautyMedGroup (beautymedgroup.ru, academy.beautymedgroup.ru)

Специфика проекта. Универсальные правила, агенты и воркфлоу — в `CLAUDE.md` и
`docs/core/`. Здесь — только то, что относится именно к этому проекту.

## Стадия

**Правки чужого сайта по ТЗ клиента.** Сайт делал другой разработчик, мы его не
переписываем — вносим точечные изменения. ТЗ, готовые тексты и порядок работ —
`tz.md`, открытые вопросы и состояние — `status.md`.

Связь с Perfect Skin: BeautyMedGroup — дистрибьютор тех же брендов ISSEIMI и
GLACÉE (производитель Heber Farma, Испания). С сайта Perfect Skin название
«БьютиМедГрупп» убрано, но фото 8 товаров Perfect Skin взяты с
beautymedgroup.ru (`docs/projects/perfect-skin/client-questions.md`).

## Выкатка

Ветки выкатки нет, GitHub Actions не участвует. Правка вносится прямо на сайте
клиента, поэтому «выкатка» = сама правка. Порядок:

1. **Полный бэкап** (файлы + БД) через ISPmanager перед первой правкой дня.
2. Правка через `wp-cli` по SSH или в wp-admin / редакторе Tilda.
3. Проверка страницы на десктопе и телефоне, сброс кэша, если он есть.

## Доступ из среды

Проверено 22.10 из облачной сессии: **HTTPS до сайта проходит** (`/wp-json/`
отвечает 200), **SSH до сервера — нет** (порт 22 не открывается: прокси среды
пропускает только HTTP/HTTPS). Значит, из облака доступен REST API WordPress
по паролю приложения, а `wp-cli` по SSH — только с Mac Гермеса:

- **Вариант А (облако):** REST API + пароль приложения из секретов окружения.
  Тексты страниц, записи, медиа. Не достаёт до бэкапа, полей ACF вне REST,
  шаблонов темы.
- **Вариант 1 (основной):** Claude Code локально → SSH на сервер → `wp-cli`
  (страницы, записи, ACF-поля, медиа, файлы темы). На reg.ru SSH, возможно,
  нужно включить в панели («Shell-доступ»).
- **Вариант 2:** Claude in Chrome в браузере, где выполнен вход в wp-admin и
  Tilda. Покрывает всё, включая Tilda и слайдер.
- **На будущее (постоянная поддержка):** официальный плагин WordPress MCP
  Adapter (WP 6.9+) + Application Password. Старый `Automattic/wordpress-mcp`
  архивирован — не использовать; коннектор WordPress.com не подходит (только
  WP.com и только чтение).

Облачная сессия готовит тексты, команды `wp-cli` и SEO-материалы.

**Логины, пароли, IP и адрес панели в репозиторий не пишутся** — они у Гермеса.
В присланных паролях возможна путаница `l` (эль) / `I` (ай). После работ все
пароли сменить (засвечены в переписке); при смене пароля MySQL — обновить
`wp-config.php`.

## Технологический стек (реальный)

Чужой, не наш дефолт: никаких Next.js, Prisma, Vercel — не предлагать.

- **beautymedgroup.ru:** WordPress + WooCommerce, самописная тема
  `wp-content/themes/beauty`, конструкторов страниц (Elementor и т.п.) нет.
  Защита форм — CleanTalk. Тексты страниц и записей — в БД; слайдер, контакты и
  подвал — вероятно, поля ACF / настройки темы или зашиты в PHP-шаблоны.
- **academy.beautymedgroup.ru:** отдельный сайт на Tilda. API Tilda только на
  чтение — правки через редактор.
- **Хостинг:** reg.ru, панель ISPmanager. MySQL доступна только с сервера
  (phpMyAdmin или SSH).

## Правила работы с чужим сайтом

- Перед правкой — найти **все** вхождения текста (`wp search-replace --dry-run`
  или поиск по БД): одни формулировки повторяются на нескольких страницах.
- `search-replace` только с `--dry-run` сначала, затем точечно по таблицам и
  ID, а не по всей БД: сериализованные поля ACF ломаются от грубой замены.
- Файлы темы правим, только если правки нельзя сделать в БД; перед правкой —
  копия файла рядом.
- Удаление медиа (п. 5а ТЗ) — необратимо, только после бэкапа.
