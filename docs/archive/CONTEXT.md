## Решения, которые нельзя забыть
- **Автономия до развилки (08.10).** Цепочку без выбора довожу сам до отчёта. Спрашиваю только на вкусе, тратах больше $1 и необратимом. Причина: целый день ушёл на подтверждения.
- **Одна ветка `claude/greeting-nnz368`.** Новых веток не создаём, ветки удаляет только Гермес.
- **Трейдинг, база:** одна PostgreSQL на дневник и агентов. Владелец схемы и миграций — Prisma (`shared/db`), Python ходит через SQLAlchemy Core по сгенерированным определениям. Причина: дневник показывает сделки человека и агента в одной модели. Отвергнуты две отдельные базы, Alembic как владелец и запись только через HTTP API.
- **Трейдинг, числа:** Decimal(38,18) вместо целых центов, float в Python запрещён. Причина: цены и объёмы крипты доходят до 1e-8, комиссии приходят в разных активах. Правило центов остаётся только для биллинга.
- **Трейдинг, единица правды — исполнение (fill).** Сделка собирается из fills, фандинга и комиссий. Ручная сделка записывается синтетическим fill. Поля `executor` (HUMAN/AGENT), `origin` и `signal_id` идут раздельно. Итоги сделки считает одна SQL-функция `tp_recompute_trade` и для TS, и для Python.
- **Трейдинг, где база:** решение Германа от 11.10 — «начнём на Маке». PostgreSQL 17 стоит в `~/Applications`, база `tradeperf` доступна только с localhost и стартует вместе с Mac. Адрес подключения — в `trade-performance/.env`. Supabase или сервер — позже.
- **Токен `claude setup-token` = та же подписка Max**, не API и не кредиты. Нужен потому, что Hermes при обновлении OAuth-сессии сбивал вход Claude Code. Токен лежит в `~/.claude/hermes-oauth-token`.
- **Код ищет сетап и считает риск, LLM только отвечает ВЗЯТЬ/ПРОПУСТИТЬ.** Причина: 9 моделей на одних свечах разошлись по входам на 240 п. Opus решает, Sonnet закрывает массовые роли. Таймфрейм 5m выбрал Герман.
- **Никакой маскировки бота под человека на пропах.** Причина: Hash Hedge (п. 12.2) запрещает ботов. Вместо этого: полуавтомат, письмо за разрешением или пропы, где автоматизация разрешена (Propr, HyroTrader, SizeProp). Памп-дамп Германа на пропы не идёт.
- **Контекст переносят файлы, а не чат.** Топик — отдельная сессия, поэтому решение сразу пишем в ТЗ, STATUS или README и коммитим.
- **PS:** факты не выдумываем, тексты клиента берём дословно. Получатели ПД — TimeWeb, СДЭК, ФНС. Реестр ФНС служит только подсказкой. В медиа сначала переиспользуем уже сгенерированное (на ролики ушло ~$35). Согласие при входе показывается, но на сервере не записывается — так и отражено в документе.
- **Действуют и раньше принятые решения:** `challenger` и `/council`, порог 80% только для находок, РКН в два гейта, `portability-check.sh`, моторика только через обёртку, дизайн оцениваем по скриншоту. Nullume: `estimate` идёт до `create`, Pinterest и X — только локально.

## Грабли
- **Секрет в чате:** 11.10 Герман прислал токен в Telegram. Ключ перевыпустили, `hermes-archive.py` теперь выкидывает такое сообщение целиком. Вставлять ключ в файл: `pbpaste | tr -d '[:space:]' > файл` (была опечатка `bpaste`, и первый файл токена вышел пустым).
- **Ложная очередь архива:** скрипт подготовки свода находит `status: raw` и в теле записи (цитата лога cron), поэтому уже свёрнутая запись попадает в список. Grep надо привязать к фронтматтеру.
- **Проверка рапортует «успех», ничего не проверив** — семь случаев. У новой проверки сначала подтверждать, что список файлов непустой.
- **Мутационные тесты** делаем только в копии worktree: в общем дереве один уже выключил потолок цены.
- **Облачная среда:** нет PIL, `sleep` заблокирован, CLIP только на Маке. CLIP не понимает кириллицу.
- **Telegram:** при включении тем ID группы меняется на `-100…`. Названия топиков боту не видны, thread_id появляется только после первого сообщения в топике.
- **Hermes на Маке:** когда Мак спит, бот и cron молчат. Edge TTS игнорирует указания по голосу.
- **MEXC klines:** не больше 500 свечей за запрос, листаем с ретраями. BSD `cut` резал UTF-8 (починено через `perl substr`).
- **Перед пушем всегда `fetch` и `rebase`:** параллельные сессии пушат постоянно.
