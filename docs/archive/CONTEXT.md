## Решения, которые нельзя забыть
- **Prop-agents: цель — автономная торговля ИИ-агентов на пропах.** Сигналы и SaaS — вторым шагом. На старте $0 на челленджи: 2–3 месяца демо (сначала бумажная торговля, потом демо), при плюсе — челленджи на счёт $5–10k. Тестируем много разнородных стратегий, оставляем 3–4. Агент = стратегия × площадка, на старте агенты изолированы, их координирует только риск-слой. Сразу полная автономия, kill-switch и лимиты остаются. Сервер 24/7. Площадки — пропы плюс свои счета на Hyperliquid и MEXC.
- **Стратегию отбираем по матожиданию в R после комиссий, а не по winrate.** Демо оцениваем по числу сделок (≥100 на стратегию), а не по календарю. Причина: на 5m со стопом 0,1–0,2% taker-комиссия съедает 0,5–1R. Ни один источник не показал скальпинг на 1–5m, который остаётся в плюсе после комиссий, поэтому SMC 5m нужен вход лимиткой (maker).
- **ИИ дневника — только Claude Opus 5.5** (решение Германа от 12.10). DeepSeek и OpenRouter не используем. Пока дневник личный, вызов идёт через подписку; для SaaS понадобится отдельный ключ Anthropic API, потому что подписку нельзя использовать в продукте для других людей.
- **Код ищет сетап и считает уровни, LLM только решает «входить или нет»** с учётом сигнала, контекста, риска и сентимента. Невалидный ответ = HOLD. Лимиты меняет только Герман. Причина: 9 моделей на одних свечах дали входы с разбросом 240 п., часть с отрицательным R:R.
- **Никакой маскировки бота под человека на пропах.** Hash Hedge (п. 12.2) запрещает ботов. Памп-дамп Германа на пропы не идёт.
- **Трейдинговая база:** одна PostgreSQL, владелец схемы — Prisma, Python ходит через SQLAlchemy Core. Деньги в Decimal(38,18), float запрещён. Единица правды — исполнение (fill). Итоги сделки считает `tp_recompute_trade`.
- **PS:** тексты клиента ставим дословно, исправляем только явные опечатки и показываем их список. Факты не выдумываем. Медиа сначала переиспользуем. Получатели ПД — TimeWeb, СДЭК, ФНС.
- **Процесс:** автономия до развилки (спрашиваем только про вкус, траты больше $1 и необратимое). Одна ветка `claude/greeting-nnz368`. Контекст переносят файлы, а не чат. Токен `claude setup-token` — та же подписка Max. Действуют и раньше принятые правила: challenger и /council, порог 80% только для находок, РКН в два гейта, моторика через обёртку, дизайн оцениваем по снимку.

## Грабли
- **В облачной сессии Claude Code нет агентов репо** («Agent type 'coder' not found» — там только general-purpose, Explore, Plan). Задачу отдаём general-purpose и вкладываем в неё полный текст агента.
- **Извлечение текста из PDF иногда возвращало прошлую страницу.** Каждую цифру сверяем с заголовком внутри полученной страницы (правило записано в скилл `grounded-citations`).
- **Ложная очередь архива:** скрипт ищет `status: raw` по всему файлу, а не только во фронтматтере, поэтому запись 10-10--hermes-friday снова попала в очередь, хотя уже свёрнута. Grep надо привязать к фронтматтеру.
- **Установка в Hermes ждёт подтверждения;** если ответа нет 5 минут, установка срывается. Язык STT по умолчанию английский.
- **Секрет в чате (11.10):** ключ перевыпустили, `hermes-archive.py` вырезает такое сообщение целиком. Вставлять ключ так: `pbpaste | tr -d '[:space:]' > файл`.
- **Проверка рапортует «успех», ничего не проверив:** у новой проверки сначала подтверждаем непустой список файлов. Мутационные тесты делаем только в копии worktree.
- **Telegram:** thread_id топика появляется только после первого сообщения. Мак спит — бот и cron молчат. MEXC klines отдаёт не больше 500 свечей за запрос.
- **Перед пушем всегда `fetch` и `rebase`:** параллельные сессии пушат постоянно. Логи упавшего job GitHub иногда отдают 404.
