### A1 — ВАЖНО: byte-level контракт смешивает несовместимые эпохи hook blocking

**Evidence upstream:** `CLI-CONTRACT.md:1399–1402` одновременно задаёт Codex/Hermes Stop `{"decision":"block","reason":...}` и обобщает «Non-blocking in every harness»; `1414` снова выводит отсутствие blocking из того, что нет exit2. Но `1557` прямо описывает Hermes Stop-only blocking с `agent.max_verify_nudges`; `1552` оставляет Codex «No». Это подтверждённое **внутреннее противоречие документа** в одной pinned revision, не доказанная runtime-ошибка engine.[1]

**Friday delta:** `.codex/CODEX.md:53–61,735–741` требует адаптации фактического runtime, `review-loop.md:4,52–54,69–73` отделяет реальные gates от декларации. Поэтому переносить таблицу как единый adapter contract нельзя: exit0 процесса не означает, что host принял stop. Для Hermes parent это особенно существенно — native Codex matrix не даёт прав/схем Hermes.[2][3]

**Действие/owner:** координатору сохранить как DOC-CONTRACT-CONFLICT; при отдельной реализации owner adapter/QA должен фиксировать `host,event,stdout-schema,exit,continuation-limit` раздельно и проверять receipt host. До этого — не заменять Friday task gate upstream hook. **Verdict: confirmed documentation conflict; runtime NOT RUN.**

### A3 — ВАЖНО: documented on/off теряет независимый scan-size limit

**Evidence upstream:** `1512` явно говорит, что `on/off` заменяет весь `hook.limits` на maxFindings/maxChars и удаляет ранее заданный `maxFileBytes`, хотя default и read semantics `1113,1150,1383` используют этот лимит для размера реально проверяемого файла. `1529` reset удаляет и hook, и detector, но оставляет manifests; это другой scope, не безопасный synonym off. Здесь речь о **заявленном документом write contract**, current Rust admin заново не прочитан, repro не выполнялся.[1]

**Friday delta:** `.codex/CODEX.md:61–66,84–90` не разрешает неоговорённую смену границ проверки; заданное включение/выключение не должно молча менять выбранную пользователем coverage policy. Возврат size threshold к default может как пропустить ранее допускавшийся большой файл, так и расширить работу относительно более строгого лимита.[2]

**Действие/owner:** координатору как интеграционный risk, не как подтверждённый live bug; будущий config/QA owner должен partial-merge `limits` либо честно документировать migration. ## Три главных вывода

1. Сам CLI-CONTRACT не однородный актуальный runtime contract: historical JS и Rust additions оставляют явное противоречие Stop blocking. Интеграции нужен event/host-specific контракт.
2. Hook activity/coverage нельзя выводить из семидневного cache, exit0 либо отсутствия новых сообщений: есть отдельные skip/budget/suppression/continuation условия.
3. Перед переносом helpers важнее сохранить Friday project/config scope: live pointer selection и on/off limit replacement меняют поведение иначе, чем обещает простое «выбрать проект/включить проверку».
