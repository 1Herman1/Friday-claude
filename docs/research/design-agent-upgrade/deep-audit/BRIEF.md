## Definition of complete

1. Пройти всю назначенную область дерева. Инвентаризация ≠ substantive reading. Для каждого файла/группы вести coverage ledger. Text, реально прочитанный полностью и осмысленный: full; частичный: partial с ranges; byte-identical duplicate: alias с sha/canonical; generated fixture/data: classified с правилом; binary: metadata-only/visual-reviewed если реально открыт. Нельзя присвоить full от простого подсчёта/хеширования/автоматического поиска.
2. Дедуп только по содержимому, не по имени. Отличающиеся runtime adapters не считать копией канона. Не пропускать ссылки/references; проверить unresolved paths, imports, script entrypoints, hook triggers.
3. Содержательная карта: каждый skill/command, trigger, вход, шаги, выход, policy, references, assets/scripts/dependencies, runtime side effects, проверка/ограничения. Конкретные идеи typography/layout/animation/interaction/a11y/content, не одна архитектура папок.
4. Сравнение с локальными аналогами с file:line доказательствами: already equivalent / partial / absent in inspected scope / conflict / not applicable. Отсутствие имени upstream не значит отсутствие правила; совпадение слов не значит semantic equivalence. По возможности отдельно readable MD, executing TOML, script, actual live state (последний не проверяем).
5. Рекомендации: добавлять только доказанный delta, указать owner/target file и expected output/test, отказ/конфликт с объяснением. Taste остаётся одним из трёх полноценно анализируемых кандидатов; не исключать его предварительно из-за house rules.
6. Итог честно указывает exact covered counts, исключения, ограничения. Большие autogenerated snapshots и binary assets можно разобрать по схеме/семействам с явным не-semantic классифицированным покрытием; не называть это ручным прочтением каждого byte. Если не успеваешь — назвать незакрытую область, не говорить полный PASS.
7. Сохранять средние батчи в собственный coverage/report файл, чтобы прогресс пережил timeout. Координатор проверяет отчёт, counts и основные доказательства.
