## 1. Live: транспорт, очередь, восстановление — не просто UI-overlay

**Входная граница.** `POST /events` сперва парсит JSON и проверяет token, отдельно отвергает прямые `manual_edits` и `manual_edit_apply`, затем валидирует тип/поля и существование journal. Browser event ID — 8 lowercase hex, generate count 1–8, variantId — строка 1–3 цифр; это уже, чем допустимый ID session-store (`A-Za-z0-9_-`, 1–128). Insert требует anchor, конечные размеры placeholder и prompt/annotations; replace — допустимое visual action и outerHTML. Browser `extractContext` несёт не только HTML, но selector anchor и число совпадений, computed styles, custom properties, parent и box; эти данные позже нужны безопасному bake. Создающие POST generate/steer идут до остальных событий, чтобы checkpoint не обогнал создание сессии. [1:1810–1840, 1876–1879]

**Доставка.** SSE — browser-facing уведомления, agent-facing работа идёт через leased `GET /poll`. Приоритет accept/discard/exit выше manual apply/steer/cleanup, выше generate; фильтр `types` и session `id` сохраняется и у parked poll. Lease по умолчанию 30 секунд, `live-poll` просит 600000 ms; первый generate pickup запускает preflight scaffold с 15-секундным таймаутом и `--defer-source-write`. Poll лишь арендует событие, а не исполняет работу. `retry` освобождает lease. `POST /poll` различает sourceEventType, manual result schema, stale reply, compile-failed publication и неизвестный ID. `steer_done` требует file либо осмысленное сообщение о no-op. [1:1853–1874]

**Восстановление.** Journal + snapshot сохраняют фазу, pending event, lease, отдельные browser/publication revision domains, owner, source/preview, generation timings, mount failures. Snapshot доверен только при совпадении ID и длины journal. Fenced/terminal/canceled поколения не должны ожить от позднего done/checkpoint. Недоставленный completion повторно broadcast-ится по generating checkpoint лишь при соответствующих условиях. `done` не равен видимому варианту: browser mount имеет отдельные success/failure events и renderState. `status`/`resume` показывают manual apply, failed mount и carbonize как разные следующие действия; resume read-only. [1:1842–1851, 1876–1893, 2135–2147]

**Операционный цикл.** `live-poll` может сам обработать accept/discard, но `{handled:false}` с exit 0 не является успехом; смысл в JSON. Carbonize оставляет `_completionAck.final:false`, требует ручной интеграции и `live-complete`; dirty-source gate блокирует complete без cleanup. Stream ждёт acknowledgement перед следующим событием. Инструкции прекращают ожидание после третьего подряд timeout; shutdown разрешает parked polls через exit, закрывает SSE и удаляет временные preview. [1:1806, 2100, 2126–2154]

## 2. Scaffold, preview, accept: долговременный source отдельно от эксперимента

**Локатор и границы.** Wrap/insert могут изолировать точный byte range на общей строке лишь в безопасных случаях, учитывают вложенные same-name tags, raw text в script/style/textarea и различия HTML/component case. JSX-изоляция ограничена `.jsx/.tsx`; обычные JS/TS modules не получают такую правку. Сильный id нельзя молча заменить более слабым class-match из другого файла. Неоднозначность, не закрытый элемент, inline Svelte anchor, generated source — явные refusals/fallback, не эвристический выбор первого элемента. Deferred wrapper несёт исходные replacement line numbers и один replacement block. В source search есть depth/extension/ignore ограничения и git-generated checks. [1:1895–1955, 2005–2007, 2156–2167]

**Variant dialect.** HTML/JSX wrappers, markers, scoped CSS и Astro global-prefixed CSS различаются. Один top-level element варианта должен сохранять tag оригинала. Params range/steps/toggle материализуются как `--p-*` и `data-p-*`; browser stylesheet управляет отображением/значениями, при переключении они возвращаются к defaults. Параметры и readiness sentinel являются временным preview-протоколом. [1:1957–2003]

**Svelte — отдельный adapter.** Требуется compiler >=5 из приложения; непереносимые constructs (component tags, render/await, directives, spreads и др.) дают source-preview fallback. AST prop contract разделяет text/raw/condition/collection/handler. Stubs, manifest v2, runtime и params лежат под `node_modules/.impeccable-live/`; done компилирует варианты и публикует новую revision directory, browser импортирует компоненты из неё и сообщает mount outcome. Source не равен preview manifest. [1:1869–1870, 2009–2028]

**Accept/discard.** Standalone marker lines проверяются повторно под source lock. Receipt делает повтор accept/discard идемпотентным, но конфликт operation/variant отвергается. Svelte accept восстанавливает expressions, примиряет CSS, защищает существующие selectors, проверяет leftovers. HTML/JSX accept с CSS обычно оставляет carbonize, а не готовую постоянную интеграцию. Mechanical `--bake` — opt-in, запрещён при knobs, динамическом/component root, неуникальном/неподтверждённом anchor, неподдерживаемом scope либо отсутствии stylesheet; правила append, не переписывание существующих. Astro `is:inline` предотвращает смену индексов compiled style modules при cleanup. Lock с owner token не снимает чужой lock. [1:2030–2075]

**Source links (из самого контракта, не независимое чтение этих файлов):** `live-server.mjs`, `live/generation-preflight.mjs`, `live/source-search.mjs`, `live-wrap.mjs`, `live-insert.mjs`, `live/svelte-component.mjs`, `live/svelte-ast.mjs`, `live-accept.mjs`, `live/accept-css.mjs`, `live/accept-verify.mjs`, `bake.rs`, browser `live-browser*.js`, `instructions.mjs`. [1:1895, 2005, 2009, 2030, 2065, 2117–2207]

## 3. Manual edits — staged transaction с реальным source proof

Buffer merges по `(pageUrl, ref)`, сохраняет первоначальный originalText. Stash, commit, discard и rollback — разные routes. Undo отдельного ref запрещён при in-flight apply/transaction; снятие superseding removal может восстановить предшествующий copy edit. Apply event содержит evidencePath, schemaVersion, deadline, chunk и repair metadata; default chunk — три op. Hard timeout tombstones ID и откатывает snapshot файлов, поздний reply получает stale 409 + rollback. [1:2077–2088]

Result требует `status`, применённые entry IDs, failed entries, touched files и notes; summary вместо source result отвергается. Проверяются unreported source changes, failed-entry changes, markers и syntax; parser может быть optional с warning. Repair bounded, `needs_decision` не является завершённым apply. Есть chat provider и subprocess providers: **Codex с `--dangerously-bypass-approvals-and-sandbox`, Claude с `--permission-mode bypassPermissions`**. Это документированная upstream способность, не разрешение применять её во Friday. Для leased chat event запрещено повторно запускать commit CLI. [1:2084, 2088–2094, 2185–2197]

Связанные source names: `live-commit-manual-edits.mjs`, `live-manual-edit-evidence.mjs`, `live-copy-edit-agent.mjs`; текст evidence содержит bounded candidate search и sourceHint statuses, включая generated/outside_cwd. [1:2092–2094, 2185–2197]

## 4. Component review: decision, provenance, lifecycle — разные доказательства

- V3 components — **plan and asset review**, assembled first viewport — stage hero. Plan строится из pinned spec/comp/plates, raster → asset, flagged/code-drawn/nonflat chrome → plan crop, остальные → codeRegions. Каждый измеренный region должен встретиться ровно один раз; specSha256 связывает packet со spec. V3 capture **не запускает browser**, а фиксирует raster-source / comp-crop proofs. Legacy v1/v2 capture использует другую native-component-preview схему. [1:2210–2247]
- Prepare snapshot-ит зависимости во внешний store, одинаковый input переиспользует round; changed input сохраняет лишь непротиворечащие approvals. Native capture замораживает declared inputs, отклоняет нестабильные pixels, script previews и плохие dimensions. Serve — foreground loopback, pinned files only, версия submission, idle/CI/headless gates; никто не review-ил — pending и exit 4, не autoapprove. [1:2248–2286]
- Approval требует всех components, отсутствия revise/reclassify/missing и inventoryConfirmed. Receipt identity — `local-browser`, не доказанная human identity. Producer-written `captureVerified` не доверяется; verify пересчитывает blob hashes, coverage и proof associations. **Provenance не доказывает эстетику, semantics, completeness или human-eval qualification.** [1:2287–2312]
- Build plates/hero gates сверяют текущую journey/spec и все pinned bytes; hosted path берёт только trusted session directories, не producer pending claims. Accepted first viewport закрывает review journey: новые source bytes либо manifest IDs не открывают её заново; новый design journey — отдельное намерение/store. Visual approval carry-forward по неизменным displayed bytes не отменяет source-integrity checks. [1:2314–2316, 2343–2355]

Source links: `docs/PLAN-REVIEW.md`, `ui/component-review/README.md`, native `component-review` и `build-phase`; в этом worker проверен контракт, а не внутренности этих модулей. [1:2212–2215, 2306–2314]

## 5. Capture: нельзя выдать reference replay за сборку

Text/control/chrome, визуально сохранившие принятый первый viewport, могут перевести numeric contradictions/missing/type readings в advisory; при whole-frame agreement >=95% numeric fight заканчивается. Material vetoes (plates, organic clips, invented ink, wrong capture size, native presence) остаются; отсутствие plate даже на принятом screenshot требует отдельного вопроса владельцу и его цитаты для force, не механического разрешения. После acceptance новый review не предлагается как обход. Responsive ищет displaced pixels, не сразу называет их missing; блокирует вытеснение за viewport и после трёх failed attempts эскалирует владельцу. [1:2320, 2335–2341]

Code-only capture использует frozen snapshot, declared dependencies либо static inventory, primary-font check, две идентичные viewport screenshots. Comp/spec не served; загруженные byte/base64 copies comp или approved screenshot запрещены. Byte equality не видит re-encoding, поэтому измеряется raster paint coverage: >=15% viewport без объявленных raster regions — refusal. Учтены псевдоэлементы, SVG references с raster content, filter/marker extents, object-fit и clipping chain. Canvas/iframe/object/embed, running animation, внешние dependencies и missing primary font отказаны в этом native пути. [1:2322]

Raster path вмешивается в declared plates ради presence proof, исключает comp/spec из сервинга, применяет сходную защиту reference copies и 15% undeclared raster coverage. Hero/desktop exclusions основаны на region boxes, mobile — на declared plate paths. Host capture должен возвращать method/spec binding, servedToPage, frameProofs и точное число receipts; невалидный payload released/refused. Clock pinning начинается в одном instant, но время продолжает течь; approved review instant можно повторно использовать. [1:2324–2328]

Важно для синтеза: фраза 2332 «never waives missing regions» читается **с уточнением 2320**: принятую владельцем отсутствующую text/control/chrome region контракт переводит в advisory, если current остаётся визуально accepted. Это не универсальное прощение отсутствующих material regions и не автоматическая переоценка поздних изменений. [1:2320, 2330–2332]

## 6. shot, motion-capture, walkthrough — evidence ≠ quality verdict

`shot` делает desktop/mobile viewport PNG либо capped full-page screenshot, ожидает load/images/fonts, пишет paths; ошибка одного viewport не отменяет запись других. Это наблюдение страницы, не trusted native review receipt. [1:2357–2370]

`motion-capture` — internal reviewer recorder: максимум 20 CDP steps, фиксированный region в 1000×760, 3–15 animated samples + before/settled, bounded timelines. Записывает transform/opacity/clips/paint order/identity/shadows, flags jump, replay, crossfade, orphan, reduced motion и др. Exit 0 означает **evidence recorded, даже с findings**; incomplete exit 1 никогда не clean verdict. Reduced-motion baseline повторяет interaction — потенциально дважды меняет app data. Canvas, timer-driven changes, cross-origin/closed roots и сложная композиция требуют visual reviewer. [1:2372–2439]

`walkthrough` локально через ffmpeg/ffprobe превращает recording <=2 минут в H.264 без аудио и poster, ограничивает размер/chapters, пишет atomic outputs и payload для needs_you walkthrough; не само approval. Проверяет tools, output collisions и не затирает пользовательские исходники. [1:2725–2769]

## 7. Loop и MCP — privileged интеграция, не переносимое имя команды

Loop install/update требуют compiled SHA256 pins, HTTPS, lock, staged rename/rollback и проверки реального executable при SIGTERM. Версия release видима update лишь после нового engine release. Connect пишет MCP, hook, rule block и местами approval mode; disconnect journal-ит undo, сохраняет unrelated edits/conflicts. macOS quarantine/version gates меняют hook behavior; Cursor/Copilot/opencode поддерживаются разными adapters. `--mcp-only` намеренно не пишет hooks/rules/Loop records и не требует app. Status read-only проверяет MCP+hooks+instruction+record, а не одно наличие bundle. [1:2484–2591, 2670–2723]

Switches sync пишет user-level agent rules, team switches — repository block; unknown lines сохраняются, duplicate/unbalanced markers отказаны. Есть special symlink/ignore/tracked guards для Cursor и fallback-preservation для opencode. Taste line — предложение/сохранённое consent, не автоматическая полная личная память. **Hermes среди документированных Loop connect adapters не перечислен**; нельзя объявить эти hooks нативно работающими здесь. [1:2503–2570, 2592–2669]

MCP — stdio proxy к account `/mcp`, stdout только frames; initialize/ping могут отвечать локально. Reauthentication относится к missing sign-in/refresh/401/insufficient_scope, не ко всякому 403; headless не ждёт browser. Browser relay single-driver, probe не claims, explicit browser_end освобождает connection; native messaging origin pinned и socket private. `artifact.asset` читает regular non-symlink file до 50 MB, хеширует и загружает bytes локально без передачи содержимого через модель; это всё равно внешняя отправка. Connected/seen presence различаются, dead records читающая команда удаляет. [1:3407–3564]

Source links: `crates/cli/loop-checksums.txt`, `scripts/check-loop-release.mjs`, account `Session`, MCP/native browser host и engine-journal adapters названы контрактом, но не исполнены и не независимо сверены этим worker. [1:2709–2723, 3445–3564]

Правила — **data, not instructions**, PRODUCT/DESIGN выше. Telemetry opt-out не отключает preference read. Taste note — явная запись предпочтений с idempotency hash, не разрешение импортировать произвольную клиентскую информацию. Upload receipts и JSON output shape могут меняться при savedTo/savedPages; local report path, remote saved page и reportsOff надо различать. [1:3288–3405, 3570–3594]
