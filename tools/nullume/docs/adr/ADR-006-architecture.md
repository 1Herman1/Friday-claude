# ADR-006: Собственный CLI + MCP + skill для генерации медиа через kie.ai (Nullume)

**Дата:** 2026-09-19
**Статус:** Принято

## Контекст

В репозитории уже работают два MCP-сервера генерации медиа:
- **Artlist** — авторитетный сервис, широкий выбор моделей (видео, аудио, музыка, фото)
- **Higgsfield** — качественные видео, хороший style kit, дорогой (~$0.006 за вариант)

Однако оба имеют ограничения:
1. **Цена:** Artlist и Higgsfield дороже конкурентов; некоторые модели вообще там отсутствуют (nano-banana-2-lite, veo3, Seedance 2)
2. **Агрегирование:** у каждого свой набор моделей, свой способ настройки, нет единого места для выбора дешёвого варианта
3. **Прозрачность:** нет стандартного способа узнать цену модели заранее (до генерации)

**kie.ai** — агрегатор сотен моделей (от нано-бюджетных до enterprise) с прямым доступом к API и прозрачным прайсингом. Отличие:
- nano-banana-2-lite: $0.02 (vs Artlist/Higgsfield молчат про цену)
- Veo 3.1: $1.28 (vs Higgsfield $3.20 за видео)
- Поддержка Seedance 2, Kling 2.5, Suno V5 (в Artlist отсутствуют)

Но есть проблема: **официального SDK/CLI/MCP нет**. Есть только MIT-репозиторий
`nick-vels/VelsVisual` (JavaScript, обёртка над kie.ai без MCP). Взяли знания
об API оттуда, каркас пишем свой на TypeScript.

## Решение

### Архитектура
- **Код:** `tools/nullume/` (универсальная инфраструктура, как `tools/icon-mcp-server/`)
- **Язык:** TypeScript, ESM, Node ≥ 22.13
- **Основные зависимости:** `commander@^15`, `zod@^4`, `@modelcontextprotocol/sdk@^1.30`
- **Три поверхности на одном ядре:**
  1. CLI (`bin/nullume.js`) — локальный инструмент
  2. MCP-сервер (`src/mcp/`) — для агентов Claude Code
  3. SKILL.md (`.claude/skills/nullume/`) — метапроцедура использования

### Провайдер и вендоринг
- Интерфейс провайдера: `Provider { name, balance(), models(), create(model, input), status(taskId), upload(path) }`
- Каталог моделей вендорится из docs.kie.ai (`docs.kie.ai/llms.txt` + `docs.kie.ai/market/*.md` + `docs.kie.ai/pricing`) в `data/models.json` и `data/prices.json`
- Второй провайдер (например, fal.ai) = новый каталог `providers/<имя>/`; строка в `providers/index.ts`

### Хранилище данных
- Конфигурация и ключи: `~/.nullume/config.json` (права 0o600)
- Сессии (для local-only импортёров спринта 2): `~/.nullume/sessions/*.json` (600)
- Кэши, результаты задач, загрузки: JSON + файлы в `~/.nullume/{cache,jobs,downloads}/`
- Спринт 2: SQLite в `~/.nullume/library/` (встроен в Node ≥ 22.13, требует флага `--no-warnings=ExperimentalWarning`)

### Ключи и авторизация
- `KIE_API_KEY` → из переменной окружения → сохраняется в `~/.nullume/config.json` (600) → читается откуда первое найдётся
- Pinterest/Dribbble/X токены → только в `~/.nullume/sessions/` (600), никогда в коде или env (за гейтом ADR-007)
- MCP-сервер получает `KIE_API_KEY` из `.mcp.json`: `"env": {"KIE_API_KEY": "${KIE_API_KEY}"}`

### Библиотека вкуса (спринт 2)
- Дескриптор стиля в форме «разбор референсов в значения» (из `docs/core/design-principles.md`)
- Компоненты: эмбеддинги (CLIP), кластеризация (k-means), поиск по семействам стилей
- Импортёры: чистые (Are.na, Unsplash, галереи) + local-only (Pinterest, Dribbble, X) — только в CLI, не в MCP

### Выкатка и CI
- **Развёртывание:** нет сервера; CLI работает на машине пользователя
- **Публикация:** npm (спринт 3); скилл в репозитории для Friday
- **CI:** GitHub Actions — typecheck, тесты, еженедельный аудит `audit:catalog`
- **Data in git:** `data/models.json` и `data/prices.json` (вендоренные снимки)
- **Data out of git:** `~/.nullume/` полностью (конфиг, кэши, загрузки, сессии)

## Альтернативы

### Отклонено: только Artlist/Higgsfield
- **Причина:** цены выше на 2–10×; нужные модели (Seedance 2, Kling, nano-banana-2) отсутствуют
- **Уникальность:** что-то нужно на дешёвых моделях; что-то только в новых (Kling 2.5 в Higgsfield нет)

### Отклонено: форк VelsVisual как есть (без изменений)
- **Причина:** нет MCP, нет провайдерной абстракции, нет библиотеки
- **Утечка:** base64 медиа в Claude Code ~20k токенов; MCP отдаёт пути файлов

### Отклонено: Nullume в top-level каталоге (`nullume/`)
- **Причина:** новый запрещённый токен в `portability-check.sh` и агентах
- **Выбор:** `tools/` уже известен как корень инструментов репозитория

## Последствия

### Позитивные
- Прозрачный прайсинг: всегда видим цену до генерации
- Низкие цены: nano-banana-2 $0.02 за фото, Veo 3.1 $1.28 за видео
- Модельное многообразие: Seedance, Kling, Suno V5 на одной платформе
- Интеграция с Claude Code: через MCP и SKILL.md
- Местное хранилище: вся история задач и результаты на диске владельца

### Нейтральные
- Новая фронтенд-зависимость в спринте 2: `@huggingface/transformers` (CLIP, ~90 МБ)
- SQLite experimental flag (но Node ≥ 22.13 заявлен как LTS)
- Необходимость еженедельного аудита каталога (doc.kie.ai меняется)

### Обязательные
- Появилась новая папка `tools/nullume/`, её имя добавлено в allow-list `portability-check.sh`
- MCP-сервер `nullume` зарегистрирован в `.mcp.json` → новый токен в allow-list
- Скилл `.claude/skills/nullume/` → новый каталог в allow-list
- При спринте 2: local-only импортёры нарушают ToS Pinterest/Dribbble/X → ADR-007 с гейтами и предупреждениями

## Довод против (challenger)

Самый сильный довод: вся ценность инструмента (цена и доступ к моделям,
которых нет в Artlist) держится на вендоренном каталоге, а каталог собирается
парсером YAML из ~180 markdown-страниц чужой документации. Деградация будет
тихой: смена разметки одной страницы даёт не падение, а неверную схему или
неверную цену — и тогда стоимостной шлюз пропустит дорогую генерацию, считая
её дешёвой.

Условие, при котором довод неверен: цены берутся с программного эндпоинта
(`/client/v1/model-pricing/page`), а не из markdown, и у каждой модели
хранится источник схемы. Принятые меры: поле `schemaSource` у модели,
`source` у оценки стоимости (скилл требует подтверждения при `fuzzy` и
`unknown`), аудит каталога сравнивает required-поля по каждой модели, а не
их количество; живая генерация на $0.02 — обязательный шаг приёмки.

Более слабые возражения, принятые к сведению: роутинг между Artlist,
Higgsfield и Nullume должен быть явным правилом в `media-generator`, а не
одной строкой; `generate` в MCP ждёт не дольше 300 с и возвращает задачу для
`get_job`; local-only импортёры библиотеки вкуса отделяются на уровне сборки,
а гейт по переменным окружения — предупреждение, не контроль доступа.

На этапе принятия решения: в репозитории уже Artlist (авторитетный) и Higgsfield (качественный).
Третий сервис добавляет сложность — 180 страниц документации kie.ai, прайс без гарантий формата,
URL результатов живут ~24 часа. Выигрыш в цене имеет смысл только если (а) объём генераций ≥ 200 фото/месяц
или (б) нужны специфичные модели (Seedance 2, Kling 2.5, Suno V5). Проверить перед кодом:
`mcp__artlist__list_models` против `data/models.json` — если Artlist покрывает все нужные — может быть, не нужна?

Ответ владельца: Pinterest и дешёвые модели обязательны; оценка трудозатрат приемлема.
